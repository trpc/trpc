# Agents (`www/`)

Working on trpc.io's site, which serves every version's docs, and writing the v12 docs in `www/v12/docs/`. Paths are relative to the repository root; [`../v12/AGENTS.md`](../v12/AGENTS.md) applies to the v12 docs too. The site is one package of the root workspace (`www`), so run its scripts with `pnpm --filter www <script>` ([`decisions/one-workspace.md`](../v12/.agent-docs/decisions/one-workspace.md)).

- Every v12 page needs `title`, `description`, `section` (one of `www/v12/sections.json`) and `order` in its frontmatter; the sidebar and `llms.txt` list it from those, so there's no index to update.
- `experiment: <id>` in the frontmatter (one of `www/src/experiments.ts`) puts a page that waits for review in an experiment: it's served at its URL but `noindex` and out of the sitemap, and out of the sidebar until the experiment is on (the Experiments menu, `?flags=<id>`, or opening one of its pages). The site's search and `llms.txt` list it whether its experiment is on or not, marked experimental, and opening it from search turns its experiment on; after a build, `search:check` searches every experiment's pages with them all off in headless Chrome; CI runs it. The build fails when a listed page links to it ([`decisions/docs-experiments.md`](../v12/.agent-docs/decisions/docs-experiments.md)).
- Where a page's v11 topic is at another slug, name the v11 page in its frontmatter (`v11: server/data-transformers`); the version banner and switcher link the two.
- The v11, v10 and v9 docs (`www/v11/docs/`, `www/v10/docs/`, `www/v9/docs/`), the home page's v11 code steps (`www/v11/home/`) and the blog (`www/blog/`) are `main`'s: edit them on `main`, and a merge of `main` into `v12` brings them to the same paths ([`decisions/old-docs.md`](../v12/.agent-docs/decisions/old-docs.md)). The v11 docs' Twoslash blocks compile in `www/samples/v11`, against the workspace's `@trpc/*`.
- trpc.io's redirects are `main`'s, in `www/vercel.json`; the build turns them into routes and fails on one that lands nowhere, and `build/legacy-urls-check.ts` checks every URL trpc.io served still reaches a page ([`decisions/old-urls-and-seo.md`](../v12/.agent-docs/decisions/old-urls-and-seo.md)).
- The sponsors in `www/sponsors.json` and the root `README.md`'s sponsors section are written by `pnpm --filter www sponsors:sync` (needs KATT's `SPONSORS_SYNC_GITHUB_TOKEN`, or asks for it; `sponsors:readme` redoes the README from `sponsors.json`), and by `.github/workflows/next-sponsors.yml` daily when a sponsor joined, left or changed tier: don't edit them by hand ([`decisions/docs-sponsors.md`](../v12/.agent-docs/decisions/docs-sponsors.md)). After merging `main` into `v12`, the `post-merge` hook reruns `sponsors:readme` when `README.md` changed; commit what it writes.
- Put package names, import paths and code (`@trpc12/trpc/server`, `t.concat()`, `httpLink`, `ctx`) in backticks, in the frontmatter's `title`, `label` and `description` too: the site renders them as code and strips them for meta tags and `llms.txt`. `pnpm lint:docs` (in `v12/`) fails on bare ones in the v12 docs and `pnpm lint:docs --fix` wraps them ([`v12/tooling/docs-lint/bare-code.ts`](../v12/tooling/docs-lint/bare-code.ts)).
- Link pages with relative `.md` links (`../client/links.md#query-urls`); the build fails on a missing page or heading.
- Everywhere else (package and example READMEs, `v12/.agent-docs/`, codemod messages), link a v12 page by its URL on the site, `https://v12.trpc.io/v12/docs/<slug>` (`site.url` and `v12.basePath` in `www/src/site.ts`), not by its path; `v12/tooling/pack/docs.test.ts` checks the package READMEs' links.
- Prefer `ts twoslash` blocks: in the v12 docs they compile in `www/samples/v12` (import its `./server.ts` and `./client.ts`, hiding the setup between `// ---cut-start---` and `// ---cut-end---`), and `// ^?` shows a type. An undeclared type error fails the build. A `sample` block names a file of a sample app under `www/samples/` (`v12/src/server.ts`) and shows it.
- `pnpm --filter www dev` serves the site; `pnpm turbo run build --filter=www` builds it after the packages it compiles against, and is the check. `pnpm check:www` lints, typechecks and tests the site and `tooling/`. Compiled blocks are cached in `www/node_modules/.cache/twoslash`.
- The site's components are vanilla shadcn in `tooling/ui` (`@shared/ui`), installed by its CLI: don't edit them, reinstall (`pnpm dlx shadcn@4.21.4 add <name> --overwrite` in `tooling/ui`). Brand colors live only in its `src/styles/globals.css` ([`decisions/shadcn-lib-and-branding.md`](../v12/.agent-docs/decisions/shadcn-lib-and-branding.md)).
- `/v12/decisions` renders `v12/.agent-docs/open/` and `v12/.agent-docs/decisions/` for the human to browse, and is hidden: never link it from the site, the sitemap or `llms.txt`; the build fails if anything does ([`decisions/hidden-decisions-pages.md`](../v12/.agent-docs/decisions/hidden-decisions-pages.md)). Their `ts twoslash` blocks compile in `www/samples/decisions`, an open question's proposed APIs against its stub in `open/`; `pnpm --filter www decisions:check` compiles them without a build ([`v12/.agent-docs/open/README.md`](../v12/.agent-docs/open/README.md)). Their filters, chosen option and view live in the URL's search, validated in `www/src/content/decision-search.ts`, never in component state. After a build, `decisions:layout` checks every decisions page fits a phone, a tablet and a laptop in headless Chrome; CI runs it.
- `site.url` in `www/src/site.ts` is the cutover switch: at `https://trpc.io` (`main`'s build), `/v12/docs` is hidden until v12 is released (`v12.hidden`) and v11's `llms.txt` is `/llms.txt`; the build checks both hidden paths ([`decisions/trpc-io-cutover-and-hidden-v12.md`](../v12/.agent-docs/decisions/trpc-io-cutover-and-hidden-v12.md)). v12's UI is then in the HTML, hidden and without links, until the session has been to v12; after a build with `site.url` at trpc.io, `v12-reveal:check` walks that in headless Chrome; CI runs it (`www-trpc-io`).
- The site is set up for Vercel: `main` deploys trpc.io and `v12` deploys v12.trpc.io, from the same root directory ([`decisions/docs-website-on-vercel.md`](../v12/.agent-docs/decisions/docs-website-on-vercel.md)). On `v12` it renders `www/`, the docs included, and its workspace dependencies: if it starts reading another path, add that path to `inputs` in `v12/tooling/vercel-ignore/src/bin/ignore.ts`, or deployments skip changes to it.
- Debugging the live site's errors: it reports them to Sentry; read the issue, its stack and its release (the commit) through the Sentry MCP server when it's connected, rather than guessing from the code ([`decisions/docs-site-sentry.md`](../v12/.agent-docs/decisions/docs-site-sentry.md)).
