# Plain JSON is the default transformer; progressive JSON is ported in, opt-in and experimental (human)

- Human, 2026-10-16 (Q11.1, decision round): "B". With no transformer, the handler and links use plain JSON (`jsonTransformer`); progressive JSON is opt-in with `experimental_createProgressiveJson()` on both ends. v11's default had no transformer either.
- Human, 2026-10-16 (Q11.2, decision round): "A". Progressive JSON's code is ported into `@trpc12/trpc/transformer` (Effect `Stream`s for the async format, [`../notes/danson-port-and-query-params.md`](https://github.com/trpc/trpc/blob/d5c34c43000547776ca234ac47edafd48370e6fd/next/.agent-docs/notes/danson-port-and-query-params.md)), not a dependency on the `danson` package; wire compatibility with standalone progressive JSON isn't kept.
- Human, 2026-10-16 (Q11.3, decision round): "For rpc I think input should work best". RPC `GET` inputs are one `?input=<serialized JSON>` param for every transformer, keys sorted ([`wire-protocol.md`](./wire-protocol.md)). Bracket notation stays with OpenAPI and forms ([`openapi.md`](./openapi.md)).
- Human, 2026-10-21: "danSON should be experimental_". Progressive JSON's public value is `experimental_createProgressiveJson()` (it was `createSerializer()`, then `experimental_createTransformer()` until the answer below; the concept's rename is in [`replaceable-transformers.md`](./replaceable-transformers.md)), tagged `@stability experimental`, and so are the types only progressive JSON uses, which keep their names as other experimental features' types do: `CustomType`, `ProgressiveJsonOptions` (its options), `SerializeRecord` and `DeserializeRecord` ([`stability-jsdoc-tags.md`](./stability-jsdoc-tags.md)). Renamed without an alias: nothing has shipped.
  - (agent) The Transformers page stays listed, with a line saying progressive JSON might change or go away in any release. An experimental export may be documented on a listed page (`experimental_createAction` is); only an export documented on hidden pages alone has to be experimental.
  - (agent) Not prefixed or retagged, since stable values share them: `TransformerError` (`DansonError` until the answer below), which `jsonTransformer` and `createSyncTransformer`'s transformers throw too; `ProgressiveJsonForm`, the form of in-process callers and `localLink`; and `Frame`, `Chunk`, `SerializedDeferred` and `SerializeReturn`, which the `Transformer` interface uses.
  - (agent) Server stores that keep progressive JSON internally (durable call results, cache keys in `@trpc12/experimental-react`) are unchanged: being experimental is about progressive JSON as a public API.
- Human, 2026-10-21: "1. Rename. We don't care about breaking changes before v12 2. Yes 3. With and without 4. Progressive json". Its 2 and 4 are about this file:
  - 2, whether `DansonError`, which every transformer throws (`jsonTransformer` and `createSyncTransformer`'s too), gets a neutral name: it's `TransformerError`, named for its domain as Effect-style errors are (`SqlError`), beside the link's `TransformerMismatch` tag. Its `name` is `'TransformerError'`; no alias.

Renamed without aliases: `experimental_createTransformer()` to `experimental_createProgressiveJson()`, its options `TransformerOptions` to `ProgressiveJsonOptions`, `DansonForm` to `ProgressiveJsonForm`, its wire name `'danson'` to `'progressive-json'` (the `trpc-transformer` header's and `init`'s value), `src/transformer/danson/` to `src/transformer/progressive-json/`, and the docs' and comments' prose. This file was `serializer.md`; its old page redirects here.
  - (agent) Kept: the port's credit to danSON in its source (`KATT/danson`, MIT), `danson` as the npm package's name, and the dated notes and proposals, which record what was true then.
- (agent) Built, 2026-10-16: `jsonTransformer` is the default of `createFetchHandler`, every link, `localLink` and `hydrationOptions`; `experimental_createProgressiveJson()` is progressive JSON; `defaultSerializer` is gone. Server stores that need rich types (durable call results, cache keys) keep progressive JSON internally, whatever the wire transformer. Plain JSON can't carry a `bigint` or a file input; those fail before sending.
- (agent) Types that are already JSON (recursive JSON types, branded tuples, AI SDK chunks) are kept as written in the JSON form, instead of being re-mapped; a key typed `unknown` stays required. Validation error `path`s are `(string | number)[]` (symbol keys arrive as `String(key)`), so error data is plain JSON.
- Deserialized objects have `Object.prototype`, not a null prototype. The deserializer already rejects `__proto__`, `constructor` and `prototype` keys.
- (agent, 2026-10-19) The deferred values' streams are built from Effect's constructors ([`effect-internal-patterns.md`](./effect-internal-patterns.md)). Sending, a deferred `AsyncIterable` or `ReadableStream` is read with `Channel.fromAsyncIterable` and a file's bytes with `Channel.fromReadableStream`, one item per item read, instead of a loop in `Stream.callback` reading up to 16 ahead and an `async function*`; a `Promise` settles a `Deferred` from the moment it's found, which also handles its rejection. Receiving, the chunk queues are made in Effect (`makeChunkQueues`, shared by progressive JSON and the framed transformers) by whichever comes first, a value's chunk or its reader, instead of with `Effect.runSync`; the `Promise`, `AsyncIterable` and `ReadableStream` handed to users run on the deserializing fiber's context (`Effect.runPromiseWith`, `Stream.toAsyncIterableWith`, `Stream.toReadableStreamWith`), and frames waiting for file bytes are fibers forked as its children instead of detached. An `AsyncIterable`'s `return()` now ends a `next()` still waiting for a chunk; the `async function*` queued it behind that read, so it hung. +301 B gzipped on the minimal client, +309 B on the full one.
- Why: the default should be the smallest thing that works with any client; rich types are one option away. Progressive JSON is experimental because the human hasn't blessed it, and the default may still change before the release ([`replaceable-transformers.md`](./replaceable-transformers.md)).
- Lost: native `Date`/`Map`/`File` outputs out of the box; legible RPC query strings (QP-C). A stable rich-type transformer: apps that want one without the experimental stage use `createSyncTransformer(superjson)`.
- Lives in: `packages/trpc/src/transformer/` (`index.ts`: `experimental_createProgressiveJson`; `progressive-json/stream.ts`: `sourceOf`, `makeChunkQueues`); tests in `packages/trpc/src/transformer/transformers.test.ts` (an `AsyncIterable` returned while it waits); docs in `www/docs/server/transformers.md`.
