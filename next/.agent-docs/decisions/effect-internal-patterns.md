# Internals follow the vendored Effect source's patterns for services, resources and concurrency (human asked)

- Human, 2026-10-19: "look at .repos/effect. it probably has a lot of nice patterns we're not leveraging. look at nice patterns and how to structure services and whatnot and see how we can refactor. nothing is sacred, go wild without chganing public facing apis (allllll internal logic should be effect though)".
- (agent) Public APIs stay as they are: the same exports and types from every entry point, checked by diffing the type surface of all 31 entry points before and after each change. What users see as a Promise, callback or class stays one at the edge ([`internals-use-effect.md`](./internals-use-effect.md)).
- (agent) The patterns, each taken from how `effect/rpc`, `effect/http` and the core modules in `.repos/effect` do it:
  - Fibers started from a callback (a socket handed to `handler.websocket()`, a hibernation event, a UI subscription) run in a `FiberSet` or `FiberMap` owned by a scope, through `FiberSet.makeRuntime` or `Effect.runForkWith(context)`, never a bare `Effect.runFork` on the default runtime. Closing the owner's scope interrupts them, as `RpcServer.makeNoSerialization` tracks request fibers with `Fiber.runIn(Scope.forkUnsafe(scope))`.
  - Something with a lifetime (a handler, a link, a connection, a shared subscription) owns one `Scope`, and its `dispose()` or `close()` closes that scope. Resources join it with `Scope.addFinalizer` or `Effect.acquireRelease`, instead of each one keeping its own release callback.
  - A resource shared by key and released when its last user leaves is an `RcMap` (by key) or `RcRef` (one), with `idleTimeToLive` for linger, instead of a hand-counted `Set` of members.
  - Interruption is the cancel signal. An `AbortSignal` a public callback needs comes from `Effect.tryPromise((signal) => …)` or `Effect.callback((resume, signal) => …)`, which abort it on interrupt, instead of an `AbortController` aborted from `onExit`. Listening to a web `AbortSignal` from Effect code goes through `Effect.callback` with a cleanup that removes the listener.
  - Async iterables, `ReadableStream`s and event targets become `Stream`s at the edge (`Stream.fromAsyncIterable`, `Stream.fromReadableStream`, `Stream.callback`), are mapped and validated as `Stream`s (`Stream.mapEffect`), and leave as `Stream.toAsyncIterable` or `Stream.toReadableStream`. No `async function*` re-running Effects per item through `Effect.runPromise`.
  - Reusable functions returning an Effect are `Effect.fnUntraced(function* () {…})` (`Effect.fn('name')` where a span helps), the form Effect's own library code and `LLMS.md` use, instead of `(…) => Effect.gen(function* () {…})`. Files aren't rewritten for this alone; it applies to code being changed anyway.
  - Services are `Context.Service` classes or keys with a `Layer`; configuration with a default is a `Context.Reference`. A record of functions passed by hand through several layers of calls (`SocketCoreShape`, `HandlerCore`) is a candidate for a service in context, as `RpcServer.Protocol` is.
  - A value built once on first use is `Effect.cached` (or `Effect.cachedInvalidateWithTTL`), not a memoized `Promise` or a `let` checked on each call.
  - Mutable state shared between fibers is a `Ref`, `SynchronizedRef` or `SubscriptionRef`; plain `let`s and `Map`s stay where one fiber or one synchronous function owns them, as in Effect's own `RpcServer` and `RpcClient`.
  - Pure synchronous code (parsers, byte buffers, encoders, `deepEqual`) stays plain TypeScript, as in Effect's own modules: wrapping it in `Effect` adds allocations and nothing to compose.
- (agent) Each area records what it moved in its own decision or in the related existing one ([`handler-core-on-effect.md`](./handler-core-on-effect.md), [`websocket-sessions-on-effect-socket.md`](./websocket-sessions-on-effect-socket.md), …), with the measured change in client bundle size (`pnpm bench budget`), type-check instantiations (`pnpm bench shapes`, `pnpm bench typecheck`) and server throughput (`pnpm bench runtime`) where it moved them.
- Why: one model for lifetimes, interruption and shared state, so `dispose()` releases everything a handler or link started, and so the code reads like the Effect source it builds on. Bare `Effect.runFork`s and hand-rolled refcounts are where leaks and races hide.
- Lost: some client bytes where an Effect primitive is bigger than the hand-rolled loop it replaces (counted per change); churn across files other agents are editing.
- Open: the OpenAPI handler and link (`src/openapi/`) and `@trpc12/experimental-tanstack-db` wait until the work in flight on them lands.
- Lives in: `packages/*/src/`; the areas and what each changed are listed in the decisions they link from here.
