# A built procedure's type carries only what is read outside it; the root ctx is on the router (human asked)

- Human, 2026-11-01: "one thing that we did quite well in v11 was to sanitize procedure so the built procedure only contained things that are needed to infer stuff outside / this makes it so that .d.ts files etc gets less noisy etc (no ctx etc) / can we do the same for v12? i think we don't need all of those things once the proc is built?"
- (agent) A built procedure is a `QueryProcedure<D>`, `MutationProcedure<D>` or `SubscriptionProcedure<D>` (aliases of `Procedure<D, 'query'>` and so on; the type moved from the def to `Procedure`'s second argument). `D` always has `input`, `output` and `errors`, and only the others that say something:
  - `ctx`, only for the keys standalone middleware on it needs that its `t`'s root ctx lacks ([`keep-t-object.md`](./keep-t-object.md)); the root ctx is on the router (below).
  - `services`, unless `never`: the handlers type `layer`/`runtime` from it (`inferRouterServices`).
  - `outputValidated: true` and `declared` (the codes `.errors()` lists, no longer the map of errors), only when an output schema validates: `experimental_validationLink({ contract: appRouter, output: 'json' })` takes a router as its contract and decodes those outputs and those codes' `data` ([`validation-link-decoded-types.md`](./validation-link-decoded-types.md)).
  - Gone: `meta` (nothing reads a built procedure's meta from its type; a contract's is `contract.meta`) and `type` (on `Procedure`).
  - `byId` in a declaration was `Procedure<{ type: 'query'; ctx: Context; meta: {}; input: …; output: Post; errors: …; services: never; outputValidated: never; declared: {} }>` and is `QueryProcedure<{ input: …; output: Post; errors: … }>`. An implemented contract procedure printed `ImplementedProcedure<ImplementerDef<With<RootDef<…>>, ContractWith<…>>, ContractProcedure<…>, never>`; it prints the same flat def. `hover.test.ts` locks the printed forms.
- Why this formulation: the def is a member of an interface of the eight combinations (`ReturnShapes` for queries and mutations, `DefShapes` over `DefFields` elsewhere), picked by `ShapeKey<keyof ctx, servicesKey, outputValidated>`. Interface members are worked out when read, and the key's arguments are types many procedures share, so each combination's checks run once. Measured before it, on `pnpm bench shapes` (1,500 procedures, server half, `plain` 349 instantiations per procedure on `v12`): a key-filtering mapped type 687; a conditional alias over seven field arguments 486 (an alias instantiates its arguments for every instantiation, where an object literal's members wait to be read); `services` checked through `Exclude` +34. `QueryProcedure` as an interface extending `Procedure` cost +14% to a handler reading 1,000 procedures from `.d.ts` (compared member by member against `AnyProcedure` where an alias of `Procedure` compares type arguments), and prints the same.
- `servicesKey` is `requires | ServicesKey<$Ret>`: a resolver's services without `Awaited` unless it returns a promise. Every procedure in a program pays the key, read or not; with `SplitReturn<$Ret>['services']` a client checking a router from source paid 6% more. It is `never` whenever `services` is, so a needed service is never left out; when the only requirements are `Scope` or provided services it says `services: never`.
- Cost of the procedure types against `v12` before (with `ctx` still on every procedure):
  - `pnpm bench shapes`, instantiations per procedure: server half +2 to +15% (`plain` 349 → 386, `output` 591 → 607, `middleware` 1,013 → 1,058, `contract` 1,289 → 1,312, `effect services` 357 → 411); with the client +2 to +9%. Memory +4 to 5%, check time within noise to +10%.
  - `spikes/big-routers` (1,000 procedures, zod, mostly `async` resolvers): the server from source 891,013 → 890,953 instantiations; a client checking the server's source 772,390 → 844,846 (+9%); reading the declarations, the apps 29,643 → 30,957 (+4%), the fetch handler 63,976 → 73,029 (+14%, 0.03 → 0.04s), `dts-split` 47,885 → 51,899.
  - Declarations: a big-routers domain 69,599 → 59,021 bytes (−15%); `examples/monorepo`'s packages 11,615 → 6,716 bytes (`billing`, implemented from a contract, 5,542 → 1,218).
- Human, 2026-11-01, on always printing `services` (`services: never` on most procedures, which would take the client-from-source cost from +9% to about +3%): "no".
- Human, 2026-11-01, on printing `SchemaValidationError<{ id: string }, z.core.$ZodIssue>` instead of `SchemaValidationError<z.ZodObject<{ … }, z.core.$strip>>` (keyed by the input and an issue family rather than the schema, which types the issues lazily: [`zod-and-effect-input-issues.md`](./zod-and-effect-input-issues.md)): "doesn't matter". It stays as is.
- Human, 2026-11-01: "i still see ctx in the hover which will cause bloat in dts files". `ctx: import("@big/base").Context;` printed once per procedure, twice in a domain whose index re-exports its files: in `spikes/big-routers` 88 KB of 1.19 MB of declarations (7%). Any type a procedure's own type carries is printed in its declaration, so the root ctx could live on the router (A), nowhere (B: `createContext`, `call()` and actions typed by what they're given), or stay, printed by name (C).
- Human, 2026-11-01, picking A: "A) this is probably why we didn't do shorthand routers as a "default" when you split stuff into separate files".
  - (agent) `t.router(routes)` returns `routes` and types it `routes & RouterCtx<TCtx>`: a required key under an unexported `unique symbol` whose value is the function type `(ctx: TCtx) => void`, on the type only. A router made with it prints as `{ … } & RouterCtx<{ userId: string | null }>`.
  - (agent) The convention: the root, and every router a module exports, is `t.router(…)`, so a module's declarations name the root ctx once, at its router. Nesting inline stays a plain object (`post: { byId, create }`). Docs, examples, samples, spikes, the benches' generators and the codemod (which now keeps v11's `t.router`) follow it ([Routers](https://v12.trpc.io/v12/docs/server/routers)).
  - (agent) Handlers (fetch, `makeFetchHandler`, v11, OpenAPI, MCP), `createRouterClient`, `localLink` and `createTrpcRsc` take `router: TRouter & RootRouterCheck<TRouter>`: a plain-object root is a type error that says to make it with `t.router()`, even when its ctx is `{}`. `inferRouterContext` is every brand's ctx in the tree and every procedure's middleware needs, intersected, so a root of routers from different `t`s needs all their ctxs.
  - (agent) `call()` is `t.call(procedure, input, opts)`, its ctx `t`'s and the procedure's needs; the free `call` export is gone. `experimental_createAction(t, opts)` and `experimental_createCallable(t, opts)` check the factory's ctx against `t`'s root ctx and each procedure's needs.
  - (agent) Why a symbol key holding a function: the clients (Promise and Effect), `inferRouterInputs`/`Outputs`, `inferContract` and `mergeRouters`' duplicate-key check map string keys only (`keyof R & string`, free on the benches), so a declaration that spells a client out never has to name the unexported symbol (TS4023, which `tooling/portability` caught); walks over every key (`inferRouterErrors`/`Services`, `ExactRouter`) see the function as a node with no keys. Required, not optional: those walks index a router by every key, and an optional one adds `undefined`. An alias, not an interface: an object literal type fits `AnyRouter`'s index signature. `t.router()` on a router already branded (`t.router(mergeRouters(a, b))`) merges the brands into one (`Branded`), since of two intersected function types inference reads only the last; `mergeRouters` returns its routers' keys and one brand naming every ctx (`MergedRouter`).
  - (agent) Cost against the procedure types above (`ctx` on every procedure, module routers plain), with the benches' generated module routers now `t.router()`-wrapped:
    - `pnpm bench shapes`, instantiations per procedure, server half: `plain` 386 → 389, `output` 607 → 613, `middleware` 1,058 → 1,076, `merged` 403 → 417, `contract` 1,312 → 1,319, `effect services` 411 → 414; the empty router 2,585 → 2,802. With the client: `plain` 685 → 688, `middleware` 1,394 → 1,412, `merged` 705 → 723.
    - `spikes/big-routers`: the server from source 890,953 → 895,978 (+0.6%); a client checking the server's source 844,846 → 849,064; the apps reading declarations 30,957 → 30,968; the fetch handler reading them 73,029 → 76,750 (+5%); `dts-split` 51,899 → 52,234.
    - Declarations: a big-routers domain 59,021 → 55,402 bytes (−6%), all of them 1,186,539 → 1,114,291 (−72 KB): 2,001 `ctx:` lines become 221 `RouterCtx` lines, one per router. `examples/monorepo`'s packages 6,716 → 6,749 bytes: its procedures had little ctx to drop, and `packages/api`'s named `AppRouter` gains `& RouterCtx<Context>` and its import.
- Lost:
  - A plain-object root: handlers reject it. With option B it would have been served, unchecked.
  - The free `call(procedure, input, { ctx })`, and actions that don't take `t`.
  - A procedure from another `t` is checked only through the router its own `t` made: put in a plain object under the root, its root ctx is in no brand, and `createContext` isn't asked for it.
  - `keyof typeof router` includes the brand's symbol, which the router's client lacks, so code indexing a client by it filters to string keys; and `t.router()` over a branded router spells out its keys.
  - `ProcedureDef`'s fields are optional; whole-router reads index them as `D[F & keyof D]` (+4k instantiations at 1,000 procedures). `meta` on a procedure's type.
- Open:
  - A contract's own procedures still print `ContractProcedure<'query', ContractWith<…>>`: `implement()` reads the builder state.
  - A named root type (`packages/api`'s `AppRouter`, against TS7056) is written `{ … } & RouterCtx<Context>`, so `RouterCtx` is public.
