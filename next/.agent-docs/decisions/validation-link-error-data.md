# `experimental_validationLink` decodes declared errors' `data`, and downgrades a mismatch to undeclared, as oRPC does (human asked)

- Human, 2026-10-20 (Q24.8): "Do what you think is best. It's an experimental feature, we can revisit when we bump it to unstable". Given after being shown how oRPC's `ResponseValidationLinkPlugin` works (its [`response-validation.ts`](https://github.com/unnoq/orpc/blob/main/packages/contract/src/plugins/response-validation.ts), and `reconcileORPCError` in [`error-utils.ts`](https://github.com/unnoq/orpc/blob/main/packages/contract/src/error-utils.ts)). The agent chose the open question's C, oRPC's way; proposal 24's A without rebuilding classes.
- The link decodes a declared error's `data` with the schema of its code's `.errors()` entry, so under `output: 'json'` a `Date` in it arrives as a `Date`, and the client types it so. Without `'json'` it checks `data` against the schema's type side, as it does results.
- A decoded error keeps its `_tag` ([`error-tags.md`](./error-tags.md)), as the server's own check of declared `data` does.
- A `data` that doesn't decode doesn't fail the call: the error is downgraded to undeclared (`defined: false`), as `reconcileORPCError` does, tagged with its code's default as an undeclared error from the server would be. A custom code keeps its `data`, untyped (`UndeclaredError`, which `matchError()` hands to `unexpected`); a built-in code loses it, with the received error as its `cause`, as `fromWireError` treats undeclared built-in codes.
- Errors that aren't `defined`, and codes without a `data` schema, pass through as they arrived.
- No class rebuilding: the error stays a plain `TrpcError`, so `instanceof PostNotFound` is still `false` on the client.
- (agent) The link checks errors' `data` for the same procedures whose results it checks (a contract procedure with a validated, non-streamed output; subscriptions included; not with `output: false`), so one per-procedure form types both. The decoded form is `DansonForm`: `DecodedResultForm`, `DecodedJsonResultForm` and `ErrorData`'s `errorData` branch are gone.
- (agent) The link's own input check (`BAD_REQUEST`) isn't run through the errors' schemas; only errors from the links after it are.
- (agent) Only codes the contract declares with `.errors()` are typed decoded. Errors a procedure returns without declaring them (a router used as the contract, middleware's errors) have no schema on the client, so their `data` keeps the links' form (its JSON form behind `httpLink`'s default serializer) on a decoded procedure too, as it arrives. Procedure defs carry `.errors()`' map as a type-only `declared` field (from `.query()`, `.mutation()`, `.subscription()`, contract procedures and `implement()`), and the decoding client's `DecodedDef` rewrites the `data` of every other code into the links' form before the decoded form applies. Measured on `@trpc12/trpc`'s own `tsc -p .`: +0.16% instantiations (1,977,243 to 1,980,399).
- Why: the types follow the wire, as for results ([`validation-link-decoded-types.md`](./validation-link-decoded-types.md)), and a server whose error `data` drifted keeps its real code and message instead of becoming `BAD_RESPONSE`. Matching is by code (`matchError()`, `Effect.catchTag`), so it needs no class registry, and the link is experimental, so B can follow without a break.
- Lost:
  - A, errors left as they arrive: nothing to build, but a `Date` in a declared error's `data` stayed a `string` under `output: 'json'` while the same `Date` in the output was decoded.
  - B, rebuilding `TrpcError.Tagged` classes on the client so `instanceof PostNotFound` holds and client `catchTag` gets the class. Postponed, not rejected (Open).
  - The open question's B and C failed a mismatched `data` with `BAD_RESPONSE`, like an output; oRPC's downgrade keeps the server's code, so a mismatch is treated as untyped, not unreadable.
  - Procedures whose results the link doesn't check (no output schema, `.output(schema, { validate: false })`, `stream()` outputs) don't have their errors checked either, even when they declare them.
- Open: B, rebuilding declared errors' classes (`instanceof PostNotFound`, client `catchTag` on the class), when `experimental_validationLink` moves from experimental to unstable ([`experimental-to-unstable-list.md`](../open/experimental-to-unstable-list.md)). It would build the `.errors()` entry's class from the decoded `data` where the entry is a `TrpcError.Tagged` class.
- Lives in: `packages/trpc/src/client/links/validation.ts` (`declaredError`), `packages/trpc/src/client/types.ts` (`ErrorData`, `DecodedFormOf`, `DecodedDef`), `src/effect/index.ts` (`DecodingEffectRouter`), `src/server/procedures/{procedure,builder,implement}.ts` and `src/contract/index.ts` (`declared`), `packages/trpc/src/client/links/validation.test.ts`, `www/docs/client/validation.md#errors-data`, `www/docs/openapi/client.md`; question in `proposals/24-error-ownership.md`.
