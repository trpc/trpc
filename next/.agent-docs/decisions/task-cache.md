# `pnpm typecheck` replays each package's `tsc` from Vite Task's cache, and CI keeps the cache between runs (human asked)

- Human, 2026-10-20 (via the coordinator): "Run per-package `typecheck` through `vp run --cache` (exclude `.tsbuildinfo` outputs) and persist `node_modules/.vite/task-cache` across CI runs with `actions/cache`." "No Turbo."
- (agent) `pnpm typecheck` is `vp run -r --cache typecheck`: every workspace package's `typecheck` script, 4 at a time in dependency order as `pnpm -r` ran them. Vite Task records the files each `tsc` reads and replays a package's output when none changed; it prunes the root's own `typecheck` from `-r`. A failing package fails the run, with `tsc`'s errors.
- (agent) Local, 4 cores, under the gates lock: `pnpm -r run typecheck` took 25.3 s. The cached run takes 29.0 s with an empty cache, 1.8 s with nothing changed (67 of 69 tasks replayed), 6.7 s after an edit to `@trpc12/tanstack-react-query` and 28.3 s after one to `@trpc12/trpc`, which every package reads (25.5 s with `pnpm -r`). `--parallel` didn't help (28.8 s cold). The cache is 28 MB.
- (agent) CI's `check` and `effect-latest` jobs restore the newest run's `node_modules/.vite/task-cache` before `pnpm typecheck` and save it after, as Vite+'s GitHub Actions guide does: a per-run key, a prefix to restore, and no inputs in the key, since Vite Task fingerprints them. Each job has its own prefix: Vite Task keeps one entry per task, and `effect-latest` installs other versions, so a shared cache would have each job overwrite the other's.
- (agent) `.tsbuildinfo` isn't excluded: a task's `cache.input` and `cache.output` go on a task in a package's `vite.config.ts`, and a task can't share its name with a `package.json` script. The two that rewrite one (`examples/monorepo`'s `tsc -b` and `examples/next-app`'s `incremental` tsconfig) always run instead, about 3 s together, and their `tsbuildinfo` already makes a second run cheap. Moving them to tasks would take `pnpm typecheck` from those examples' readers.
- Lost: a replayed package is only as right as Vite Task's tracking of what `tsc` read. An input it can't see (an environment variable) wouldn't rerun it; `vp cache clean` empties the cache. A cold run is about 3 s slower than `pnpm -r`, and CI pays the restore and save of the cache.
- Not done: Turborepo's remote cache, and Vite Task's, which isn't in a released `vp`.
- Lives in: `next/package.json` (`typecheck`), `.github/workflows/next.yml` (`check`, `effect-latest`), `next/README.md`.
