# `matchError()` is exhaustive: a key per inferred code, and one required `unexpected` (agent)

- Human, 2026-10-19, replying to "type errors for a wrong output now name the one expected type instead of a four-member union — OK?": "it should be exhaustive based on the errors / is that matchError forced to be exhaustive on the inferred errors? if not make it".
- Human, 2026-10-19 (the D answer, [link-errors](./link-errors.md)): "the types should rule it, and if it's inferred we should still have it in the match [...] links should be able to infer their own errors they can return [...] there's always a "catch all" unexpected error but we should do our best outside of that to be exhaustive".
- Human: "always fix stuff if there's a faster way without sacrificing dx".
- Human, 2026-10-18 ([granular-errors](./granular-errors.md)), which the categories came from: "i'd like to push it as far as possible without it becoming annoying and handling dozens of type of errors for every rpc call [...] it'd be good to have some generic errors that you'd be forced to match (or sub-types)". The forced generic errors are now the link codes and `unexpected` (four keys over `httpLink`, not dozens), and `unexpected`'s `e.code` narrows to the sub-types.
- (agent) Before, `matchError()` required a key for every defined code (returned, failed with, declared, the input's `BAD_REQUEST`, links' defined errors), but not for the link codes: `NETWORK_ERROR`, `BAD_RESPONSE` and `STREAM_INTERRUPTED` were optional keys that otherwise fell into their category. The rest went to four categories (`rejected`, `unavailable`, `failed`, `aborted`) or `builtin`. Something had to take every error, but listing the four categories made the catch-all implied, and a new link code didn't break any call site.
- (agent) Now every key the error type lists by code is required: each defined code, and each link code the client's links declare. `unexpected` is the one catch-all and is required while anything else is left: built-in codes nothing declared (crashes, aborts, `CLIENT_ERROR`, a proxy's status, a procedure the server lacks) and `UndeclaredError`s. Once nothing is left (only defined errors, or only link codes), `unexpected` is a type error, like any key for a code the type doesn't have. `builtin` and the four category keys are gone.
- (agent) Members that share a code share its key, and the handler gets their union: two `NOT_FOUND`s with different `data`, or a defined `NETWORK_ERROR` and the link's. A built-in error with a defined code (`defined: false`) goes to `unexpected`, as before it went to its category.
- (agent) Picked over four required categories (plus optional link keys): that's four keys of ceremony on every call where one does, and the categories split what is still one "the call didn't do what the types say" case. The categories stayed as `ERROR_CATEGORY` until [granular-errors](./granular-errors.md) question 5 dropped it, since nothing read it. Also set aside: categories as optional keys beside `unexpected` (two ways to say the same thing, and more type-check cost).
- (agent) The link codes cost three keys on every `httpLink` call. They're the same for every call through a client, so the docs show one object of their handlers spread into each `matchError()`; excess keys are still type errors, since the check is in the constraint, not literal freshness.
- Human, 2026-10-19 (first-release review, question 1, on [#7692](https://github.com/trpc/trpc/pull/7692)): "do it".
- (agent, [#7692](https://github.com/trpc/trpc/pull/7692)) `STREAM_INTERRUPTED` is a key only for calls that can get it: a subscription, or a procedure whose output is an `AsyncIterable` (a generator, a `Stream`). A query or mutation whose output doesn't stream has its result before anything can be cut, so the key was a handler that never ran on most calls, and a leftover key on those is now a type error. `httpLink`'s plain calls take two link keys instead of three. Values deferred inside an output still reject with it, untyped, as before. Measured with `pnpm bench shapes` (instantiations, deterministic): `match` 1,846,423 to 1,810,433 (-1.95%, one handler fewer), `links` 978,562 to 990,585 (+1.23%), `plain` 942,544 to 954,567 (+1.28%), about 8 instantiations per procedure for the output check. The cheapest of six formulations: an inline `D['output'] extends AsyncIterable<any>` in `CallError`, with subscriptions on their own `SubscriptionError`.
- (agent) Type-check cost, `pnpm bench shapes` (its new `match` shape: 1,500 plain procedures, each called through `safe()` and `matchError()` with six handlers, tsc 7, single-threaded, median of 3):

  | `matchError()` types | handlers                          | instantiations |   types | memory | check |
  | -------------------- | --------------------------------- | -------------: | ------: | -----: | ----: |
  | before               | 2 defined + `builtin`             |      2,559,791 | 340,183 | 535 MB | 3.52s |
  | before               | 2 defined + 3 link + `builtin`    |      3,119,743 | 358,231 | 560 MB | 3.62s |
  | after                | 2 defined + 3 link + `unexpected` |      2,158,330 | 305,442 | 519 MB | 3.04s |

  The same call is 31% fewer instantiations than before, and fewer than the old three-handler form. The cut comes from three changes: one key-remapped mapped type (`[K in KeyedOf<E> as K['code']]`, which unions members per key) instead of an `Extract` per key; `Exclude<E, Keyed>` against two small object types instead of the computed keyed union; and the excess-key check as `Record<Exclude<keyof H, keyof ErrorHandlers<E>>, never>`. `safe()` alone accounts for about 400 instantiations per call; `plain`'s annotated `await` is 617 per procedure.

- (agent) A leftover key's type error names it: the check is `Leftover<Exclude<keyof H, keyof ErrorHandlers<E>>>`, a mapped type whose value is `` `'${K}' handles no error of this call` ``, so the error reads `Type '() => string' is not assignable to type '"'GONE' handles no error of this call"'` instead of `... to type 'never'`. A named alias over only the leftover keys is cached when there are none: `match` 1,846,423 to 1,846,431 instantiations; the same mapped type inline (closing over `H` and `E`) was +4.9%.
- (agent) First-release review, question 6: "A declared code named `unexpected` collides with `matchError()`'s catch-all. Recommended: make it a type error in `.errors()` and `error()`."
- Human, 2026-10-19 (first-release review, question 6): "unsure waht this is - same as above" (the answer to question 5: "make a call and defer the decision").
- (agent) Deferred: the human asked the agent to decide; revisit before 1.0.
- (agent) In plain words: `matchError()` takes one handler per error code, plus one named `unexpected` for every error without its own. A procedure could name one of its own errors `unexpected` too, and then both wanted the same handler, so that error was quietly handled as "something went wrong". Naming an error code `unexpected` is now a compile error whose message says why. Every other name works as before.
- (agent) The check is where a code is named: a `.errors()` key (procedures and `experimental_contract`), `error({ code })` and `TrpcError.Tagged(code)`. The message is `'unexpected' is matchError()'s catch-all key: name this code something else`. A code typed `string`, or a map typed `Record<string, …>`, still passes. There is no runtime guard: nothing checks declarations at runtime (`.errors()` only merges its map), and a defined `unexpected` that gets past the types still goes to the `unexpected` handler.
- (agent) `.errors()` intersects its map with `ReservedKeyCheck`, an interface whose optional `unexpected` key has the message as its type, so it costs no conditional and a map passed through a generic helper still compiles. `error()` intersects its options with `ReservedCodeCheck<TCode>`. A conditional on `code` itself would print better, but `error()` then inferred `string` instead of `'NOT_FOUND'` in some returns (`procedures.test.ts`), since inference into a conditional ranks lower.
- (agent) Not checked: `new TrpcError({ code })` and a link's `errors` type. TypeScript can't evaluate the check for a generic code, so it would reject `<C extends string>(code: C) => new TrpcError({ code })` (two of tRPC's handlers are written like that) and generic link factories (`<E extends AnyTrpcError>() => link<{ errors: E }>(…)`). A link's errors are usually `TrpcError.Tagged` instances, which the class check already covers.
- (agent) Measured with `pnpm bench shapes` (instantiations, deterministic, with the client): `errors` 1,440,768 to 1,443,779 (+0.21%, two per `.errors()` call), `match` 1,664,595 to 1,664,609, `plain` 957,221 to 957,235, `links` 993,239 to 993,257.
- Why (question 6): a defined error should reach its own handler. The collision only shows up in the handler that receives it, far from the declaration, so the check is at the declaration, where the fix is to rename the code.
- Lost (question 6): `unexpected` as a code name. A helper generic over the code it passes to `error()` or `TrpcError.Tagged()` (`<C extends string>(code: C) => error({ code })`) no longer compiles: give its parameter the type `string`, or build the error with `new TrpcError({ code, defined: true })`.
- Open (question 6): the `TrpcError` constructor and links' `errors` types stay unchecked.
- Lives in (question 6): `packages/trpc/src/internal/error.ts` (`ReservedCodeCheck`, `ReservedKeyCheck`, `error`, `TrpcError.Tagged`), `src/server/procedures/builder.ts` and `src/contract/index.ts` (`.errors()`), exported for declaration emit from `src/internal/index.ts`; tested in `src/server/errors.test.ts`; documented in `www/docs/server/errors.md#codes-and-statuses`.
- Why: the error type is the list of what can happen to a call; a handler per listed code makes adding an error on the server, or a link that can fail a new way, a type error at every call site, and the one catch-all is always written out.
- Lost: category keys (`rejected` etc.) and `builtin`; three more keys per `httpLink` call. A `TrpcClient<AppRouter>` with untyped links has all three link codes, so its calls need all three keys.
- Lives in: `packages/trpc/src/client/client.ts` (`ErrorHandlers`, `matchError`); tested in `src/server/errors.test.ts`, `src/client/links/link-errors.test.ts`, `packages/tanstack-react-query/src/{index,link-errors}.test.tsx` and `spikes/closed-errors/`; documented in `www/docs/client/errors.md#handling-every-error`, `www/docs/getting-started.md`, `www/docs/server/errors.md`, `www/docs/integrations/tanstack-query.md` and the home page's call sample; measured by `tooling/bench/shapes.ts` (`match`).
