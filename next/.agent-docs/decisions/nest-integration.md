# NestJS: `@trpcdev/nest` implements contracts in controllers on the OpenAPI handler (agent)

- Answers the parity row "Nest.js integration: later, built on contracts" ([`../reference/orpc-parity.md`](../reference/orpc-parity.md)), with the Effect-native lean and pending a human. No human decision exists on its shape.
- (agent) A separate package, `@trpcdev/nest`, because it brings its own peers (`@nestjs/common`, `@nestjs/core`, `rxjs`, `@effect/platform-node`) ([`integration-packages.md`](./integration-packages.md)).
- (agent) Shape, after oRPC's: `@Implement(contract)` on a controller method adds the Nest route for the contract's REST mapping and an interceptor; the method returns the procedure (`impl.post.byId.query(…)`), so resolvers reach Nest-injected services through `this`. A leaf needs `.route({ path })`; a contract router (method returns `impl.router({ … })`) gets default paths from its keys, through `resolveRoute` from `trpcdev/openapi`. `TrpcModule.forRoot(options)` / `forRootAsync({ inject, useFactory })` is a global module.
- (agent) Serving: the module holds one `createOpenApiHandler` (so the `layer` is built once and disposed on shutdown), and its new `serve(request, { path, procedure, route?, params })` skips route matching because Nest already routed. Nest's Node request and response are bridged by Effect, not by hand: `NodeHttpServer.makeHandler` from `@effect/platform-node` around `toHttpEffect` from `trpcdev/http`, which already replays bodies Express parsed. Urlencoded bodies Nest parsed go back through `toBracketNotation`.
- (agent) `createContext`'s `platform` is Nest's `ExecutionContext`, so ctx can read whatever guards attached to the request.
- (agent) Nest's own pipeline runs first: guards, pipes and filters apply to the generated routes, with method metadata copied onto each route a router adds (put `@Implement` topmost).
- Why: contracts are the part of trpcdev that doesn't need a router at startup, which is what Nest's decorator-per-method model wants; reusing the OpenAPI handler keeps one REST behavior (errors, coercion, SSE).
- Lost: the RPC wire protocol from Nest (REST only; serve `createFetchHandler` with `app.use` for RPC); Fastify and other Nest adapters (Express only); type-level checks that every contract leaf is implemented across controllers, or that the module's `layer` provides what procedures need (a missing service fails the call).
- Lives in: `packages/nest/src/index.ts`, `packages/nest/src/index.test.ts`, `packages/trpcdev/src/openapi/handler.ts` (`serve`, `OpenApiCall`), `src/openapi/routes.ts` (`resolveRoute`, now public), `test/integration/openapi.test.ts` (`serve()`), `docs/openapi.md` (NestJS).
