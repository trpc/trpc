# NestJS: `@trpc12/nest` implements contracts in controllers on the OpenAPI handler, as experimental (human)

- Answers the parity row "Nest.js integration: later, built on contracts" ([`../reference/orpc-parity.md`](../reference/orpc-parity.md)).
- Human, 2026-10-16 (decision round): "B". The shape below stays, and every value is experimental until the human blesses it ([`stability-jsdoc-tags.md`](./stability-jsdoc-tags.md)): `experimental_Implement`, `experimental_TrpcModule`, `experimental_TrpcHost`, `experimental_ImplementInterceptor`, `experimental_TRPC_MODULE_OPTIONS`. The option types keep their names, tagged `experimental`. Lost: serving the RPC protocol from the module (option C), and a stable Nest API before the human has used it.
- (agent) A separate package, `@trpc12/nest`, because it brings its own peers (`@nestjs/common`, `@nestjs/core`, `rxjs`, `@effect/platform-node`) ([`integration-packages.md`](./integration-packages.md)).
- (agent) Shape, after oRPC's: `@experimental_Implement(contract)` on a controller method adds the Nest route for the contract's REST mapping and an interceptor; the method returns the procedure (`impl.post.byId.query(…)`), so resolvers reach Nest-injected services through `this`. A leaf needs `.route({ path })`; a contract router (method returns `impl.router({ … })`) gets default paths from its keys, through `resolveRoute` from `@trpc12/trpc/openapi`. `experimental_TrpcModule.forRoot(options)` / `forRootAsync({ inject, useFactory })` is a global module.
- (agent) Serving: the module holds one `createOpenApiHandler` (so the `layer` is built once and disposed on shutdown), and its new `serve(request, { path, procedure, route?, params })` skips route matching because Nest already routed. Nest's Node request and response are bridged by Effect, not by hand: `NodeHttpServer.makeHandler` from `@effect/platform-node` around `toHttpEffect` from `@trpc12/trpc/http`, which already replays bodies Express parsed. Urlencoded bodies Nest parsed go back through `toBracketNotation`.
- (agent) `createContext`'s `platform` is Nest's `ExecutionContext`, so ctx can read whatever guards attached to the request.
- (agent) Nest's own pipeline runs first: guards, pipes and filters apply to the generated routes, with method metadata copied onto each route a router adds (put `@experimental_Implement` topmost).
- Why: contracts are the part of @trpc12/trpc that doesn't need a router at startup, which is what Nest's decorator-per-method model wants; reusing the OpenAPI handler keeps one REST behavior (errors, coercion, SSE).
- Lost: the RPC wire protocol from Nest (REST only; serve `createFetchHandler` with `app.use` for RPC); Fastify and other Nest adapters (Express only); type-level checks that every contract leaf is implemented across controllers, or that the module's `layer` provides what procedures need (a missing service fails the call).
- Lives in: `packages/nest/src/index.ts`, `packages/nest/src/index.test.ts`, `packages/trpc/src/openapi/handler.ts` (`serve`, `OpenApiCall`), `src/openapi/routes.ts` (`resolveRoute`, now public), `packages/trpc/src/openapi/openapi.test.ts` (`serve()`), `docs/openapi.md` (NestJS).
