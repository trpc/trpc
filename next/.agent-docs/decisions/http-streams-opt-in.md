# `httpLink` reads streamed single-call outputs and binary frames only with `streams: experimental_httpStreams()` (human asked)

- Human, 2026-10-19: asked for the client-bundle cuts in [`../notes/client-bundle-anatomy.md`](../notes/client-bundle-anatomy.md), one PR each. This is the fifth: streamed single-call outputs (the JSONL reader, resume) and binary frames, which every `httpLink` bundled whether or not it streamed.
- (agent) The API: `httpLink({ url, streams: experimental_httpStreams() })`, or `experimental_httpStreams({ binary: true })` for frames. `binary` moved off `httpLink` into it ([`binary-frames.md`](./binary-frames.md)). An option value, not a second link, so `HttpLinkDecl`'s typing and the one-link design ([`wire-protocol.md`](./wire-protocol.md)) hold. An import passed to the link, like `batching()` and `sse()`, so a client that doesn't pass it doesn't bundle it. Experimental, as new APIs start ([`stability-jsdoc-tags.md`](./stability-jsdoc-tags.md)).
- (agent) The protocol check: the handler never looks at `accept` to decide whether to stream. An output with deferred values is JSONL (`vary: accept`) whatever `accept` says, and `accept` only picks frames over JSONL. Buffering can't work: a deferred value can be an endless stream. A 406 can't work either: the procedure has already run when the handler finds out the output streams. Pinned by `fetch-edges.test.ts` ("an output that streams answers JSONL whatever accept says").
- (agent) So the client copes. Without `streams`, a single call asks for `application/json` only. If the answer streams anyway, the call fails with `UNSUPPORTED_PROTOCOL`, naming the call and the fix. The link cancels the body, so the stream stops on the server. With `streams`, single calls ask for `application/json, application/jsonl` (frames first with `binary`).
- (agent) Batches are unchanged: their response is JSONL already, so a batched call reads its deferred values with or without `streams`. Batches ask for frames only with `streams` and `binary`. So a v11 `httpBatchStreamLink` moved to `httpLink({ batch: batching() })` keeps streaming, since a batch of one is still a batch request. Batching bundles the JSONL reader for its own lines, so a client with `batching()` saves less.
- (agent) A byte stream input (`experimental_byteStream()`) always goes alone, so a call that streams its output back needs `streams`. It is never resumed.
- (agent) `experimental_durableLink`'s mid-stream resume (`trpc-resume-from`) lives in `experimental_httpStreams()`, so resuming needs `streams` too. Without it, a durable call whose output streams fails as above.
- Size, gzip, built on cut 3 (`batching()` and `sse()` imports), 2026-10-20: the minimal client goes from 36,612 to 35,072 B (−1.54 kB). The full budget fixture (`retryLink`, danSON) goes from 40,977 to 39,499 B (−1.48 kB). With `batching()` and `sse()` passed too, it goes from 44,272 to 43,656 B (−0.62 kB). Opting back in costs +1.74 kB on the minimal client, 0.2 kB over cut 3, since the transport's fallback for a streamed answer stays. The frames decoder rides along with `streams` (+5 B for `binary`), since `binary` is a runtime option. On `v12` without cut 3, the cut alone saves 0.67 kB (39,770 to 39,098 B).
- Lost: without `streams`, an unbatched call whose output streams doesn't work by default. It runs, then fails on the client, and the types don't catch it.
- Lives in: `packages/trpc/src/client/links/http/streams.ts`, `src/client/links/http/transport.ts` (`readResult`, `readStream`), `src/client/links/http/link.ts` (`streams`; `binary?: never` makes the old option a type error); tests in `src/client/links/http.test.ts` and `src/server/handler/fetch-edges.test.ts`; docs in `docs/client/links/http.md`.
