# Errors' `data` and streamed outputs are typed in the form they arrive in, behind a link that decodes only results too (agent)

- Found while compiling [`open/validation-link-error-data.md`](../open/validation-link-error-data.md)'s examples: `experimental_validationLink({ output: 'json' })` declared `DansonForm`, which typed both its decoded outputs and the errors' `data` it doesn't decode as the schemas' types, so a `Date` in a declared error's `data` was typed `Date` and arrived as a `string`.
- (agent) `OutputForm` gains an optional `errorData?: OutputForm`: the form errors' `data` arrives in, for a `streaming` form whose outputs a link decodes. The link declares `DecodedJsonForm` (`DansonForm` with `errorData: JsonForm`), exported from `@trpc12/trpc/serializer` beside the other forms. `ErrorData` reads `errorData` only in its `streaming` branch, so `matchError()`, `safe()`, `createSafeClient`, the Effect client and TanStack Query's hooks, which all take their error types from `ClientError`, follow it. A transport's own serializer still decides as before: a danSON chain keeps `Date`s in errors' `data`, plain JSON makes them `string`s.
- (agent) The link passes `stream()` query and mutation outputs through undecoded too (they aren't checked on the client, [`client-validation-link.md`](./client-validation-link.md)), so their items were typed `Date` and arrived as `string`s. `OutputForm` gains `streamedOutput?: OutputForm`, and `DecodedJsonForm` sets it to `JsonForm`. The Promise and Effect clients apply it (`StreamedForm`) only in their existing branch for an `AsyncIterable` output; `inferRouterOutputs` picks a mapped type once per client, by whether the form has one. Subscription events are decoded, so they keep the schemas' types.
- Why: the types say what arrives, the rule of [`links-declare-result-form.md`](./links-declare-result-form.md). A form already says how values arrive, so the error side sits on it rather than in a second chain declaration (`errorForm` beside `form` on `LinkDecl`), which would need its own first-link-wins walk and its own override in `TrpcClient`'s explicit form.
- Why this formulation (`pnpm bench shapes --only plain,errors,match,contract`, 1,500 procedures, with the client): 0 added instantiations on all four shapes. Checking `errorData` first in `ErrorData` cost +4,506 on `match` (3 per procedure); resolving the error form once in `ClientError` cost +1,520 on every shape.
- Why the streamed formulation (`pnpm bench shapes`, 1,500 procedures, with the client, plus local danSON-chain shapes): 0 added instantiations on `plain`, `match` and their danSON variants; +3,012 (2 per streamed procedure, 0.23%) on `streamed` and its danSON variant; +1,206 on `infer`, a constant per `inferRouterOutputs` use. Checking `streamedOutput` in `ClientValue` itself cost +7,500 on every danSON shape (5 per procedure), and a per-procedure check in `inferRouterOutputs` +16,508 on `infer`.
- Lost: an `errorData` on a non-`streaming` form is ignored; no link needs one. Decoding `stream()` items on the client (with the stream schema's item) would give the schemas' types instead; it would wrap every streamed output and ship the schemas' codecs, so the link keeps passing them through.
- Open: whether the link decodes declared errors' `data` (and rebuilds their classes) at runtime, [`open/validation-link-error-data.md`](../open/validation-link-error-data.md). If it does, its form drops `errorData`.
- Lives in: `packages/trpc/src/internal/types.ts` (`OutputForm.errorData`, `OutputForm.streamedOutput`, `DecodedJsonForm`, `StreamedForm`), `src/client/types.ts` (`ErrorData`, `DecorateCarried`), `src/effect/index.ts`, `src/server/procedures/router.ts` (`inferRouterOutputs`), `src/client/links/validation.ts` (overload), `src/serializer/index.ts`, `packages/trpc/src/client/links/validation.test.ts`, `www/docs/client/validation.md`, `www/docs/client/errors.md`, `www/docs/openapi/client.md`.
