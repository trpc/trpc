# AWS Lambda events through `@trpc12/trpc/aws-lambda` (agent)

- (agent) Built for the human Q12.3 answer ("provide adapters for the rest", [`platforms-through-effect-layers.md`](./platforms-through-effect-layers.md)): Effect has no Lambda event adapter, so `@trpc12/trpc/aws-lambda` is ours, a dependency-free subpath ([`flat-entry-points.md`](./flat-entry-points.md)).
- (agent) It wraps a fetch handler rather than the router. `toLambdaHandler(handler, { timeoutMargin? })` converts the event to a web `Request`, calls `handler.fetch(request, { event, context })` and converts the response back. The handler core stays platform-free; Lambda is the platform argument ([`handler-platform.md`](./handler-platform.md)), typed with `createFetchHandler<AppRouter, LambdaPlatform>`.
- (agent) One function for every event shape: REST APIs and ALB (payload 1.0), HTTP APIs and function URLs (payload 2.0), and Lambda@Edge. The event's own shape picks the result shape, so there is no `format` option.
- (agent) Bodies: text content types (JSON, JSONL, forms, XML, `text/*`, `+json`) stay text. Everything else is base64. Set-cookie goes to `multiValueHeaders` (1.0), `cookies` (2.0) or CloudFront headers (Edge).
- (agent) The call's `signal` aborts `timeoutMargin` (default `'1 second'`) before `context.getRemainingTimeInMillis()` runs out, through `request.signal`. That needed `handler.fetch` to honor `request.signal` at all: `HttpEffect.toWebHandler` runs apps uninterruptibly, so `createFetchHandler` and `createV11Handler` now wrap the app in `Effect.interruptible`, and the `base.run` promises are interruptible.
- (agent) Response streaming is a second function, `toLambdaStreamingHandler`, wrapped by the app with `awslambda.streamifyResponse`. It writes the HTTP integration prelude (status, headers and cookies as JSON, then 8 null bytes) and then the body with drain backpressure. It's separate because buffered and streamed Lambdas are configured differently (`InvokeMode`), and `awslambda` is a runtime global we don't import.
- Why: the most common serverless target, and a fetch-handler wrapper keeps middleware, platform typing and the whole HTTP protocol identical to Workers and Node.
- Lost: API Gateway WebSocket APIs (connection-per-invocation, needs an external connection store). Use a WebSocket server elsewhere or SSE over response streaming.
- (agent, 2026-10-19) The request's `signal` comes from one place: the `Effect.promise` that calls `handler.fetch` passes its own signal, aborted when the call is interrupted, joined with the deadline's `AbortSignal.timeout` by `AbortSignal.any`. It replaced a `new AbortController().signal` that never aborted for contexts without `getRemainingTimeInMillis` ([`effect-internal-patterns.md`](./effect-internal-patterns.md)). Effect's signal is aborted only on interruption, not when the promise settles, so a streamed body isn't cut. The deadline stays a host timer: an Effect timeout would interrupt the call and lose the error response the handler writes when its signal aborts.
- (agent, 2026-10-20) Audited under [`effect-first-public-apis.md`](./effect-first-public-apis.md): `toLambdaHandler` and `toLambdaStreamingHandler` stay functions of a fetch handler, with no `runtime` or `Layer` form. The adapter runs none of the caller's Effects, only the event's conversion, so a `runtime` would provide nothing. The router's services belong to the handler (`createFetchHandler`'s `layer`, or its `runtime` once the handler takes one). Lambda has no shutdown hook a scope could close on.
- Lives in: `packages/trpc/src/aws-lambda/index.ts`, `packages/trpc/src/server/handler/fetch.ts` (`Effect.interruptible`), `packages/trpc/src/interop/handler/handler.ts`, `packages/trpc/src/aws-lambda/aws-lambda.test.ts`, `packages/trpc/src/client/links/links.test.ts` (aborted `request.signal`), `www/docs/adapters/aws-lambda.md`.
