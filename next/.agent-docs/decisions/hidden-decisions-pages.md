# The open questions and the decisions are browsable on the docs site, at a path nothing finds (human asked)

- Human, 2026-10-20: "put the things that needs decisions or spikes and stuff that have some more nuance where you need a human's input in a specific folder where you link the spikes and link documentation and nuances and pros cons and stuff, and the nuances should show code examples of implications of the DX. I want to be able to reference those things when doing decisions. Decided things can live elsewhere". That folder is [`open/`](../open), one file per question in the format its README gives.
- Human, 2026-10-20: "Actually. Put them on the website in a special path that isn't visible to seo or search or anything. I'd also be interested to use that to browse old decisions".
- Human, 2026-10-20: "Make sure the story telling is interactive so they're easy to grok at a glance".
- Human, 2026-10-20: "Also update the decision skill to link to decisions on the website url and just do a summary". A decision round asks each item as the question, a line per option and the recommendation, linking the item's page for the code, pros and cons; after an answer it links the record's page ([`.agents/skills/decision-round/SKILL.md`](../../../.agents/skills/decision-round/SKILL.md)).
- (agent) The site serves them under `/v12/decisions` (`decisions.basePath` in `www/src/site.ts`): the index at `/v12/decisions`, each open question at `/v12/decisions/open/<file name>`, each decision at `/v12/decisions/<file name>`. The markdown stays in `.agent-docs/`, read at build time by `www/build/decisions-content.ts` with `tooling/decisions`' parsers, so a file the site can't render fails `pnpm test tooling/decisions` too.
- (agent) The index: a filter box over both lists, open questions first as cards (area, status, the recommended letter, title, summary) with status and area chips, then every decision newest first (by the latest date in its bullets), with who-decided and has-open-points chips. Status is "PR to review" when a `pr` link is listed, "Spike" when a `spike` link is, "Write-up" otherwise.
- (agent) An open question's page leads with its summary and its spike, PR and preview links as buttons (the other links as chips), then "Why it matters", the options as tabs (the recommended one selected and starred, `#option-b` links one) or side by side, each with its code and its ✅ and ❌ bullets as pros and cons, the recommendation, what's blocked, and `## Details` collapsed. Everything is in the prerendered HTML, so `curl` and agents read it all.
- (agent) The kitchen-sink `demo` fence isn't used: it embeds a live app from `www/src/kitchen-sink`, and an option's code is a sketch of an API that doesn't exist yet. The pages use `@shared/ui`'s tabs, toggle group, collapsible and badges.
- (agent) Hidden means: every page says `<meta name="robots" content="noindex, nofollow">` and every response under the path `X-Robots-Tag: noindex, nofollow`, on every host; `robots.txt` disallows the path; the sitemap, `llms.txt`, `llms-full.txt`, the site's search and the nav leave it out, and no page links there. `www/build/hidden-paths.ts` fails the build when a built page links there, a text file lists it, `robots.txt` doesn't disallow it, or a page there isn't `noindex`; `www/src/content/decisions.test.ts` fails when code outside its routes reaches it.
- (agent) Hidden isn't secret: the repo is public, and `robots.txt` names the path. The point is that searching or browsing the docs never lands there.
- (agent) Relative links in the files resolve on the site: to an open question or a decision, its page; to any other file of the repo, the file on GitHub's `v12` branch.
- Lives in: `www/build/decisions-content.ts`, `www/build/hidden-paths.ts`, `www/src/components/decisions.tsx`, `www/src/routes/v12.decisions.*.tsx`, `tooling/decisions/open.ts`.
