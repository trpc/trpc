- `@trpc12/experimental-react`, built 2026-10-16:
  - Render-as-you-fetch. A loader calls `trpc.post.byId.query(input)`, which starts the request and returns a promise. The component reads it with `use(useQuery(promise))`. `useQuery` finds the cache through the promise, so there is no provider.
  - Stable promises are built in, not a link. There is one promise per query key (path plus danSON input, plain object keys sorted) while it loads, and the same promise while the data doesn't change. Settled promises carry `status` and `value` (raf-query's `thenable.ts`), so `use()` renders cached data without suspending.
  - (agent) Dedupe is part of stable promises: one promise per key in flight is one request per key, so there is no dedupe link. The core `dedupeLink()` still dedupes the plain client.
  - (agent) Without links, an entry lives only while a request is in flight or a mounted `useQuery` reads it. A mounted entry returns stale data at once and refetches in the background.
  - The links are real tRPC links, in the same `links` array before the transport: `cacheLink({ staleTime, gcTime })`, `structuralSharingLink()`, `refetchOnMountLink()`, `refetchOnWindowFocusLink()`, `refetchOnReconnectLink()`, and `invalidateOnMutationLink()`. Each registers what it adds to the cache through `withQueryFeature` (a WeakMap, like `withSerializer`); in a plain client they only pass operations through.
  - `standardLinks()` is the standard array, matching TanStack Query's defaults: cache (5 minutes, stale at once), structural sharing, refetch on mount, focus and reconnect, and the core `retryLink()` (3 retries). It also holds `invalidateOnMutationLink()`, below.
  - (agent, tentative) `refetchOnMountLink()` skips the first mount after a `.query()` call that started a request. Otherwise every loader's request is sent twice under `staleTime: 0`, TanStack's well-known double fetch.
  - Human, 2026-10-17 (decision round, whether `invalidateOnMutationLink()` belongs in `standardLinks()`): "A", then "Actually do B instead on last one". So it's in `standardLinks()`: every mutation invalidates every query, unless `standardLinks({ invalidates })` narrows it, as a router revalidates its loaders after an action. This reverses the agent's opt-in call, which followed TanStack's default.
  - (agent) It waits for the mounted queries to refetch before the mutation resolves, as raf-query's `invalidate` does, so an action stays pending until fresh data shows.
  - Cache methods on the client: `invalidate(input?)`, `setData`, `getData` on queries, and `trpc.invalidate(prefix | predicate)`. Mutations and subscriptions are the plain client's.
  - `dehydrate(trpc)` and `hydrate(trpc, state)` carry settled queries with the links' serializer. A server's store (`isServer`, by default when there is no `window`) never drops entries, so a per-request client keeps what it rendered.
- `@trpc12/experimental-react-atom`, built 2026-10-16 from spike D:
  - `createAtomClient({ router, links })`.
  - Query atoms take reactivity keys and a time-to-live; mutation atoms invalidate keys; subscription atoms hold the latest event. Atoms carry typed errors from the Effect client.
  - Keys sort plain object keys, as in the promise client.
  - Hydration: query atoms are `Atom.serializable`, keyed `trpc:<path and input>`, with `AsyncResult.Schema({ success: serializerSchema(serializer) })`, a `Schema` that encodes with the links' serializer (default `jsonSerializer`). Failures don't encode, so `Hydration.dehydrate` skips them and the browser runs those queries again.
- (agent) The promise client's store owns a `Scope` with a `FiberSet` runtime. Requests are `Effect.tryPromise` fibers, so interruption aborts their signal; GC timers are `Effect.sleep` fibers; links' `attach()` cleanups are finalizers of the scope. `dispose()` closes it, which ends the store: it starts no requests afterwards. Cost: 462 B gzip (`createReactClient` with `standardLinks()`: 46,055 to 46,517 B) ([`effect-internal-patterns.md`](./effect-internal-patterns.md)).
- (agent) After `dispose()`, a promise client's read of a query without data rejects with a `TrpcError` `CLIENT_CLOSED_REQUEST` whose message names `dispose()`, and so do first loads in flight at `dispose()`. Before, they stayed pending forever, and a component suspended on one never rendered. Cached data still reads, and `refetch`/`invalidate` start nothing. `CLIENT_CLOSED_REQUEST` is what a link reports when the caller ends a request, which is what disposing does (human-decided, second pass).
- (agent) A promise client's lifetime is public, through a symbol and an option, so procedure names are unaffected (second pass, under [`effect-first-public-apis.md`](./effect-first-public-apis.md)):
  - `createReactClient({ scope })` forks the store's scope from the caller's, so closing it disposes the store, for a server client made in an Effect request;
  - `ReactClient[Symbol.dispose]` disposes the store, so `using trpc = createReactClient(…)` ends a per-request client;
  - the atom client takes no `runtime` or `scope`: it runs on the Effect client, exposes its `AtomRuntime`, and owns nothing the registry doesn't, since atoms end with their registry.

- (agent) The atom client keys `Atom.family` by an `AtomKey` that is `Equal` and `Hash` by its key string. The family holds atoms weakly and forgets a key once its atom is collected; the `Map` of keys it replaced kept every key forever.
- (agent) Passing server-started promises from React Server Components to `use()` in the browser is not a goal of either package (Q20.3).
- Why: the human wants a React integration without TanStack in v1, both the Effect-native one and a plain-promise one with raf-query's model. Every feature beyond stable promises is opt-in, so an app pays only for the links it uses.
- Lost:
  - A single React package: two caches to keep in step with each other and with TanStack's behavior.
  - Shipping the spikes' core hook (`request()` returning a link's promise). The React client owns its promises, so the core is untouched.
- Open: infinite queries, polling (`refetchInterval`), `select`, placeholder data, a devtools panel, streaming pending queries in `dehydrate`, a `useMutation` hook, and staleness timers that re-render `useQueryState` when data goes stale on its own. raf-query has most of these.
- Open: atom-package mutations and subscriptions aren't serializable. `Hydration.dehydrate` needs a registry that keeps idle atoms (`defaultIdleTTL`) until it runs.
