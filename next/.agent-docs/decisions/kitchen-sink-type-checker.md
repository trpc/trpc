# The kitchen-sink editor type-checks in a worker, against declarations the build bundles (agent)

- (agent) For the Open bullet of [`kitchen-sink-demos.md`](./kitchen-sink-demos.md): "a lazy TypeScript worker for errors and hovers in the editor". The first focus of a demo's editor starts a module worker, one per sample for the page's life, that loads TypeScript 6's JavaScript API (the `typescript6` alias Twoslash uses) and the sample's declarations, then checks every file of the demo after each pause in typing. CodeMirror shows the errors (`@codemirror/lint`), quick info on hover and completions; a tab whose file has errors turns red with their count.
- (agent) TypeScript 6, not 7.1: 7.1 is the native compiler, with no JavaScript API to run in a page. Both check the demos' samples the same way at build time.
- (agent) The declarations are a build step (`build/kitchen-sink-types.ts`): a program over the sample's `tsconfig.json` that imports each package a demo can import (`package-names.ts`, which a test keeps equal to `packages.ts`). It keeps every file the program loads under a short path (`/lib/`, `/node_modules/<package>/`, `/packages/…`) and records how each import and `/// <reference types>` resolved. The worker's language service replays those resolutions instead of resolving, so the browser needs no `node_modules` layout, pnpm symlinks or `package.json`s, and resolves exactly as the sample does. A demo file's package import uses the package's resolution from the sample's `src/`; anything outside `package-names.ts` is "Cannot find module", as it fails when the demo runs.
- (agent) Third-party and lib declarations are reprinted without comments: 15.6 MB of source becomes 4.7 MB, 660 KB gzipped, most of it Effect's JSDoc and the DOM lib's. The workspace's own `.ts` sources keep theirs, so hovers on tRPC's API show its docs. The bundle is a module per sample (`virtual:kitchen-sink-types/<sample>`), fetched by the worker in parallel with TypeScript, so the page and the editor load neither until someone focuses the code.
- (agent) Type errors don't stop the app: Sucrase still compiles and runs every edit, as Vite's dev server does.
- Why: renaming a field on the server and watching the client turn red is tRPC's pitch, and the demo now shows it in the page. Replaying the build's resolutions makes the browser's view of the packages the one `tsc` checked, with no hand-kept list of files or paths, and a new package is one line in `packages.ts` and `package-names.ts`.
- Lost: `@typescript/vfs` and `@valtown/codemirror-ts`, which recreate a file system for TypeScript's own resolution; with pnpm's symlinked layout that means shipping links and `package.json`s, and they add little over a 200-line host. Third-party JSDoc in hovers. `worker.format` is `es` for the whole site, so a worker needs module workers (every browser the site supports has them).
- Open: the Effect subpath idea (emitting declarations that import Effect by subpath) would shrink the bundle's largest part.
- Lives in: `www/build/kitchen-sink-types.ts`, `www/src/kitchen-sink/` (`ts-service.ts`, `ts-worker.ts`, `type-check.ts`, `package-names.ts`, `types.d.ts`, `editor.tsx`, `frame.tsx`, `ts-service.test.ts`), `www/vite.config.ts` (`kitchenSinkTypes()`, `worker`), `www/docs/kitchen-sink/overview.md`.
