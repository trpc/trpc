# A streamed output's iterable carries the call's errors, and `safe()` iterates it (human)

- The question (first-release review, 2026-10-19): "A streamed query's typed failures appear in no client type. `ErrorsOf` drops a `Stream`'s `E`, and the client output is a plain `AsyncIterable<A>`, so a `Stream.fail(error({ code: 'X' }))` (or a generator that returns/yields an error) arrives `defined: true` though nothing lists it. Recommended: type the client iterable with its errors, as subscriptions already are (`'~error'` like `TrpcSubscription`)."
- Human, 2026-10-19 (first-release review, question 4): "yes for safe client of safe calls i think".
- (agent) Read as: type them, at least where the safe APIs (`safe()`, `createSafeClient`) expose them, so that iterating a safe call's output can `matchError()` the iteration's error with the stream's codes, `STREAM_INTERRUPTED` and `unexpected`.
- (agent) Server: a returned `Stream`'s `E` is the procedure's errors (`ErrorsOf` in `builder.ts`), like an `Effect`'s, so the client, TanStack and `.errors()` all see it through the one `errors` field. `DeclaredCheck` no longer adds the stream's failures itself (`StreamFailuresOf` is gone). With `.output(stream(Item))` and `.errors()`, a `Stream` failing with an undeclared code is now a type error too; it used to pass (`ValueOf` took any `TrpcError`).
- (agent) Generators: their thrown errors have no type, so they stay typed only when `.errors()` lists the code (as in a resolver). A `TrpcError` a generator yields or returns is a value (an item, or the final value) at runtime, as in a subscription, so it isn't a failure in the types either. Runtime already settled stream failures like a resolver's (`settleStreamed`, `settleIterable`); tests over `httpLink`, `wsLink` and `createRouterClient` check the typed codes arrive `defined: true` with their `data`.
- (agent) Client shape, the subscription pattern: the call's root `AsyncIterable` is a `TrpcIterable<T, TReturn, E>` (`AsyncIterable<T, TReturn> & { '~error'?: E }`), `E` being the call's error, the same union its `TrpcPromise` carries. A `ReadableStream` output keeps its type. One union for the call and its iteration, as a subscription has, which TanStack's streamed queries already need (they report both as the query's error).
- (agent) Iterating safely: `safe()` takes an iterable too and returns an `AsyncIterable<SafeResult<T, E>>`: each item `[item, undefined]`, a failure as a last `[undefined, error]`, then the end; breaking out closes the source; a framework's control-flow error still throws. Subscriptions get it for free (`safe(client.onPost.subscribe())`). `createSafeClient` is `safe()` on each call, as before: its streamed data is the same `TrpcIterable`, for `safe()` to iterate. The overload and `TrpcIterable` are `@stability experimental`.
- (agent) Effect client: a streamed call's `Effect` error channel has the stream's failures (it already had `STREAM_INTERRUPTED`), and its output is the same `TrpcIterable`. TanStack: `queryOptions()`, `streamedMutationOptions()` read the call's `'~error'`, so their error has the stream's failures with no change there.
- (agent) Measured with `pnpm bench shapes` (1,500 procedures, tsc 7, instantiations, against `5af84b5f7` with the new `streamed` shape): see the table below. Three formulations were measured; the cheapest is an inline `D['output'] extends AsyncIterable<any>` in each method's return type, whose streamed branch intersects the value with `{ '~error'?: E }`. An alias around both branches (`CallPromise`) cost calls that don't stream +4 per procedure; inferring the item and return types into a named interface cost the streamed shape twice as much (+6.2% instead of +3.3%, at 300 procedures).

  | shape (with client)    |    before |     after | change |
  | ---------------------- | --------: | --------: | -----: |
  | `plain`                |   954,567 |   957,221 | +0.28% |
  | `links`                |   990,585 |   993,239 | +0.27% |
  | `errors`               | 1,486,131 | 1,440,768 | -3.05% |
  | `effect client`        | 1,856,541 | 1,827,340 | -1.57% |
  | `match`                | 1,810,441 | 1,664,595 | -8.06% |
  | `streamed`             | 1,252,360 | 1,294,379 | +3.36% |
  | `errors` (server half) | 1,026,047 |   985,536 | -3.95% |

  The other shapes move by under 0.5% either way, and `plain` checks with 2.2% fewer types (138,488 to 135,427) in the same memory. `errors` is cheaper because `DeclaredCheck` reads the split errors only; `match` and `effect client` probably because a call's error is now a plain union rather than an alias over the procedure (`CallError<D, F, TLinks>`), which `matchError()` and `catchTag` instantiate less. `streamed` is the only shape that pays: the stream's failures are new members of its union.

- Why: "defined means typed": a `defined: true` error that no type lists can't be handled by `matchError()`, and the stream's codes belong with the call's like a resolver's. Using the subscription's pattern (`'~error'` on the iterable, the call's union) keeps one way to read a stream's errors across the Promise, safe, Effect and TanStack clients.
- Lost: a streamed call's `TrpcPromise` and `Effect` error now list the stream's failures, though the promise itself never rejects with them (the call resolves before its stream fails), so `matchError()` on the call's own error needs their keys; the same over-approximation `STREAM_INTERRUPTED` already had. The iteration's error also lists the call's own (input `BAD_REQUEST`, returned errors). `safe()` on an iterable drops the generator's return value.
- Open: a separate error type for the iteration and for the call (more precise keys, one more conditional per streamed procedure); `createSafeClient` wrapping streamed outputs and `subscribe()` so iteration yields results without `safe()`; the Effect client returning a streamed output as a `Stream` with the error channel instead of an `AsyncIterable`; a generator's `return error()` failing the stream, like a resolver's.
- Lives in: `packages/trpc/src/server/procedures/builder.ts` (`ErrorsOf`, `DeclaredCheck`, `ValueOf`), `src/client/types.ts` (`TrpcIterable`, `Streamed`, `StreamedPromise`, `StreamedError`, `DecorateCarried`), `src/client/client.ts` (`safe`, `iterateSafely`), `src/effect/index.ts` (`StreamedEffect`); tested in `src/client/streamed-output-errors.test.ts`, `src/server/execution/stream-output.test.ts` and `packages/tanstack-query/src/index.test.ts`; documented in `www/docs/server/streaming.md#errors`, `www/docs/client/errors.md#streamed-outputs-and-subscriptions`, `www/docs/server/errors.md` and `www/docs/subscriptions/overview.md`; measured by `tooling/bench/shapes.ts` (`streamed`).
