# Streamed HTTP responses wait for the client (agent)

- (agent) A streamed query, a deferred value, a batch, a subscription's SSE stream, an OpenAPI subscription and the v11 interop's JSONL batch only read the procedure as fast as the client reads the response. The internal `Stream.callback` queues are bounded (`backpressure` in `internal/effects.ts`, 16 items, `Queue.offer` suspends), and OpenAPI's SSE body is a pulled `ReadableStream`. A generator behind a paused client stops at its `yield`; when the client leaves, the generator's `return()` runs. Before this, the server read the whole stream into memory while the socket was full: a 1 KB-per-yield generator went from 5k yields (bounded) to all of them.
- Why: an unbounded queue in front of a slow or stalled client is a memory leak per connection, and Effect's Node server already waits for `drain` on stream bodies, so the queue was the only thing in the way. Generators are lazy in JavaScript; reading them ahead only makes sense up to a small buffer.
- Lost: a producer that is faster than its client now waits for it. One that has to finish on its own schedule should run in the background (for example a publisher) and stream from there.
- Open (human): WebSockets still buffer. `WebSocketLike.send` is synchronous (the WHATWG interface, see [websocket-standard-interface.md](./websocket-standard-interface.md)), and Effect's socket writer and `ws` queue behind it, so a slow WebSocket client grows the server's buffers for every subscription on it. Fixing it means an async `send`, or polling `bufferedAmount` (which WHATWG sockets expose), in `server/sockets/socket.ts` and every transport (`runSocket` in `server/sockets/socket-session.ts` for WebSockets and raw sockets, MessagePort, Cloudflare hibernation). v11 behaves the same. Worth doing before 1.0, or leave it to the platform?
- Lives in: `packages/trpc/src/internal/effects.ts` (`backpressure`), `packages/trpc/src/serializer/stream.ts` (`sourceOf`, the chunk merge), `packages/trpc/src/server/fetch.ts` (`linesResponse`), `packages/trpc/src/server/execution/events.ts` (`emitEvents`), `packages/trpc/src/openapi/handler.ts` (`events`), `packages/trpc/src/interop/jsonl.ts`, tests in `server/fetch-edges.test.ts`, `openapi/openapi.test.ts` and `interop/handler-edges.test.ts` ("waits for a slow client", "nobody reads").
