# tRPC's own failures carry a `reason` (human asked)

- Human, 2026-10-18: "We should probably be more specific with trpc errors too so we just don't use a blanket one everywhere".
- (agent) Effect's shape for this, as in `HttpServerError` and `AiError`: one error, and a tagged `reason` saying which failure it was (`.repos/effect/packages/effect/src/http/HttpServerError.ts`). The one isomorphic `TrpcError` stays ([`errors.md`](./errors.md)), and its `_tag` stays its code ([`error-tags.md`](./error-tags.md)).
- (agent) `TrpcErrorReason` is a closed `Data.TaggedEnum` of about 60 failures tRPC makes: reading a request (`BodyTooLarge { limit }`, `InvalidJson`, `UndecodableInput`, …), finding the procedure (`ProcedureNotFound { path }`, `WrongProcedureType`, `BatchTooLarge { maxItems }`, …), running it (`NotImplemented`, `Aborted`, `Unexpected`, …), durable calls, socket messages, connection tokens, client links (`FetchFailed`, `ConnectionLost`, `SerializerMismatch { server, client, transport }`, `UnexpectedStatus { status }`, …) and streams. A reason's fields are what its message needs, and what a log wants.
- (agent) Internals build errors with `failure(Reason.X(…), cause?)`, not `new TrpcError({ code, message })`. One table in `internal/failure.ts` fixes each reason's built-in code and another its message, so codes, messages and the wire format are unchanged (the full suite passed untouched). `UnexpectedStatus` takes its code from the status.
- (agent) `TrpcError.reason` is public and optional, and never serialized: it stays on the side that made the error. `onError` sees the server's; on the client only link-made errors have one; errors users make have none. Users match it with `Predicate.isTagged(err.reason, 'BodyTooLarge')`. `withDefined` and `toBuiltinError` keep it.
- (agent) Internals type their failures precisely: `Failure<ReasonOf<'BodyTooLarge' | 'BodyUnreadable'>>` is a union of errors, each `TrpcError<code> & { reason }`, so `Effect.catchTag('PAYLOAD_TOO_LARGE', …)` narrows the reason and `Effect.catchReason` picks one out (`server/body.ts`'s `readBytes` is typed this way). Public errors stay `AnyTrpcError`, whose optional `reason` `catchReason` can't narrow.
- (agent) Not reasons: errors rebuilt from a wire or a store (`fromWireError`, `fromOpenApiError`, durable replays), declared and input-validation errors (typed, with `data`), the masked `INTERNAL_SERVER_ERROR` that replaces an unexpected one, and the v11 interop handler, which sends v11's own messages.
- Why: the same code covered unrelated failures (`PARSE_ERROR` for bad JSON, a bad multipart body or an undecodable input; `NETWORK_ERROR` for a failed fetch or a lost socket), built ad hoc in up to four places each with copied messages, and typed `AnyTrpcError` throughout.
- Lost: a free-text message at each site (a new failure needs a reason, a code and a message in the table); one more field on `TrpcError`.
- Open: reasons for the v11 interop handler's failures; whether clients should type link-made errors with their reasons, so `catchReason` works on the Effect client.
- Lives in: `packages/trpc/src/internal/failure.ts`, `src/internal/error.ts` (`reason`, `REASON`), every handler and link in `src/server/`, `src/client/links/`, `src/openapi/` and `src/cloudflare/token.ts`; tests in `src/internal/failure.test.ts` and `src/server/reasons.test.ts`; `docs/server/errors.md#trpcs-own-failures`.
