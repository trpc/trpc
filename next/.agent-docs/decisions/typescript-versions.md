# The repo builds with TypeScript 7.1; users need 5.7 or later with `strict` (human asked)

- Human, 2026-10-20: "Make v12 support the 7.1 ts beta. If you can do optimisations due to it, feel free to set it as a minimal peer dep. You can ignore benchmarks in any older ts version as well. 7.1 should be the one we use in the project as our goto."
- (agent) Every `package.json` has `typescript: 7.1.0-beta`, pinned exactly: `^7.1.0-beta` resolves to the `7.1.0-dev.*` nightlies, which sort after `beta`. Benchmarks run on it alone. Twoslash 0.3.9 needs TypeScript 6's JavaScript API, which 7 replaced, so the docs site compiles its blocks with the `typescript6` alias; Hey API and svelte-check run their own TypeScript too.
- (agent) The peer stays `>=5.7.2`. 7.1 changed no instantiation count in `pnpm bench shapes` beyond `match` (+5%, fixed by a cheaper `matchError` constraint that is as cheap on 7.0), so nothing in the types needs 7.1 ([`type-check-shapes.md`](../notes/type-check-shapes.md)). A `>=7.1.0-beta` peer would fail `npm install` with `ERESOLVE` in every app on TypeScript 5, 6 or 7.0, since npm checks an optional peer that's installed, and Next, svelte-check, Hey API and Twoslash still need 6.
- (agent) The published declarations type-check on TypeScript 5.7.2, 5.9.3, 6.0.3, 7.0.2 and 7.1.0-beta (checked 2026-10-20 against the built `@trpc12/trpc`, `@trpc12/tanstack-query` and `@trpc12/tanstack-react-query`: every `@trpc12/trpc` entry point, a router with `.errors()`, a client, `safe()` and `matchError()` with their `@ts-expect-error` cases, and `queryOptions` in `useQuery`, with `skipLibCheck: false`). 5.6 fails on `Uint8Array<…>`, which Effect's own declarations use too, and 5.4 on `AsyncIterable<T, …>`. `strict: false` fails inside `client/types.d.ts` and loses the output form (a `Date` stays a `Date` over JSON). The declarations use `AsyncDisposable`, so `lib` needs `esnext.disposable` (or `esnext`) unless `skipLibCheck` is on, as for Effect. On 7.1 with `skipLibCheck: false`, zod 4.6.5's own declarations fail with TS5115 (circular instantiations); zod 4.6.7 fixed it ([colinhacks/zod#6637](https://github.com/colinhacks/zod/issues/6637)).
- (agent) `experimental_generateOpenApiFromTypes` imports `typescript/sync`, which 7.1 added in place of 7.0's `typescript/unstable/sync`, so it fails to load on anything older; its docs say it needs 7.1. Its declarations don't reference `typescript`.
- Why: v11 supports TypeScript 5.7.2 and later, so v11 apps can install the preview without upgrading their compiler first.
- Lost: a peer range that says the OpenAPI type generator needs 7.1. CI type-checks with 7.1 only, `tooling/portability` included; the range below it is re-checked by hand.
- Open: move the peer to `>=7.1` once Next, svelte-check and Twoslash run on 7, if the types then use something 7.1 adds. Re-check the range by hand when the declarations start using newer syntax. `vp check`'s type-aware lint runs oxlint-tsgolint, which embeds TypeScript 7.0 until it ships a 7.1 build.
- Lives in: `packages/trpc/package.json` (`peerDependencies.typescript`), `pnpm-workspace.yaml` (`minimumReleaseAgeExclude`), `www/build/markdown.ts`, `www/docs/getting-started.md`, `www/docs/openapi/document.md`, `packages/trpc/src/openapi/typescript.ts`.
