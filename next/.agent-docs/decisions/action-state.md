# Actions take `useActionState`'s call; React's hooks replace `useServerAction` (agent)

- (agent) For the parity row "`createFormAction`, `useServerAction`, optimistic actions" (oRPC `server-action.md`), which had no decision. `action(procedure)` already takes a form's `FormData` (oRPC's `createFormAction`). It now also takes `(previousState, inputOrFormData)`, the call `useActionState` makes, so `useActionState(createPost, undefined)` types its state as the action's result (or `undefined` before the first submit) and its payload as the input or `FormData`.
- (agent) No `useServerAction` or `useOptimisticServerAction` hook. React 19's `useActionState` gives the result and `isPending`, and `useOptimistic` the optimistic value, so @trpc12/trpc ships no React code for actions and keeps `@trpc12/trpc/actions` free of React ([`react-use-package.md`](./react-use-package.md): no React package in v1). `docs/actions-and-rsc.md` shows both hooks together.
- (agent) The previous state is ignored: with two arguments, the second is the input. An action bound with `.bind(null, x)` therefore reads the form, not `x`; procedures take one input, so bound arguments have no slot anyway.
- Compared: oRPC's `useServerAction(action)` returns `{ execute, data, error, status }` and is a separate React package; v11 had `experimental_serverActionProcedure` with a `useAction` hook in `@trpc/next`.
- Lost: an `execute()` with status flags outside a form or transition (`startTransition(() => submit(input))` does it).
- Lives in: `packages/trpc/src/actions/index.ts` (`Action`), `packages/trpc/src/actions/actions.test.ts`, `packages/trpc/src/actions/react.test.tsx`, `docs/actions-and-rsc.md#form-state-and-optimistic-updates`.
