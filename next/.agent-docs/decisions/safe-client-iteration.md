# `createSafeClient` iterates a streamed output and `subscribe()` safely on its own (human)

- The question (decision round, 2026-10-20): should `createSafeClient` make a streamed output's iteration safe on its own? Its queries and mutations resolved to `safe()` results, but the streamed output inside was the plain `TrpcIterable`, and `subscribe()` was the plain `TrpcSubscription`: both threw while iterated unless wrapped in `safe()` again. It follows [`streamed-output-errors.md`](./streamed-output-errors.md), whose answer was "yes for safe client of safe calls i think".
- Human, 2026-10-20 (decision round): "B". The safe client iterates safely too: a streamed output and `subscribe()` on a safe client yield `[item, error]` without `safe()`. Nothing on a safe client throws, as with oRPC's `createSafeClient`, except a framework's control-flow error (Next's `redirect()`), which `safe()` rethrows too.
- (agent) Runtime: `createSafeClient` settles `query()` and `mutate()` with `safe()`, and when the data is a root `AsyncIterable` other than a `ReadableStream`, it's iterated as `safe(iterable)` iterates: each item `[item, undefined]`, a failure a last `[undefined, error]`, breaking out closes the source. `subscribe()` returns `safe(subscription)`. A `ReadableStream`'s bytes have no typed failures, so it stays as it is. `safe()`'s iteration is now a `Stream` (`Stream.fromAsyncIterable`, `Stream.catch`, `Stream.toAsyncIterable`) instead of a hand-written generator ([`effect-apis-over-hand-rolled.md`](./effect-apis-over-hand-rolled.md)).
- (agent) Types: `SafeClient` checks the call's data with an inline `T extends AsyncIterable<any>`, then infers the item only in that branch, so calls that don't stream pay one cheap check; a streamed output becomes `AsyncIterable<SafeResult<Item, E>>`, `E` being the call's error, and `subscribe()` returns `AsyncIterable<SafeResult<T, E>>`. The iteration's error is the call's union, as `safe(iterable)` gives ([`streamed-output-errors.md`](./streamed-output-errors.md)).
- (agent) Measured with `pnpm bench shapes` (1,500 procedures, `typescript@7.1.0-beta`, instantiations), on two new shapes that call through `createSafeClient`: `safe client` (`plain`'s procedures) and `safe streamed` (`streamed`'s, each output iterated: through `safe()` before, directly after). Three formulations were measured; the cheapest is the one above. Inferring the item in the first check (`T extends AsyncIterable<infer I>`) cost `safe client` +1.3% instead of +0.8%; putting the check on the method's return type, around two `Promise<SafeResult<…>>` branches, cost `safe streamed` 1,500 more.

  - `safe client`: 1,412,394 before, 1,423,646 after (+0.80%)
  - `safe streamed`: 2,036,829 before, 2,144,069 after (+5.26%), with 7% fewer types (321,659 to 299,151) and 8% less memory (388 to 356 MB)
  - `plain` and `streamed`, which don't use `createSafeClient`, are unchanged (957,634 and 1,294,795).

  `safe streamed` pays because each streamed procedure's data now goes through the conditional and a `SafeResult` per item, where before a `safe()` call at each loop was the only cost.

- Why: a safe client that throws while iterating surprises people who picked it so nothing throws, and a streamed call needed two `safe` layers.
- Lost: A, keeping `safe()` around each iteration: one rule (`safe()` is what makes anything safe), and a plain `for await` on the safe client's iterable for code that wants to throw. C, a separate `.safe()` on every streamed iterable and a `safeSubscribe()`: explicit at the loop, with one iterable type everywhere, for a new method and a second subscribe verb doing what `safe()` already does. Code moving between the plain and safe clients changes its loops, since their iterables differ. `safe()` on a safe client's iterable now wraps each result again; it isn't needed there.
- Open: the two points [`streamed-output-errors.md`](./streamed-output-errors.md) leaves open, a separate error type for the iteration and a generator's `return error()` failing the stream, weren't part of this answer.
- Lives in: `packages/trpc/src/client/client.ts` (`SafeClient`, `createSafeClient`, `iterateSafely`); tested in `src/client/streamed-output-errors.test.ts` and `src/server/errors.test.ts`; documented in `www/docs/client/errors.md#streamed-outputs-and-subscriptions`; measured by `tooling/bench/shapes.ts` (`safe client`, `safe streamed`).
