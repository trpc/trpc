# Type-safe error boundaries ship as `unstable_createErrorBoundary`, a `[Boundary, useBoundary]` tuple in `@trpc12/tanstack-react-query` (human)

- Human, 2026-10-20 (Q24.4), on the open question's first version: "It's basically type safe error boundaries. The mutation example is a bit confusing, but for queries it'd be easier to grok... Kinda tempted to ship something experimental about this, but expand on the example and come back to it."
- Human, 2026-10-20 (Q24.4, Q24.5): "We should do shells, but make sure they're tuples in react to follow react context normalnconventions and that we throw if the context can't be found". That is the open question's E (proposal 24's A, boundary mode, shipped now behind a prefix), with two changes: a tuple instead of the spike's object with static members, and hooks that throw outside their boundary.
- Human, 2026-10-20: "Let's have shells as unstable_ but let's also jam with some alternative names, I found thay naming weirdn". So `unstable_`, not E's `experimental_`: the feature stays, and its shape can change in a minor ([stability-jsdoc-tags](./stability-jsdoc-tags.md)).
- Human, 2026-10-20, picking a name: "Do number 1, just call it error boundary". So `unstable_createErrorBoundary`, used as `const [AuthBoundary, useAuthBoundary] = unstable_createErrorBoundary(...)`. "Shell" is gone from the API and the docs.
- Human, 2026-10-20: "Do some more digging on the DX alternative nitty gritty and give me a decisions". The open questions below.
- (agent) What's built, internal for now (`createErrorBoundary`, not exported):
  - `createErrorBoundary({ name, parent?, claims, unexpected?, fallback })` returns `[Boundary, useBoundary]`. `claims` lists codes; `unexpected: true` owns every `defined: false` error too; `parent` is the boundary component it sits under. Its owned codes add up along `parent`, so `useAuthBoundary().useQuery(...)`'s `error` is typed without `UNAUTHORIZED` and what `Root` owns, and `matchError()` below it needs no handler for them.
  - The hook returns `{ useQuery, useMutation, owns }`. Those set TanStack's `throwOnError` to "this boundary or one above it owns it", or-ed with the options' own `throwOnError`. Each `Boundary` renders its `fallback` for its own claims and re-throws the rest.
- (agent) Why this tuple: it's `createTrpcContext`'s `[TrpcProvider, useTrpc]`, and what context helpers in React apps return (`const [Provider, useThing] = createSafeContext()`). The caller names both, so two boundaries never shadow each other. The component comes first because the tree needs it once and components many times. A tuple can't carry static members, so the parent is the component itself (`parent: RootBoundary`), and its owned codes ride on a type-only brand, as TanStack's `DataTag` does on query keys. Whether the hook returns hooks or option transforms, and whether the tuple has two or three elements, is open: [error-boundary-hook](../open/error-boundary-hook.md).
- (agent) Calls with an obvious answer, not asked:
  - **A missing boundary throws**, on the first render, as the human asked. The hook outside its boundary: `The Auth error boundary's hook found no <AuthBoundary> above it: wrap the tree in <AuthBoundary>`. A boundary without its parent above it: `<AuthBoundary> needs <RootBoundary>, its parent, above it`. Both name the component as it's written in JSX, which is the fix, like React's own "must be used within" errors. result-rpc throws on the first render too; react-error-boundary's `useErrorBoundary` does too.
  - **`displayName` is `${name}Boundary`**, so React DevTools and the messages read `<AuthBoundary>`.
  - **The fallback gets `{ error, reset }`.** `reset` is TanStack Router's and Next.js's name (react-error-boundary's is `resetErrorBoundary`). It resets the failed queries under the boundary, so they refetch, then renders the children again.
  - **One `QueryErrorResetBoundary` for a whole chain**, made by the outermost boundary. The spike found that with one per boundary, retrying from `Offline` reset the wrong one and the query never refetched.
  - **Nesting:** the innermost boundary that claims an error renders it, and a boundary re-throws what it doesn't claim, so an error no boundary owns reaches the app's own error boundary, as an error thrown past react-error-boundary or `CatchBoundary` does. An error the options' own `throwOnError` throws, but no boundary owns, goes the same way.
  - **A code claimed twice in a chain** goes to the innermost claim, so a page can own `NOT_FOUND` under an app-wide one. result-rpc rejects a duplicate claim when the shell is defined; here it's legal, since nesting is how React boundaries work.
  - **Suspense:** `useSuspenseQuery` throws every error while it has no data, so its owned errors already reach their boundary and the rest go past it; nothing to wrap, and there's no `error` to type. `reset` refetches them like the others. The docs page says so; there's no suspense hook.
  - **SSR:** React doesn't run error boundaries on the server. A query that fails while streaming SSR makes React render that Suspense boundary again on the client, where the error boundary catches it. A failed prefetch isn't dehydrated, and a pending one that `hydrationOptions()` streams fails on the client, so the client's boundary takes the error either way. The docs page says so; there's nothing to build.
  - **React only, all in `@trpc12/tanstack-react-query`** (Q24.5 B for now). `owns()`, `Remaining` and the `throwOnError` transform have no React in them and can move to `@trpc12/tanstack-query` (Q24.5 A) when another adapter wants boundaries, re-exported so nothing breaks.
  - **Stability:** `unstable_createErrorBoundary` is `@stability unstable`. Its types keep their names (`ErrorBoundarySpec`, `ErrorBoundaryFallbackProps`, `ErrorBoundaryComponent`, `Remaining`), tagged `unstable`. Its docs page is `www/docs/integrations/tanstack-query/error-boundaries.md` with `stability: unstable`: badged, listed and indexed, not hidden in an experiment.
- Why: a component's `error` lists only what it must handle, and the app's sign-in, offline and crash handling is written once, in components that own them, with types to match. Boundary mode needs nothing from TanStack. `unstable_` lets apps use it while the questions below get answered from use.
- Lost:
  - The open question's A, no boundaries: each component handling the whole union, with app-wide failures in `unexpected` or an untyped boundary.
  - Its B as a stable, unprefixed export now: the shape isn't settled.
  - Its C, a side-effect mode (`mode: 'react'`, the hook's `error` `null` while `status` is `'error'`, `onError` with `retry`). What an owned mutation error does is asked again in [error-boundary-owned-errors](../open/error-boundary-owned-errors.md).
  - Its D, the primitives only (`owns()`, `Remaining` and the options transform, with each app writing its boundaries, the mounted-chain check and the shared reset boundary).
  - The spike's API: `createShell()` returning `{ Boundary, useQuery, useMutation, owns }`, `RootShell.extend({ … })` for nesting, and hooks that only checked their chain at render.
  - E's `experimental_` prefix and its page hidden in an experiment.
