# TanStack Query subscriptions: one observer, plus streamed and live queries (human)

- Human, 2026-10-15 (Q19.5): "Sure thay could be good.... There light be some nuances though as sometimes you only care about the last value and sometimes aggregated. But good if we could dedupe them automatically". `streamedOptions` (every event, capped by `maxChunks`) and `liveOptions` (the latest event) ship in v1. Both run through TanStack's cache, so components with the same key share one subscription.
- (agent) `SubscriptionObserver` is the framework-agnostic core, like TanStack's `QueryObserver`. Statuses are `idle`, `connecting`, `active` and `error`. It starts with the first listener and stops with the last; a new key or `enabled` restarts it; callbacks use the latest options; `reset()` starts it again; each change is a new immutable result. Every adapter wraps it in a few lines, so semantics match everywhere.
- (agent) Adapters start subscriptions only in the browser lifecycle, never during SSR: an effect (React, Preact), `onMounted` or immediately in a bare effect scope (Vue), `onMount` (Solid), `$effect` (Svelte), `afterNextRender` (Angular), `hostConnected` (Lit).
- (agent) `streamedOptions` accumulates a subscription's events into an array, with TanStack's `refetchMode` and an optional `maxChunks`; `liveOptions` keeps the latest event. A query whose output is an `AsyncIterable` also streams through `queryOptions()`, and its data is the chunk array.
- (agent) Lost: subscription state only in the `QueryClient` cache (`liveOptions` alone). It's kept next to `useSubscription`, not instead of it, because `onData` callbacks and per-event side effects don't fit the cache.
- (agent) Observers share one subscription per client and key through a `SubscriptionCache` (one per client, in a `WeakMap`), as TanStack's cache does for queries. A late observer starts from the current state; each keeps its own callbacks, so `onData` runs once per observer and event; `reset()` restarts it for all of them; it closes when the last one leaves. Options without a cache (hand-written, or `subscriptionCache: undefined`) keep an observer's own subscription. Call context isn't part of the key, as with queries.
- (agent) Inside, each start of a shared subscription is a `Stream.fromAsyncIterable` loop forked into a child scope of the cache's `Scope`, and `subscribe`'s signal is that scope's `Effect.abortSignal`. Leaving, a new key and `reset()` close the child scope; interruption replaces the old `live()` checks ([`effect-internal-patterns.md`](./effect-internal-patterns.md)). The child scope runs its finalizers in parallel: `fromAsyncIterable` awaits the iterator's `return()` when interrupted, and an async generator waiting on a signal-aware source only settles that once the signal has aborted (test "leaving a hand-written subscription aborts its signal while its generator awaits").
- (agent) The member set stays a plain `Set`, not an `RcMap`. Each member needs its own callbacks and synchronous pushes, so the set exists anyway and already counts them. `RcMap` would add ~1.4 kB gzip to a TanStack bundle (rolldown probe of `RcMap` + `FiberHandle` + `Stream` against `FiberHandle` + `Stream`, 2026-10-19) to count it again. Its `idleTimeToLive` linger would be a new behaviour, not wanted here. The move to Effect cost 432 B gzip (`createTrpcQueryUtils` + `SubscriptionObserver` with `httpLink`: 41,701 to 42,133 B, streamed mutations included).
