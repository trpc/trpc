- (agent) `pnpm --filter @trpc12/www old-docs:copy` (`www/build/old-docs-copy.ts`) reads trpc.io's Docusaurus site in `v11/www/` (v11 in `docs/` with `sidebars.ts`; v10 and v9 in `versioned_docs/` with `versioned_sidebars/`) and writes every page of each version's sidebar to `next/www/<version>/docs/<slug>.md`, at trpc.io's slugs (`/docs/v10/server/procedures` is `/v10/docs/server/procedures`; v11 is served at `/docs`, as on trpc.io, since 2026-10-18, see [`docs-v11-by-default.md`](./docs-v11-by-default.md)), with the sidebar's top-level categories as sections in `<version>/sections.json` and the images the pages show in `www/public/<version>/img`. The copies are committed, and nobody edits them: after the docs change, run the copy again. Leaving the old docs alone means leaving the copies alone.
- (agent) Nothing is left out by accident. Every file git lists under `v11/www/docs`, `v11/www/versioned_docs` and `v11/www/blog` is copied, or it's in `notCopied` in `old-docs-copy.ts` with why (v10's copies of the home page's `landing-intro` steps, a Twoslash test page, `authors.yml`, the `.gitignore`s); a partial no page includes is noted as such. The copy fails on any other file (a doc no sidebar lists, a post in a folder, an image beside a doc), on a `notCopied` entry that's gone or copied, and on two files that would be written to the same path, before it writes anything. `next/www/old-docs.json` lists each file and what was written from it: the page or post, the pages a partial or component is inlined into, an image's copies.
- (agent) The copy is deterministic: it reads the files git lists in `v11/www/` (tracked, or untracked and not ignored), so a local Docusaurus build's API reference stays out; it sorts by code unit, not locale; and two runs over a tree write the same bytes. `old-docs:check` copies into a scratch dir and fails on any committed copy that differs, is missing, or is left over.
- Nothing reruns or checks the copy automatically: no post-merge hook, no CI job, and `next.yml` doesn't run on changes to `v11/www/`. After merging `main` (or whenever the copies should catch up), an agent follows [`.agents/skills/sync-old-docs/SKILL.md`](../../../.agents/skills/sync-old-docs/SKILL.md): fetch the v10 and v9 release tags, copy, bump `samples/v11`'s `@trpc/*`, build, check, commit. (agent) Why: with v11's 378 blocks compiling, a sync can need a new canary or package before it builds, which a hook in the middle of a merge can't do.
- (agent) The conversion (`www/build/old-docs-convert.ts`) is pure and turns MDX into this site's Markdown. v11's Twoslash blocks (its pages and the home page's steps) stay Twoslash, with `// @include:` expanded and the `// ^?` queries in hidden setup dropped (trpc.io's renderer ignores them; the site's rejects them); older versions' and the blog's become the plain code trpc.io shows (hidden setup, `// @…` directives and `// ^?` markers go, `// @include:` is expanded). Admonitions become alerts with their titles, `<Tabs>` become tab groups (package managers switch with the install commands), partials, `<InstallSnippet>`, `<YouTubeEmbed>`, v10's StackBlitz `<Iframe>`, SVG imports and the static components are inlined, and HTML comments go. Anything else fails the copy, so a new construct in the old docs doesn't render as raw MDX. A `:::tip` inside an open tip closes it: trpc.io's v9-to-v10 migration guide has one by mistake, and Docusaurus nests the rest of the page in it.
- (agent) Links go where trpc.io sends them, after its redirects (`www/vercel.json`), to the copied page of whichever version that is (a cross-version link is that page's path here), to the copied image, to the copied blog post, or else to trpc.io (the API reference, `/discord`). One exception: the v10 and v9 docs were written as the current docs, so their `/docs/…` links, which trpc.io now serves from v11, go to the page in their own version where it has one. A category that opens a Docusaurus generated index (v10's "Backend Usage") gets that page, listing its items.
- (agent) No link is broken. The site's build fails on a link to a page or heading that doesn't exist, and every heading's id counts, not just the table of contents' `h2`/`h3`. The copy drops the `#hash` of links to headings that exist nowhere (Docusaurus only warns about them). Links to the repo's `main` from v10 and v9 point at the version's last release (`v10.45.4`, `v9.27.4`, read with `git ls-tree`) where it has the file, since `main` holds v11's code. Pages that moved or went away since the docs linked them are in `movedLinks`: their new address, the project's repo, or a Web Archive snapshot. On 2026-10-18 every external link answered except bot checks (Cloudflare, Vercel's checkpoint) in front of pages that exist.
- (agent) A nested category nests in the sidebar as on trpc.io: the doc or generated index it links, or else its first doc, is the parent page (labelled with the category's name), and its other items are that page's children, at any depth ([`docs-nav-levels.md`](./docs-nav-levels.md)). A nested category that opens with none has no page to hang from, so its items stay in place in the parent's list. A doc outside the categories (v10's migration guide) is a section of its own.
- (agent) The site serves each copy with an instance of the docs plugin (`build/content.ts`, `virtual:<version>-docs-manifest`), without agent files or the sitemap: each page's canonical link is its trpc.io URL, where those docs stay.
- (agent) v11's blocks compile as v12's do (hovers, `// ^?`, the build failing on an undeclared error), in their own sample app, `www/samples/v11` (`inlineApp: 'v11'`), against tRPC v11 from npm rather than the workspace, since `main`'s packages aren't in `next/`. The app pins `@trpc/*` to the canary built from the `main` the docs came from, not the latest release: the docs show `main`'s API (`.errors()` isn't in 11.19.0). It has none of its own files for the blocks to see, since each brings its own (`// @filename: server.ts`) as on trpc.io, and the packages its blocks import (validators, adapters, Next.js, React), pinned. Blocks with the same file names compile one after another, so the renderer deletes a block's files after it instead of emptying them: an emptied `utils/trpc.ts` from one block still resolved before the next block's `utils/trpc.tsx`, with no text.
- (agent) As in Docusaurus, a version dropdown in the header switches between "v12 experimental", "v11 stable", "v10 unmaintained" and "v9 unmaintained", landing on the page of the same topic, and every page has a banner that says which version it is, linking to its counterpart in the version to read instead (v11 for v12, v10 and v9; v12 for v11), or else to that version's first page. Between the copies, a page's counterpart is the page at its slug, as in Docusaurus. A v12 page's v11 counterpart is the page its `v11` frontmatter names, or the v11 page at its own slug; a v11 page's is the v12 page at its slug, or else the first v12 page that names it; v10 and v9 go by way of v11. Search looks in the version being read.
- (agent) The same copy brings over trpc.io's blog (`v11/www/blog`) to `next/www/blog/<slug>.md`, served at `/blog` and `/blog/<slug>` by `build/blog-content.ts` (`virtual:blog-manifest`). The date and slug come from the file name (or its `slug`), the authors from `authors.yml` or the post's own `author*` fields, and the description from its first paragraph. A post's links resolve as a v11 page's, since trpc.io's blog is read beside its current docs. An embedded post on X becomes a link to it; one that's been deleted (Dan Abramov's, in "Using Server Actions with tRPC") becomes a note that says so. Each post's canonical link is its trpc.io URL, and posts stay out of the sitemap; `/blog` is in it. The header, the mobile menu and the footer link `/blog`.
- (agent) The same copy converts the three steps of trpc.io's home page intro (`www/docs/landing-intro/Step{1,2,3}.md`) to `next/www/v11/home/step-{1,2,3}.md`, Twoslash blocks as on trpc.io, which the home page's v11 view imports (`build/content.ts`'s `snippetsDir` renders them, compiled in `samples/v11`). v10's copies of those steps aren't copied: nothing shows them.
- Why: readers of every version keep their docs next to v12's, linked page by page, at no upkeep: the copies are generated, and trpc.io stays the source.
- Lost: Twoslash types in v10's, v9's and the blog's code blocks (they'd need their own apps on v10 and v9), and the generated API reference (it links to trpc.io); edits to the copies, which the next copy overwrites. The `movedLinks` fixes and the release pinning are the copies' only: trpc.io still has those dead links. With no hook or CI check, the copies fall behind `main` until someone syncs them, and nothing says so. A cold `pnpm docs:build` compiles v11's blocks too (a few minutes; CI caches them).
