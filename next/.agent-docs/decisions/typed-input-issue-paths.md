# Input issue paths are typed from the input (human asked)

- Human, 2026-10-17: "With us inferring errors and only supporting standard schema, couldn't we also infer the shape of input errors?"
- (agent) Standard Schema fixes an issue's shape (`{ message, path? }`) for every library, with no per-schema issue type, so the path is what all libraries share: it follows the input's shape, and that is known. `InOf<Schema>` is the Standard Schema input type or the Effect Schema `Encoded` type, the side validation checks. The libraries' own fields are [`zod-and-effect-input-issues.md`](./zod-and-effect-input-issues.md).
- (agent) `IssuePath<TInput>` is `readonly []` for the whole input, then a key or index per level (`['tags', 0]`, `['author', 'name']`), distributed over unions. Numeric object keys are their strings. `Date`, binary data, `Blob`/`File` and functions are leaves. `unknown` inputs, `Map`, `Set` and levels past the sixth (recursive types) fall back to `ReadonlyArray<string | number>`. `InputIssue<TInput>` (the shape for libraries other than zod and Effect) and `InputValidationErrorData<TIssue>` default to the untyped shape.
- (agent) Per schema, not per procedure: each chained `.input()` adds its own `BAD_REQUEST` with its own paths, because each schema validates the raw input on its own and middleware can change the input between them (`next({ input })`). On the client, `err.data.issues` is then a union of arrays, and `issue.path?.[0]` is the union of both schemas' keys.
- (agent) Types only. The runtime OpenAPI document keeps its generic `issues` schema.
- Why: forms match issues to fields without casts, and a misspelled key (`path[0] === 'titel'`) is a type error.
- Lost: a schema can report a path outside its input type, and the type doesn't allow for it: a refinement given its own path (zod's `refine(…, { path })`), or a strict object rejecting an unknown key (Valibot's `strictObject` and ArkType's `'+': 'reject'` report the key's path; zod 4 reports `[]`). Typing paths as `Key | (string & {})` would cover those, but loses the typo check. Typecheck cost: each procedure with an input now has its own error type instead of sharing one. `pnpm --filter @tooling/bench bench typecheck` (3,000 procedures, every one with an input) went from 1,105,865 to 1,217,050 instantiations (+10%), check time 0.88s to 0.93s. The paths themselves are lazy: replacing `IssuePath` with the untyped array changes nothing.
- Open: whether the typo check is worth the paths a refinement can report outside the input type.
- Lives in: `packages/trpc/src/server/validation/schema.ts` (`IssuePath`, `InputIssue`, `inferInputIssue`), `src/server/procedures/builder.ts` (`InputDef`), `src/contract/index.ts`, `packages/trpc/src/server/basics.test.ts`, `www/docs/server/procedures.md`.
