# A docs website in `next/www`, rendered from `next/docs` (human asked)

- Human, 2026-10-17: "build a website in the `next/www` folder for v12 … borrow ideas freely and steal stuff from raf-query (also my package); it uses shadcn nicely and has good twoslash stuff that is cached etc. … ignore v11 linking etc for now". This supersedes Q21.5's "We won't build the website yet" ([`repo-and-tooling.md`](./repo-and-tooling.md)).
- (agent) `next/docs/` stays the source: plain Markdown that reads on GitHub, one short page per topic in a folder per sidebar section (`server/`, `middleware/`, `client/`, `subscriptions/`, `openapi/`, `adapters/`, `integrations/`, `migrations/`). Frontmatter (`title`, `description`, `section`, `order`) is required; `section` must be one of `sections` in `www/src/site.ts`. `docs/README.md` is the GitHub index and isn't a page.
- (agent) The site is raf-query's: TanStack Start, prerendered to static files, Tailwind 4 and shadcn (base-ui) components from `shared/ui` ([`shadcn-lib-and-branding.md`](./shadcn-lib-and-branding.md)), Shiki with `@shikijs/twoslash`, a disk cache of compiled blocks, `llms.txt`, `llms-full.txt` and a `.md` twin of every page (also on `Accept: text/markdown`). The build pipeline is Effect, under `www/build/`, with its tests in the root `node` project.
- (agent) A `ts twoslash` block compiles in the `www/samples/docs` app: its imports resolve against the workspace packages, `./server.ts` and `./client.ts` are the app's shared router and client, and `// @filename:` defines more files (a block's file replaces the app's file of the same name). A type error the block doesn't declare with `// @errors:` fails the build, so examples can't drift from the API. Blocks that need platforms the app doesn't install (Workers, Lambda, Nest, React hooks) stay plain `ts`.
- (agent) Links between pages are relative `.md` links, so they work on GitHub too. The build rewrites them to site URLs and fails on a missing page or heading; links outside `docs/` go to the file on GitHub (`site.sourceUrl`).
- (agent) The cache lives in `www/node_modules/.cache/twoslash`, one file per block, keyed by the block, its compiler options, the app files it read and the lockfile. CI restores it in the `www` job of `next.yml`.
- Why: compiled examples are the only docs that stay right through a rewrite this large; keeping Markdown as the source keeps the GitHub reading and the agents' workflow ("update docs with each change") as they were.
- Lost: MDX and React components inside pages (a page is Markdown only); typechecking the blocks that stay plain `ts`; a generated API reference.
- Open: the Vercel project and the domain (`site.url` is `https://v12.trpc.io`, unclaimed); the repo side is ready ([`docs-website-on-vercel.md`](./docs-website-on-vercel.md)); links to and from the v11 site; versioned docs; full-text search (the dialog matches titles, descriptions and headings).
- Lives in: `next/www/` (`build/`, `src/`, `samples/`), `next/docs/`, `next/vite.config.ts` (`www/build` tests), `.github/workflows/next.yml` (`www`).
