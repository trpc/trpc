# RPC URLs can join path segments with `~`, `_` or `-` instead of `.`, opt-in and in URLs only (human asked)

- The question: Q10.2 put `.` in URLs (`/trpc/post.byId`, [`routers.md`](./routers.md)), and some firewalls and WAFs block `.` in URL paths, so those users can't reach a tRPC API over HTTP ([#5752](https://github.com/trpc/trpc/issues/5752)). Draft PRs explored an opt-in separator: v11's #7845 on `main` and this one, #7846.
- Human, 2026-11-03 (via the coordinator), on #7845's final design: "ship it". And for v12: once #7845 is decided, "follow suit and merge it straight on the v12 branch". #7845's design: a type-only `'.' | '_' | '~' | '-'` (no `/`), no runtime check of the value, the `'.'` default resolved once where public options are read and required inside, the router-key check kept, and `'~'` recommended in the docs.
- `experimental_pathSeparator` on `createFetchHandler`, `httpLink` and `experimental_generateOpenApi` (`target: 'rpc'`). The handler maps the URL to the dotted path once, before lookup, and still serves the dotted URL, so servers can move before clients. Everything else keeps `post.byId`: middleware `path`, `onError`, `createContext`'s `info.calls`, batch bodies, socket frames, contracts, query keys, OpenAPI operation ids, durable-call and rate-limit keys.
- (agent) The type is RFC 3986's unreserved punctuation: URLs never escape it, normalizers leave it alone, routes give it no meaning. `/` would need catch-all routes in every adapter and framework (Next.js `[trpc]` files, Fastify's `:path`, Lambda's `pathParameters`, measured in #7845), and URL parsing resolves `..` and proxies merge `//`. A JS caller passing something else gets whatever URL that makes.
- (agent) The default is applied in `makeHttpHandler`, `makeTransport` and `generateDocument`, which read the public options; `makeUrlPaths` and `toUrlPath` take a concrete `PathSeparator`.
- (agent) A router key holding the separator makes two paths share a URL (`get_user` and `get.user` with `'_'`), so the handler throws when it's created, and on the first call into a lazy subtree that loads one.
- (agent) The options live on the handler and the link, where v12 already puts what shapes the wire (`endpoint`, `batch`, the serializer since Q11.5, [`replaceable-transformers.md`](./replaceable-transformers.md)), not on `initTrpc` as in #7845's `initTRPC.create({ pathSeparator })`. They keep the `experimental_` prefix: it can change or go.
- (agent) Paths stay dotted strings, on the client too. Router keys can't hold `.` (`checkRouterKeys`), so a dotted path and a tuple are the same value, and `httpLink` builds the same URL from either. `Operation.path` is what links compare (`splitLink` conditions typed by `RouterPaths`), key on (`dedupeLink`), name spans with and send (`wsLink`, batches); tuples would move a `join('.')` into each and break custom links' `op.path === 'post.byId'`. TanStack Query's keys are tuples already (`[['post', 'byId'], …]`) and don't change.
- Why: one character in one place, the URL, which is all a firewall sees. Nothing changes unless it's set.
- Lost: `.` only (A; users behind such networks rewrite URLs in a proxy or use a socket link). Tuple paths on the client (C): joins in every link for no change in the URL. `/` and arbitrary strings with a runtime check (this PR's first draft): every adapter's route would change, and the check was runtime code in every handler and link for what types catch.
- Open: whether the client's type should be forced to match the handler's separator, as the serializer is (a mismatch is a `NOT_FOUND`); a strict mode that refuses the dotted URL; that a lazy subtree's bad key fails at request time, not at startup; the `experimental_` prefix on option keys ([`../open/experimental-prefix-on-types-and-methods.md`](../open/experimental-prefix-on-types-and-methods.md)).
- Lives in: `packages/trpc/src/internal/protocol.ts` (`PathSeparator`, `toUrlPath`), `packages/trpc/src/server/handler/path-separator.ts`, `packages/trpc/src/server/handler/http-handler.ts`, `packages/trpc/src/server/handler/app.ts`, `packages/trpc/src/server/handler/call.ts`, `packages/trpc/src/server/handler/fetch.ts`, `packages/trpc/src/client/links/http/link.ts`, `packages/trpc/src/client/links/http/transport.ts`, `packages/trpc/src/openapi/generate.ts`, `packages/trpc/src/server/handler/path-separator.test.ts`, `www/v12/docs/server/routers.md#urls-without-dots`, `www/v12/docs/client/links/http.md`, `www/v12/docs/openapi/document.md`.
