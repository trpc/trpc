# Lazy routers load as Effects (human asked)

- Human, 2026-10-18: refactor code that isn't Effect-like to Effect-native APIs. The outcome is theirs; the details below are the agent's.
- (agent) A lazy subtree's load is one `Effect.cached` Effect (`LazyDef.loadEffect`), made when `lazy()` is called: concurrent first calls share one load, and its result, or the loader's rejection as a defect, is kept. Before, it was a memoized `Promise` with a `.then` that set `loaded`. `load()` is `Effect.runPromise` of it, so a failed load still rejects with the loader's own error.
- (agent) `resolveProcedure` walks the router synchronously and loads each lazy subtree on the path with `Effect.flatMap` instead of a `.then` chain; when nothing needs loading it is an `Effect.succeed`, so `Effect.runSync` works on a loaded router. `loadRouter` is `Effect.runPromise` of `loadRouterEffect`, an unbounded `Effect.forEach` over the tree instead of `Promise.all` over `async` functions.
- (agent) Kept as a Promise, at the edge: `loadRouter`, public in `@trpc12/trpc/server`, which apps await before `experimental_generateOpenApi` or `experimental_toContract`. `LazyDef.load()` stays for code that reads a `LazyRouter`'s `~lazy`; nothing in the package calls it.
- (agent, 2026-10-20, [`effect-first-public-apis.md`](./effect-first-public-apis.md)) `resolveProcedure` in `@trpc12/trpc/extend` returns `Effect.Effect<AnyProcedure | undefined>`. It was `AnyProcedure | undefined | Promise<AnyProcedure | undefined>`, running the Effect form (`resolveProcedureEffect`, now gone) with `Effect.runPromise` when a subtree needed loading. `/extend` is for libraries, whose next step is `callProcedure`, already an Effect, and a value-or-Promise union made every caller branch on it. `getProcedure` stays the synchronous lookup of what has loaded. Lost: a Promise caller writes `Effect.runPromise(resolveProcedure(…))`.
- (agent) The Effect callers use the Effect forms instead of wrapping the Promises in `Effect.promise`/`tryPromise`: `resolveProcedure` in `server/handler/call.ts` and `server/handler/batch.ts` (one call, and a batch's paths with an unbounded `Effect.forEach`), `server/sockets/socket.ts`, `client/links/local.ts`, `interop/handler/handler.ts`, `interop/handler/socket.ts`, `cloudflare/hibernation.ts` and the OpenAPI handler's contract routes, and `LazyDef.loadEffect` for the OpenAPI handler's lazy loads. A failed load is a defect in each, which their error handling reports as an unexpected error, as it did the failure `tryPromise` made of it in `socket.ts` and the OpenAPI handler.
- (agent) A hibernated subscription's delivery resolves its procedure inside the Effect that sends the event, so a subtree that fails to load on a woken object ends the subscription with an error, as a rejected event does. Before, `deliver` rejected and the subscription stayed parked.
- Why: one memoization with Effect's semantics instead of a hand-rolled `??=` cache, and lazy loads that compose into the callers' Effects.
- Lost: a loader that throws synchronously (rather than rejecting) used to throw out of `resolveProcedure` and be retried on the next call; it is now a cached defect like a rejection. An Effect caller interrupted while it is the only one waiting on a load abandons that load, so the next call runs the loader again (`Effect.cached` doesn't cache interruption); the Promise APIs are never interrupted.
- Lives in: `packages/trpc/src/server/procedures/router.ts` (`lazyWith`, `resolveProcedure`, `loadRouter`, `loadRouterEffect`), and the callers above; tests in `packages/trpc/src/server/procedures/routers.test.ts` (a shared load, a failed load, the Effect forms) and `packages/trpc/src/cloudflare/hibernation.test.ts` ("a lazy subtree that fails to load after a wake ends its hibernated subscriptions with an error").
