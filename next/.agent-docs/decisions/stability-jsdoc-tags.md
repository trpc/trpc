# APIs are experimental, unstable or stable, named `experimental_*`, `unstable_*` or plain, with a stability tag; promoting renames with a deprecated alias (human)

- Human, 2026-10-16 (Q21.1, decision round): "B + keep stability tag, when promoting we should rename and do a deprecated alias".
- Human, 2026-10-16 (decision round, prefix): "A", switching the prefix from `unstable_` to `experimental_`, after writing `experimental_` in two earlier answers. The name and the `@stability experimental` tag now say the same thing.
- Human, 2026-10-19 (decision round, unstable stage): "B) experimental mean the feature might go away at any time, unstable means we want the general feature but how it works can change at any time.. that's how v11 rules worked and it should be documented the same". So there are three stages, as in v11: `experimental_` (might change or go away in any release), `unstable_` (we want it, but its name, options and behavior might change in a minor) and stable.
- Human, 2026-10-16 (decision round, which features start experimental): "B - we can probably have experimental_ on any api i haven't explicitly blessed". Experimental: the features v11 never had, `experimental_socketLink`, `experimental_messagePortLink`, `experimental_createAction`, `experimental_createCallable` (all of `@trpc12/trpc/actions`) and `experimental_createHibernatingWebSockets`, next to `experimental_durable`, `experimental_durableLink` and `experimental_generateOpenApiFromTypes`. Later in the round, all of `@trpc12/nest` ([`nest-integration.md`](./nest-integration.md)).
- Tentative (human): "we can probably have experimental_ on any api i haven't explicitly blessed". So a new public API starts experimental unless a `(human)` decision settles its shape. Existing exports outside the list above stay `stable` until the human names more. Challenge it when it gets in the way.
- Every export reachable from a published entry point carries `@since <version>` and `@stability experimental | unstable | stable | internal`, plus an `@example`; the `trpc/jsdoc` lint rule enforces it ([`acronym-casing.md`](./acronym-casing.md), Q21.4).
- An experimental export's name starts with `experimental_` (`experimental_durableLink`), and an unstable one's with `unstable_`. Promoting either adds the next name (`experimental_x` to `unstable_x` or `x`, `unstable_x` to `x`) and keeps the old name as an alias tagged `@deprecated Use <name>`, removed in the next major. The codemod rewrites the alias.
- (agent, tentative) Built, 2026-10-16. Before this, all 468 public exports were tagged `experimental`, because the package is alpha; prefixing them all would rename the whole API. So `@stability` now says how an export is planned to ship in 12.0.0, and prereleases promise nothing (`docs/README.md`). The core is `stable`.
  - Only values (functions, classes, consts) carry the prefix. Their option types are tagged `experimental` or `unstable` but keep their names (`DurableLinkOptions`, `MessagePortLinkOptions`, `CreateActionOptions`), as v11 did for `unstable_httpBatchStreamLink`. Types shared with a stable value (`SocketLink`, `ConnectionLinkOptions`, used by `wsLink`) stay `stable`.
  - `trpc/jsdoc` enforces both directions for both stages. An `experimental` or `unstable` value must be named with its own stage's prefix, and a prefixed value must be at that stage or `@deprecated`: a stable `unstable_x` or an unstable `experimental_x` is reported as promoted, to be exported under its next name with the old one as an alias. A `@deprecated` export must say `Use <name>`.
  - The codemod reads `PROMOTED` (`packages/upgrade/src/promoted.ts`, empty for now) and rewrites imports of promoted `experimental_*` and `unstable_*` names from `@trpc12/trpc` and `@trpc12/*`. (agent, 2026-10-19) It follows chains to their end, so `PROMOTED` keeps `experimental_x: 'unstable_x'` when `unstable_x: 'x'` is added, and old code goes straight to `x`.
  - Renamed without deprecated aliases: no release has shipped the old names.
- Human, 2026-10-16 (decision round, the Effect Atom React package): "In first version but with the name in c where the whole package is prefixed with experimental" ([`react-use-package.md`](./react-use-package.md)). A whole package can be experimental: `@trpc12/experimental-react` and `@trpc12/experimental-react-atom`.
  - (agent) In an `@trpc12/experimental-*` package, every export is `@stability experimental` and none carries an `experimental_` or `unstable_` prefix, since the package name already says it. `trpc/jsdoc` enforces both.
  - (agent, tentative) Promoting such a package publishes it without the prefix (`@trpc12/react-atom`), and the last `experimental-` release re-exports it, marked deprecated on npm. (agent, 2026-10-19) Its exports that aren't stable yet get `unstable_` in the new package. The codemod reads `PROMOTED_PACKAGES` (`packages/upgrade/src/promoted.ts`, empty for now): the old package name, its new one, and the names that changed (`atom: 'unstable_atom'`), then `PROMOTED`; it rewrites subpaths too.
  - (agent, 2026-10-19) No `@trpc12/unstable-*` packages, and `trpc/jsdoc` reports one. Unstable means the feature stays, so its package can have its final name now, with its unstable exports named `unstable_*`; promoting them is then non-breaking through aliases, where renaming a package isn't.
- (agent, 2026-10-19) Docs pages: an unstable feature's page is badged, not hidden. `stability: unstable` in its frontmatter shows an "Unstable" badge ("How it works might change in a minor release", linking Stability), and the page stays in the sidebar, search, `llms.txt` and the sitemap, because the human wants the feature used. Experimental features' pages stay hidden in experiments ([`docs-experiments.md`](./docs-experiments.md)); a page with both shows the Unstable badge. `docs/packages.md` (Stability) has v11's FAQ definitions for both stages, under `#unstable` and `#experimental` as in v11.
- Open: which `experimental_` exports become `unstable_` (a decision round, 2026-10-19). No export is renamed until the human confirms the list.
- (agent) No separate experimental entry points. `@trpc12/trpc/internal` and `@trpc12/trpc/internal/testing` are the no-guarantee entry points ([`entry-points.md`](./entry-points.md), [`testing-helpers-internal.md`](./testing-helpers-internal.md)).
- Why: stability is visible at the import site; the deprecated alias keeps promotion non-breaking, which v11's `unstable_httpBatchStreamLink` rename wasn't. Two prefixes tell a reader what v11's did: whether to build on a feature (`unstable_`) or only try it (`experimental_`).
- Lost: names that never change; promotion leaves an alias behind until the next major, and a feature that goes experimental to unstable to stable leaves two.
- Lives in: `tooling/oxlint-plugin/jsdoc.ts` (and its `fixtures/`), `tooling/oxlint-plugin/public-exports.ts`, `vite.config.ts` (`trpc/jsdoc` override), `packages/upgrade/src/promoted.ts`, `packages/upgrade/src/transform.ts`, `docs/packages.md` (Stability), `www/build/content.ts` (`stability`), `www/src/components/doc-page.tsx`.
