# Experimental APIs have an `experimental_` prefix and a stability tag; promoting renames with a deprecated alias (human)

- Human, 2026-10-16 (Q21.1, decision round): "B + keep stability tag, when promoting we should rename and do a deprecated alias".
- Human, 2026-10-16 (decision round, prefix): "A", switching the prefix from `unstable_` to `experimental_`, after writing `experimental_` in two earlier answers. The name and the `@stability experimental` tag now say the same thing.
- Human, 2026-10-16 (decision round, which features start experimental): "B - we can probably have experimental_ on any api i haven't explicitly blessed". Experimental: the features v11 never had, `experimental_socketLink`, `experimental_messagePortLink`, `experimental_createAction`, `experimental_createCallable` (all of `@trpc12/trpc/actions`) and `experimental_createHibernatingWebSockets`, next to `experimental_durable`, `experimental_durableLink` and `experimental_generateOpenApiFromTypes`.
- Tentative (human): "we can probably have experimental_ on any api i haven't explicitly blessed". So a new public API starts experimental unless a `(human)` decision settles its shape. Existing exports outside the list above stay `stable` until the human names more. Challenge it when it gets in the way.
- Every export reachable from a published entry point carries `@since <version>` and `@stability experimental | stable | internal`, plus an `@example`; the `trpc/jsdoc` lint rule enforces it ([`acronym-casing.md`](./acronym-casing.md), Q21.4).
- An experimental export's name starts with `experimental_` (`experimental_durableLink`). Promoting it to stable adds the unprefixed name and keeps `experimental_*` as an alias tagged `@deprecated Use <name>`, removed in the next major. The codemod rewrites the alias.
- (agent, tentative) Built, 2026-10-16. Before this, all 468 public exports were tagged `experimental`, because the package is alpha; prefixing them all would rename the whole API. So `@stability` now says how an export is planned to ship in 12.0.0, and prereleases promise nothing (`docs/README.md`). The core is `stable`.
  - Only values (functions, classes, consts) carry the prefix. Their option types are tagged `experimental` but keep their names (`DurableLinkOptions`, `MessagePortLinkOptions`, `CreateActionOptions`), as v11 did for `unstable_httpBatchStreamLink`. Types shared with a stable value (`SocketLink`, `ConnectionLinkOptions`, used by `wsLink`) stay `stable`.
  - `trpc/jsdoc` enforces both directions. An `experimental` value must be named `experimental_*`, and an `experimental_*` value must be `experimental` or `@deprecated`. A `@deprecated` export must say `Use <name>`.
  - The codemod reads `PROMOTED` (`packages/upgrade/src/promoted.ts`, empty for now) and rewrites imports of promoted `experimental_*` names from `@trpc12/trpc` and `@trpc12/*`.
  - Renamed without deprecated aliases: no release has shipped the old names.
- (agent) No separate experimental entry points. `@trpc12/trpc/internal` and `@trpc12/trpc/internal/testing` are the no-guarantee entry points ([`entry-points.md`](./entry-points.md), [`testing-helpers-internal.md`](./testing-helpers-internal.md)).
- Why: stability is visible at the import site; the deprecated alias keeps promotion non-breaking, which v11's `unstable_httpBatchStreamLink` rename wasn't.
- Lost: names that never change; promotion leaves an alias behind until the next major.
- Lives in: `tooling/oxlint-plugin/jsdoc.ts`, `tooling/oxlint-plugin/public-exports.ts`, `vite.config.ts` (`trpc/jsdoc` override), `packages/upgrade/src/promoted.ts`.
