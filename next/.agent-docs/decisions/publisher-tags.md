# No publisher tags: a channel per audience (human)

- (agent) Built for the "tag targeting is later" in [`hibernation-state-and-subscriptions.md`](./hibernation-state-and-subscriptions.md), as an `experimental_Publisher` feature rather than a Cloudflare one: `publish(channel, data, { tags })` and `subscribe(channel, { lastEventId, tags })`. A subscriber gets an event when they share a tag; untagged events go to everyone, and untagged subscribers get only those.
- (agent) Tags travel inside the event (`{ '~trpc/tags': [...], data }`), wrapped by the `Posts.publish` accessor and unwrapped by `Posts.subscribe`. Backends store and replay it like any data, so the memory layer, the Redis and Postgres recipes and `experimental_hibernatingPublisher` filter by tag with no change to their shape, and replays after `lastEventId` respect tags too.
- (agent) The hibernating adapter keeps a parked subscription's tags in the socket attachment (`t`), so `publish` only sends to matching sockets after a wake.
- (agent) Tags are set on the server. The docs say to take them from `ctx` (or a [signed token](./hibernation-connection-tokens.md)), not from input, because a client choosing its own tags could read anyone's events.
- Compared: oRPC's `publishEvent(payload, { tags, targets, exclude })` on Durable Iterator objects. `targets` and `exclude` take socket objects, which only exist inside one object; tags work for every backend. Excluding the sender is left to the app (tag events with the audience instead).
- Why: the tag filter is a stream filter over the existing service, so Effect's `PubSub`, Redis pub/sub and the hibernating fan-out share one implementation.
- Lost: per-event filtering on the backend (Redis still sends tagged events to every process, which drops the ones its subscribers can't see); code that reads the service shape directly sees the envelope.
- Human, 2026-10-16 (decision round, publisher tags after oRPC v2): "B". Tags are dropped; an audience is a channel (`inbox:${userId}`, `chat:${roomId}`), typed by a template literal key in the publisher's events. The bullets above describe what was built and removed.
  - Options were: A) keep tags; B) drop them and use one channel per audience. oRPC v2 removed Durable Iterator, including `publishEvent`'s `tags`, `targets` and `exclude`; its `DurablePublisher` has resume but no tags (`.repos/orpc/apps/content/docs/migrations/from-v1.mdx`, `.repos/orpc/apps/content/docs/helpers/publisher.mdx`).
  - (agent) Removed: `PublishOptions`, `SubscribeOptions.tags`, the `'~trpc/tags'` envelope and `isFor`, and the parked subscription's `t` field in hibernated attachments. The accessors pass straight through to the service.
  - Why: Effect's `PubSub`-per-topic model, the backend filters (Redis subscribes per channel instead of every process dropping others' events), and no envelope in the service's data.
  - Lost: one publish reaching several audiences (publish to each channel); a subscriber listening to several audiences needs one subscription per channel, or a merged stream.
- Lives in: `packages/trpc/src/server/subscriptions/publisher.ts` (`PublisherEvents`, `SubscribeOptions`), `src/cloudflare/hibernation.ts` (`Parked`), `packages/trpc/src/server/subscriptions/publisher.test.ts`, `packages/trpc/src/cloudflare/hibernation.test.ts`, `docs/subscriptions/publisher.md` (A channel per audience), `docs/adapters/cloudflare.md`.
