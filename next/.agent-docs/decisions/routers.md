# Routers are plain objects; `mergeRouters` rejects duplicate keys (human)

- Human, 2026-10-09 (Q8.2): "helper". Keep a variadic `mergeRouters(a, b, …)` that errors on a shared key, at the type level and at runtime, instead of relying on object spread.
- Why: the spike ([`../notes/contracts-and-routers-typing.md`](https://github.com/trpc/trpc/blob/d5c34c43000547776ca234ac47edafd48370e6fd/next/.agent-docs/notes/contracts-and-routers-typing.md)) showed `{ ...a, ...b }` silently keeps `b`'s value, and the duplicate is gone at runtime too, so neither types nor the handler can catch it. Spread still works; it just isn't checked.
- Lost: spread only (proposal 08's recommendation).
- Human, 2026-10-15 (Q10.2): "A". The path separator is `.`, in `path` and in URLs (`/trpc/post.byId`). The URL matches the resolver's `path`, and RPC URLs stay distinct from OpenAPI's slash routes (`/api/post/byId`).
- Human, 2026-10-15 (Q8.3): "Yes an openapi only". `t.router({ prefix, tags }, { … })` exists only to group OpenAPI routes. It takes no middleware ([`middleware.md`](./middleware.md): router-level middleware is "never").
- Human, 2026-10-15 (Q8.4): "D". `lazy(() => import('./admin'), { prefix? })` loads a subtree on first use. For OpenAPI, a lazy subtree is found by its `prefix` (the default), by a contract passed to the handler, or else by loading every lazy subtree at startup.
- (agent, Q8.1) Routers are plain objects. Keys are path segments. The root, and a router a module exports, is made with `t.router(routes)`, which returns `routes` and records `t`'s root ctx on its type; inline nesting stays a plain object ([`sanitized-procedure-types.md`](./sanitized-procedure-types.md)).
- (agent) A group's prefix goes before every route below it: before an explicit `.route({ path })`, and before the path derived from the keys below the group (`admin: t.router({ prefix: '/staff' }, { users })` is `/api/staff/users`). Tags-only groups don't change paths. The group rides on a non-enumerable key, so `Object.keys` and RPC paths don't see it.
- (agent) `lazy(load, { prefix })` scopes its subtree like a group with that prefix, which is what makes the prefix lookup sound. `load` may return the router or a module with a `default` export. The RPC handlers and `localLink` load on the first call (`resolveProcedure`); `experimental_generateOpenApi` and `experimental_toContract` throw on an unloaded subtree and ask for `await loadRouter(router)`. The contract the OpenAPI handler takes is the `experimental_toContract()` JSON, generated at build time.
- Human, 2026-10-16 (decision round, routers after oRPC v2): "B". OpenAPI groups move under the `experimental_openapi()` extension's `route` meta, at router level, and core's `lazy()` stays, with the extension supplying the prefix lookup. This replaces the Q8.3 and Q8.4 spellings above (`t.router({ prefix, tags })`, `lazy(load, { prefix })`); what they do is unchanged.
  - Options were: A) keep them in core; B) this. oRPC v2 moved `.prefix()`, `.tag()` and `.route()` into one `experimental_openapi()` meta ([`apps/content/docs/migrations/from-v1.mdx`](https://github.com/middleapi/orpc/blob/v2.0.0-beta.44/apps/content/docs/migrations/from-v1.mdx), "Routing Moved to OpenAPI Metadata").
  - (agent) Built: `t.router({ meta: { route: { prefix, tags } } }, routes)` and `t.lazy(load, { meta: { route: { prefix } } })`. Core stores a router's `meta` on a non-enumerable key (`routerMetaOf`, exported from `@trpc12/trpc/extend` for other extensions); `flattenRoutes` reads its `route` key, as it reads a procedure's.
  - (agent, tentative) Typing: a router's `meta` is `RouterMeta<TMeta>`, the root's meta keys whose value type names a router-level form with a type-only `'~router'` key. `Route['~router']` is `RouteGroup` (`{ prefix?, tags? }`), so a router's `route` takes no `method` or `path`, and keys like `auth` (procedure-only, since routers have no middleware) are type errors. Without `experimental_openapi()` a router takes no `meta`.
  - (agent, tentative) The plain `lazy(load)` import takes no options, because it can't see the root's meta type; meta goes through `t.lazy`. A lazy subtree's `route` may now carry `tags` too.
  - Lost: the short `t.router({ prefix })` spelling; the standalone `lazy(load, { prefix })` without `t`.
- `mergeRouters` merges router-level meta and throws on a key set to different values: [`merge-routers-meta.md`](./merge-routers-meta.md).
- (agent) A `then` key or a key with a `.` is an error when the router is served: `createFetchHandler` and `createRouterClient` walk the eager tree once (`checkRouterKeys`), and a lazy subtree is checked when it loads. Before, the handler served a `then` procedure that every client read as `undefined` (the proxy hides `then` so clients can be awaited), and a dotted key was unreachable. v11 rejected `then`, `call` and `apply` in `router()`; `call` and `apply` work here, since the proxy doesn't treat them specially. The OpenAPI and interop handlers rely on the lazy-load check only.
- Lives in: `packages/trpc/src/server/procedures/router.ts` (`router`, `lazyWith`, `checkRouterKeys`, `RouterMeta`, `routerMetaOf`), `src/server/procedures/init.ts` (`t.router`, `t.lazy`), `src/openapi/rest/routes.ts` (`RouteGroup`, `routeGroupOf`), `src/internal/describe.ts` (`flattenRoutes`, `scopedRoute`), `src/openapi/handler.ts`; tests in `packages/trpc/src/server/procedures/routers.test.ts`.
