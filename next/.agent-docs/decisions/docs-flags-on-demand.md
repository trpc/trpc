# Flagged pages are rendered on request; the build prerenders each page once (human asked)

- Human, 2026-10-19: "make sure SSR works with flags... but every combination obvs don't need pre-rendering on build".
- (agent) "Flags" are what the URL turns on: `?flags=<id,...>`, the experiments ([`docs-experiments.md`](./docs-experiments.md)), and `?version=v12` on the home page ([`docs-v11-by-default.md`](./docs-v11-by-default.md)). The site keeps neither in cookies. The home page's host default and remembered version stay in the browser ([`docs-home-version-by-host.md`](./docs-home-version-by-host.md), [`docs-remembered-version.md`](./docs-remembered-version.md)).
- (agent) What was broken: Vercel serves the prerendered file for a path whatever its query, so `/v12/docs/x?flags=publisher` got the same bytes as `/v12/docs/x`, and the server never rendered a flag. `useFlagsOn` returned no experiments until hydration, so the sidebar, search, pagination and the menu's count changed right after the first paint. `/?version=v12` arrived showing v11 until the head script ran.
- (agent) The build still prerenders each page once, without a query (371 pages, the same as before). `build/vercel-output.ts` also writes a Node.js function, `_ssr`, which is the server build (`dist/server`, bundled with its dependencies by `bundledServer()` so it needs no `node_modules`) behind a small `(req, res)` handler. Routes before the filesystem rewrite two kinds of request to it: a page path whose `?flags=` names only known experiments (any order, commas plain or encoded), and `/` with `?version=v12`. Everything else, including `?flags=` with an unknown name, gets the prerendered file. The function sends the pages' `Cache-Control` (`s-maxage=86400`), so Vercel's CDN caches each URL it renders until the next deploy.
- (agent) The app reads flags the same way on the server and in the browser: `useFlagsOn` reads `?flags=` directly, and the root document renders `<html data-home-version>` from `?version=`. A flagged URL's HTML has the experiments' pages in its sidebar and the menu's count, and `/?version=v12` arrives with the v12 panels shown, before any script runs. A static page is only served for a URL without flags, which hydrates with none, so the two always agree.
- Why: every combination of ten experiments is 1,024 variants of each of 371 pages, too many to prerender, and almost every visitor has no flags. Rendering on request costs a function call per uncached URL, about 15 ms locally, and keeps the static site, its routes and its tests as they were.
- Lost: considered and set aside: Vercel ISR prerender functions with `allowQuery` (a cache key limited to the flag params, but it can't be tested locally and the cache is keyed in a way the routes' rewrite has to match); Nitro's Vercel preset (a new dependency and build output in place of `vercel-output.ts`); cookies for flags (a link wouldn't share them). Also lost: `vp preview` doesn't show the split, because it renders every request on the server; the static/on-demand split only exists in `.vercel/output`.
- Open: an experiment page opened without its flag still turns the flag on after hydration (`useEnableOnVisit`), so its sidebar entry appears then. On v12.trpc.io, `/` without `?version=` is still the prerendered v11 page that the head script switches to v12. Rendering either on the server would need the host or a redirect, which those decisions ruled out.
