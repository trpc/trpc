# `experimental_rateLimit()` is Effect middleware over Effect's `RateLimiter`, with `experimental_` Upstash and Durable Object stores (human asked)

- oRPC ships `@orpc/experimental-ratelimit`: its own `Ratelimiter` interface with memory, Redis, Upstash and Cloudflare adapters, a middleware and a handler plugin for headers. Effect 4 already has `RateLimiter` in `effect/persistence` (fixed window and token bucket, fail or delay, memory and Redis stores). Effect-native first ([`effect-native-by-default.md`](./effect-native-by-default.md)) means using it, not a second interface.
- (agent) `experimental_rateLimit<{ ctx }>({ key, limit, window, algorithm?, onExceeded?, tokens? })` from `@trpc12/trpc/middleware` is an Effect middleware that requires `RateLimiter.RateLimiter`, so a handler without it in `layer` is a type error. Its key function sees `ctx`, `input`, `meta` and `path`, typed by the requirement like `middleware<{ ctx }>()`.
- (agent) Past the limit it fails with the exported `experimental_RateLimited` (`TrpcError.Tagged('TOO_MANY_REQUESTS', { status: 429, data: { limit, retryAfter } })`, `retryAfter` in milliseconds), so the error is typed on the client. Store errors are defects (masked 500): they are not the caller's fault.
- (agent) Headers: `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` (seconds) on every call, `Retry-After` on 429, set through the call's `response` handle, so no handler plugin. Inside a batch they merge like other headers.
- (agent) `retryLink`'s `delay(attempt, error)` gets the error, so a client can wait `retryAfter`; the default retry still skips typed errors.
- Human, 2026-10-19 (decision round, which partial oRPC-parity rows to defer past 12.0): "C) but they should all be experimental_ and hidden by default in the docs". No row is deferred: this one gets its Upstash and Cloudflare stores before 12.0, exported as `experimental_` and documented only on hidden pages.
- (agent) Upstash: `experimental_upstashRedis({ url, token, fetch? })` is Effect's `Redis` service over Upstash's REST API (a JSON command array per `fetch`, `Authorization: Bearer`), so Effect's own Redis store and its Lua scripts run unchanged: `experimental_upstashRateLimiterStore()` is `RateLimiter.layerStoreRedis()` on it. Scripts load once and run by `EVALSHA`, reloaded on `NOSCRIPT`. The same layer serves `experimental_redisLocker()`. `subscribe` fails: Upstash's REST API has no pub/sub.
- (agent) Cloudflare: a Durable Object store, not the Workers Rate Limiting binding. `experimental_durableRateLimiterStore(env.RATE_LIMITS)` sends each key to its own object running `experimental_durableRateLimitObject(this.ctx)`, which counts with the object's clock, keeps the counters in its storage (so they outlive an eviction), and deletes them from an alarm once they expire. Its fixed window and token bucket are Effect's memory store's, checked against it call for call in the tests. The binding can't be a `RateLimiterStore`: its limit and period (10 or 60 seconds) are fixed in `wrangler.jsonc` rather than passed per call, it counts per Cloudflare location and settles eventually, and it answers only `{ success }`, so there's no count for `RateLimit-Remaining` or `retryAfter`, and no token bucket. The Rate limiting page says so, and how to call it from your own middleware.
- (agent) Both are documented on Rate limiting (the `middleware` experiment) and the Cloudflare page (the `cloudflare` experiment), so they're hidden by default ([`docs-experiments.md`](./docs-experiments.md)). (agent, 2026-10-19) The middleware and its error were `rateLimit()` and `RateLimited`, tagged stable; the human asked that everything documented only on hidden pages be prefixed ([`stability-jsdoc-tags.md`](./stability-jsdoc-tags.md)), so they're `experimental_rateLimit()` and `experimental_RateLimited` now, and `trpc/jsdoc` fails on an unprefixed one.
- (agent) `examples/cloudflare` limits `send` to three messages a minute per sender in a room on the Durable Object store, which `pnpm example` runs on workerd. saas-api doesn't use a store: it uses stable API only, and Upstash would need a real database.
- Why: Redis-backed distributed limits, token buckets and delay mode come from Effect; @trpc12/trpc adds only the tRPC error and headers.
- Lost: the Workers Rate Limiting binding as a store, and adaptive limiting in the Durable Object store (`adaptiveConsume`, which Effect's HTTP client uses, always reports no state); oRPC's per-request dedupe of the same limiter and key (leading duplicates in `.concat()` are dropped, [`middleware-dedupe.md`](./middleware-dedupe.md)).
- Open: the Upstash store is tested against an Upstash-shaped REST endpoint in front of Redis (`REDIS_URL`, as in CI), not Upstash itself, which needs a database and its token.
- (agent, 2026-10-19) The Durable Object side is Effects run once at its `fetch` and `alarm` (`Effect.runPromise`): the counters load through `Effect.cached` instead of a memoized `Promise`, time comes from `Clock`, and `save` and the count are `Effect.fnUntraced` ([`effect-internal-patterns.md`](./effect-internal-patterns.md)). Counting stays a synchronous step on the loaded object, so two calls still can't interleave between reading a counter and writing it.
- (agent, 2026-10-19) `experimental_upstashRedis` keeps `fetch` inside `Effect.tryPromise` (whose signal aborts on interruption) rather than Effect's `HttpClient`: a Worker with a fetch handler and the Upstash store grows from 81.9 to 85.1 kB gzipped (253.2 to 265.4 kB minified) with `HttpClient` and `FetchHttpClient`, for one POST of a JSON array per command and the same error mapping. `HttpClient` would add a span per command when a tracer is installed; revisit if that's wanted.
- (agent, 2026-10-20) Decided again under [`effect-first-public-apis.md`](./effect-first-public-apis.md), which would allow the 3.2 kB: Upstash stays on `fetch`.
  - `HttpClient` isn't cleaner here. Upstash's error mapping (a 200 with `{ error }`, non-JSON gateway answers) stays as it is, and the public `fetch` option would turn into a `FetchHttpClient.Fetch` layer on top.
  - Its span per command doubles the subrequest spans Workers Traces already records, and its trace propagation sends `traceparent` headers to a third party.
  - Taking the client from the caller (`Layer<Redis, never, HttpClient>`) would make every user provide `FetchHttpClient.layer` for nothing they use.
  - The Durable Object side keeps its shape: the object's `fetch` and `alarm` are what the class methods return to Workers, so they stay Promises, and the store is already a `Layer`.
  - `experimental_rateLimit`'s options are per-procedure.

  Lost: Effect's HTTP client spans and retry combinators on Upstash calls. Wrap the `fetch` option to retry.
