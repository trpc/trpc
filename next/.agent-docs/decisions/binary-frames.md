# Streamed HTTP outputs can be binary frames, chosen by `accept` (agent)

- (agent) Builds the "binary framing can come later, chosen by `accept`" in [`file-bytes-encoding.md`](./file-bytes-encoding.md). A client that sends `accept: application/vnd.trpc.frames` gets streamed outputs and batches in that format instead of JSONL; other clients get JSONL as before, and streamed responses say `vary: accept`.
- (agent) The format is JSONL's lines as records: a kind byte, a big-endian `u32` length, the payload. A JSON record is one line; a bytes record is an attachment of the next JSON record, which points at it as `{ "~trpc/bytes": n }`. So batches, deferred values and errors are the same lines, and only file bytes change. Markers are only read in records that have attachments, and those hold just a byte chunk, so user data can't be mistaken for one.
- (agent) File bytes are a `Uint8Array` subclass (`JsonBytes`) whose `toJSON` returns base64. JSONL, SSE and text WebSocket messages are byte-for-byte what they were; frames take the bytes out; `postMessage` clones them as a plain `Uint8Array`, so `messagePortLink` now sends file bytes unencoded too, and `localLink` never copies them. The decoder takes either form.
- (agent) Opt-in: `httpLink({ binary: true })`, default off. JSONL stays readable in the browser's network tab and with `curl`, and only nested files gain from frames (a root file of an unbatched call is already the raw body).
- (agent) The codec is a `Stream.mapAccum` over the body, which keeps received chunks in a list so a large file is copied once. A truncated or unknown record dies the stream, as a malformed JSONL line does.
- Compared: oRPC answers an output holding files with a `multipart/form-data` body (`rpc-serializer.ts`), but not inside event iterators. A multipart body can't carry deferred values or batch lines without scanning every chunk for the boundary; length-prefixed records keep one decoder for single calls, batches and streams.
- Lost: frames aren't readable as text; SSE subscriptions stay base64 (`EventSource` is text-only).
- Open: binary WebSocket messages. A socket has no `accept`, so the client would have to negotiate per connection (a subprotocol or a URL param) on every upgrade path (Node, Bun, Deno, the Cloudflare hibernation attachment). Not built until someone needs large files over WebSockets.
