# Links declare the errors they make; a call's union has only its links' (human)

- Human, 2026-10-19 (Q24.3, how `matchError()` keys work): "D) i think we already covered this? the types should rule it, and if it's inferred we should still have it in the match and if its declared that's the only types that the producere _can_ return without type errors..
  additionally, links should be able to infer their own errors they can return, i'm sure there's some on the http link that that can return etc specific to that etc
  there's always a "catch all" unexpected error but we should do our best outside of that to be exhaustive"
- (agent) Three built-in codes are made only by links, `LinkErrorCode`: `NETWORK_ERROR` (no response, or the connection dropped), `BAD_RESPONSE` (a response that isn't tRPC's or doesn't decode) and `STREAM_INTERRUPTED` (a stream cut off). A link declares the ones it makes with `LinkDecl.builtinErrors`; a call's error union has those its chain declares, and every other built-in code (the catch-all: crashes, a missing procedure, proxy statuses, aborts, `CLIENT_ERROR`), which any call can get.
- (agent) What each link declares, from an audit of where each fails calls:
  - `httpLink`, `wsLink`, `experimental_messagePortLink`, `experimental_socketLink`: all three.
  - `experimental_openApiLink`: `NETWORK_ERROR`, `BAD_RESPONSE`.
  - `experimental_validationLink`: `BAD_RESPONSE` (a result that fails its schema).
  - `splitLink`, `switchLink`: their chains' (the union of the branches).
  - `localLink`, `retryLink`, `dedupeLink`, `loggerLink`, `experimental_durableLink`, `fromV11Link`: none. `createRouterClient` has none.
- (agent) The other errors links make stay in the catch-all, since a server or proxy can send the same codes: `CLIENT_CLOSED_REQUEST` (the call's `signal`, or `close()` on a socket link), `UNSUPPORTED_PROTOCOL` (another serializer or protocol version), `METHOD_NOT_SUPPORTED` (`httpLink` with subscriptions off), `NOT_FOUND`/`METHOD_NOT_SUPPORTED` (`localLink`), a proxy page's status (`httpLink`, `experimental_openApiLink`: `502` is `BAD_GATEWAY`), `BAD_REQUEST` (an input the serializer can't write), `CLIENT_ERROR` (`switchLink` without the branch, a link that threw).
- (agent) A client whose links aren't typed (`TrpcClient<AppRouter>`, `ClientError<E>`, a `TrpcLink<any>` in the chain) has all three, so it accepts a client with any links. Server actions and callables have none: their results come from the server.
- (agent, superseded by [exhaustive-match-error](./exhaustive-match-error.md)) `matchError()` takes an optional key per link code in the union, which takes that code from its category (`NETWORK_ERROR` beside `unavailable`); a category left with no codes is then a type error, and so is a key for a link code the links don't declare. The four categories and `builtin` stay the catch-all for now. A defined error with a link code's name shares its key with the built-in one. Inside an arrow handler, the category's `e` may still list a code a sibling key takes (TypeScript types the handlers before it knows every key); it never receives it.
- (agent) `httpLink` answers a body that isn't JSON or doesn't decode with `BAD_RESPONSE` ("Invalid response body"), as [closed-client-errors](./closed-client-errors.md) says, instead of `NETWORK_ERROR`.
- (agent) An empty body with `200` is `BAD_RESPONSE` ("Empty response body") too, where it used to resolve `undefined` whatever the output's type: a tRPC server writes `{}` for `undefined` with either serializer, so the empty body came from something else. `204`, `205` and `304`, which can't have a body, still resolve `undefined`.
- Why: the error type lists what can happen on this client: an in-process client has no network failure to handle, and a handler for one is a type error.
- Lost: a key for a link code the links don't declare no longer compiles. A custom link that makes a link code without declaring it leaves it out of the union (as with `errors`); `matchError()` sends it to its category. TanStack Query's options and helpers take the error type both ways (`retry`, `throwOnError` take it), so helpers from a `localLink` client no longer pass where the app's `httpLink` helpers are expected; `examples/react-spa/cache.test.ts` now uses `httpLink` with a `fetch` that calls the API's handler in process.
- Measured (2026-10-19): the standard client bundles grow 9-10 B gzip (39 184 to 39 193 B and 43 330 to 43 340 B), all from the `BAD_RESPONSE` fix; `matchError()` grows 25 B where it's used. Type checking 200 procedures with `safe()` and `matchError()` each: 576 k instantiations before, 582 k after (+1%), 603 k with a `NETWORK_ERROR` key on each (+5%); 2% fewer types; check time within noise (0.73-0.80 s).
- Since [exhaustive-match-error](./exhaustive-match-error.md): the four categories and `builtin` are replaced by one required `unexpected`, and every link code in the union is a required key. Batched and streamed lines that don't parse still fail with `NETWORK_ERROR`, as tested; a client-side `TIMEOUT` (Q24.6 B) would need a link code a server also sends.
