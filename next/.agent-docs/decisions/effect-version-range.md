# The workspace stays on `effect` 4.0.2 while `effect-latest` tests the newest 4.x, and code compiles against both (agent)

- (agent) 2026-10-31, after effect 4.0.6 to 4.1.1 broke the `effect-latest` job: the pin stays at 4.0.2. With `effect-latest`, CI checks both ends of the `^4.0.0` peer range ([`effect-dependency.md`](./effect-dependency.md)); moving the pin would leave nothing testing the versions below it.
- (agent) Code compiles against both. Where an Effect constructor gained an option, the options are a variable typed as the old options plus the new ones (`Parameters<typeof Redis.make>[0] & { readonly connect: … }`): a literal either misses a field the new version requires or has a property the old one rejects, and `trpc/typed-objects` wants the type. The type's comment names the version that added the option, so it can go back to a literal once the pin passes that version.
- (agent) What changed, and where it's handled:
  - 4.0.6: `Stream.toReadableStream` only pulls as the body is read, so a stream body nobody reads holds its fiber and `dispose()` waited for it. The OpenAPI and MCP handlers send JSON as text (`textWebResponse`, `fromWebResponse` in `server/handler/responses.ts`), as the fetch handler does.
  - 4.0.6: a hydrated atom runs on mount unless it's `skipInitialRun` (`experimental-react-atom`). Schema codegen prints `Schema.Int`, which `openapi/to-contract.ts` prints on every version. `Socket.fromWebSocket` leaves a no-op `error` listener when it lets go.
  - 4.0.7: `Redis.make` needs `connect` (`middleware/upstash.ts`), and `HttpMiddleware.xForwardedHeaders` takes `{ trustedProxies }`.
  - 4.1.0: `KeyValueStore.makeStringOnly` needs `keys` (`examples/cloudflare`), `NodeHttpServerRequest.toIncomingMessage` can return an `Http2ServerRequest` (`experimental-nest`), and `@effect/platform-node` imports `ws`'s `WebSocket` by name (`framework-matrix`'s `vite.config.ts`).
- (agent) `effect-latest` updates only the workspace's direct dependencies (`pnpm update -r --depth 0`): `vendor-src` pins `effect` and `@effect/platform-node` 4.0.1, and a full update moved its `@effect/platform-node-shared` to a version that doesn't run on that `effect`.
- Lost: the gates that need services (the Redis and Postgres tests in `check`) and `bun`, `node-lts` and the docs build only run on 4.0.2; `effect-latest` runs `typecheck` and `test` without Redis or Postgres.
- Open: moving the pin to 4.1 would run every gate on what a new install gets, but it should raise the peer floor to `^4.1.0` with it, which changes a human decision, and needs `pnpm vendor:sync effect`. Giving `effect-latest` a Redis service would run the Redis tests on the newest 4.x.
- Lives in: `.github/workflows/next.yml` (`effect-latest`), `packages/trpc/src/middleware/upstash.ts`, `packages/trpc/src/server/handler/responses.ts`, `packages/experimental-react-atom/src/index.ts`, `packages/trpc/src/openapi/to-contract.ts`, `examples/cloudflare/src/storage.ts`.
