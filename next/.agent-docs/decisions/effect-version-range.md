# Packages peer `effect` `^4.1.0`, the workspace pins the newest 4.1.x, and `effect-latest` tests the newest 4.x (human)

- Human, 2026-10-31, asked whether moving the pin to 4.1 should raise the peer floor to `^4.1.0`: "raise it". Every package that peers `effect` peers `^4.1.0`, as `experimental-nest` peers `@effect/platform-node`, and the `upgrade` CLI depends on `^4.1.0`. This raises the `^4.0.0` of [`effect-dependency.md`](./effect-dependency.md).
- (agent) The workspace pins `effect` and every `@effect/*` at 4.1.1, the newest 4.1.x, which brings 4.1.1's fixes: `RateLimiter`'s fixed window honors `limit: 0`, the Redis store rejects an over-limit first request instead of charging it, the memory store drops expired keys, and `Sse.encoder` strips CR and LF from `id` and `event`, so they can't add fields or events. `.repos/effect` is at `effect@4.1.1` (`pnpm vendor:sync effect`).
- (agent) Earlier the same day the pin stayed at 4.0.2, so that CI covered both ends of `^4.0.0` while code compiled against both. With the floor at 4.1 that's gone: the options 4.0.7 and 4.1 added are literals again (`Redis.make`'s `connect`, `KeyValueStore.makeStringOnly`'s `keys` and `clearPrefix`, `Atom.serializable`'s `skipInitialRun`), and `openapi/to-contract.ts` no longer rewrites `Schema.Number.check(Schema.isInt())` to `Schema.Int`, which Effect prints itself.
- (agent) What changed from 4.0.2 to 4.1, and where it's handled:
  - `Stream.toReadableStream` only pulls as the body is read, so a stream body nobody reads holds its fiber, and `dispose()` waited for it. The OpenAPI and MCP handlers send JSON as text (`textWebResponse`, `fromWebResponse` in `server/handler/responses.ts`), as the fetch handler does.
  - A hydrated atom runs on mount unless it's `skipInitialRun` (`experimental-react-atom`). `Socket.fromWebSocket` leaves a no-op `error` listener when it lets go (`websockets.test.ts`).
  - `Redis.make` needs `connect` (`middleware/upstash.ts`), and `HttpMiddleware.xForwardedHeaders` takes `{ trustedProxies }`.
  - `KeyValueStore.makeStringOnly` needs `keys` (`examples/cloudflare`), `NodeHttpServerRequest.toIncomingMessage` can return an `Http2ServerRequest` (`experimental-nest`), and `@effect/platform-node` imports `ws`'s `WebSocket` by name (`framework-matrix`'s `vite.config.ts`).
- (agent) `effect-latest` widens the pins to `^4.1.0` and updates to the newest 4.x, so a 4.2 shows up there before it reaches the lockfile. It updates only the workspace's direct dependencies (`pnpm update -r --depth 0`): `vendor-src` pins `effect` and `@effect/platform-node` 4.0.1, and a full update moved its `@effect/platform-node-shared` to a version that doesn't run on that `effect`.
- Lost: an app on `effect` 4.0.x has to upgrade to install, and nothing tests 4.0.x. Nothing in CI runs exactly 4.1.0 either: the lockfile has 4.1.1 and `effect-latest` the newest 4.x. On 2026-10-31, with every pin and range at exactly 4.1.0, `pnpm typecheck` and `pnpm test` (with Redis) passed.
- Open: giving `effect-latest` a Redis service would run the Redis tests on the newest 4.x.
- Lives in: `packages/*/package.json` (`peerDependencies`), the workspace's `package.json` pins, `vendor-src.json`, `.github/workflows/next.yml` (`effect-latest`), `packages/trpc/src/middleware/upstash.ts`, `packages/trpc/src/server/handler/responses.ts`, `packages/experimental-react-atom/src/index.ts`, `examples/cloudflare/src/storage.ts`.
