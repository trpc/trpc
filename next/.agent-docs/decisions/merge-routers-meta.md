# `mergeRouters` merges router-level meta and throws on a conflicting key (human)

- Question (first-release review, question 11): `mergeRouters` silently dropped a router's group meta (`t.router({ meta: { route: { prefix } } }, …)`), so OpenAPI prefixes disappeared. Recommended: throw and point at nesting.
- Human, 2026-10-19 (first-release review, question 11): "sounds good - i think we can combine the group meta with mergeRouters too and if there's collisons we throw & type error if it isn't expensive".
- (agent) Merge: the result's router-level meta is the union of its routers' top-level meta keys, stored as `t.router()` stores it, so `flattenRoutes` (the OpenAPI generator, handler and `experimental_toContract`) puts every procedure of the result under it, the other routers' too, as if the routers had been one `t.router({ meta }, …)`. A key set to `undefined` counts as unset. Nested merges compose, since the result is a router with meta. No input with meta: the result stays a plain object.
- (agent) Collision: one key in two routers with values that aren't `Equal.equals` (Effect's structural equality: equal plain objects and arrays match, functions by reference). The throw names both routers by argument position and first keys, the key and both values, and says to nest them under keys of their own.
- (agent) Shallow keys: a value belongs to the extension that declares its key, and core can't combine two of them (joining prefixes is what nesting does; unioning tags would give each router's procedures the other's), so a key's value is compared whole.
- (agent) A root router's own `route` meta now applies too (`flattenRoutes` starts from it), so `mergeRouters(adminGroup, other)` passed as the root keeps `/admin`. Before, the root's group was ignored.
- (agent) No type error: runtime only. Router types don't carry meta, so the check needs `t.router()` to return `TRoutes & { [symbol]?: TMeta }` with the meta inferred as literals, `mergeRouters` to compare those, and seven router mapped types (`inferRouterInputs`/`Outputs`/`Errors`, the Promise and Effect clients, `inferContract`, `ExactRouter`, `DuplicateKeys`) to skip the symbol. Measured with `pnpm bench shapes` (1,500 procedures, instantiations): `plain` +0.17%/+0.06% (server/with client), `middleware` +0.06%/+0.03%, and the new `merged` shape (150 `t.router()` groups with equal `route` meta through 16 `mergeRouters` calls) 550,095 → 619,013 server (+12.5%) and 984,049 → 1,057,159 with the client (+7.4%). The brand alone was +6%, over the ~1% bar for "isn't expensive".
- Why: the meta was lost with no error. A union keeps `mergeRouters(group, more)` meaning what it reads as; the throw catches the one case that has no right answer.
- Lost: per-router scoping (each input's meta over its own keys only), which never collides but leaves the result with no one meta for `routerMetaOf`; throwing on any meta (the review's recommendation), which rules out splitting a group across files; the type error, and the visible `[symbol]` key it adds to every `t.router()` type.
- Open: a type error if router types come to carry their meta for another reason (the formulation measured is the one above).
- Lives in: `packages/trpc/src/server/procedures/router.ts` (`mergeRouters`), `src/internal/describe.ts` (`flattenRoutes`), `tooling/bench/shapes.ts` (`merged`); tests in `src/server/procedures/routers.test.ts`; docs `www/docs/server/routers.md`, `www/docs/openapi/routes.md`.
