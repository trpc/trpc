# Every package is side-effect free, and a module that imports unused leaves nothing in a bundle (human)

- Human, 2026-10-19: "can you pick up https://github.com/trpc/trpc/pull/7702 and make sure that all packages are side effect free in v12? feel free to push straight to v12 and close that pr. if there's a good reason why they wouldn't be side effect free, feel free to not do it".
- (agent) Every package under `packages/` declares `"sideEffects": false`, except `@trpc12/upgrade`, which lists its CLI (`["./src/bin.ts", "./dist/bin.js"]`): that file runs the codemod when it loads, and isn't an entry point. #7702 added the flag to `@trpc12/experimental-nest` and `@trpc12/upgrade`, the two without it.
- (agent) Beyond the flag, each built module bundles to nothing when imported unused and the flags are ignored: module-level calls a bundler can't prove pure are marked `/* @__PURE__ */` (`Context.Service()`, `Context.Reference`, `new TextEncoder()`, `experimental_createProgressiveJson()`, `Effect.fnUntraced`, `Data.taggedEnum` members, `TrpcError.Tagged` bases, progressive JSON's `instancesOnly`/`objectsOnly` registrations). That covers bundlers and setups that skip the flag, and modules an app uses part of, whose unused top-level values then drop too.
- (agent) Three modules still run code on load, each with a reason:
  - `@trpc12/experimental-nest`: Nest's decorators record dependency-injection metadata on the module's own classes. Nothing outside the module sees it, so the flag still drops the module unused.
  - `trpc/internal/error.ts`: the loop that attaches `TrpcError.NotFound` and the other built-in classes to `TrpcError` as own properties. It changes only `TrpcError`, so the flag still drops the module unused. A pure form would cost bytes in every client (25 named static fields) or change what `Object.keys(TrpcError)` lists (lazy getters). A `static #builtins = attach(TrpcError)` field shakes out unused but is dropped by rolldown's minifier when used.
  - `@trpc12/upgrade`'s `bin.ts`, the CLI, listed in `sideEffects`.
- (agent) `tooling/pack/pack.test.ts` checks it after the build. For every package, it checks the `sideEffects` value, and that only the modules listed in `runsOnLoad` keep code when bundled alone with flags ignored. For every published entry, it checks that an unused import bundles to nothing with flags honoured. The bundles are rolldown builds with dead code removed (`dce-only`, in `tooling/pack/side-effects.ts`). Reading a member of an import (`Equal.symbol`) counts as pure, as minifiers assume.
- Why: the human asked; and an app importing one helper from `@trpc12/trpc/server` shouldn't carry the module-level values of everything else that file's module graph reaches.
- Lost: `/* @__PURE__ */` comments in about 50 places, which the next module-level call needs too (the test shows the module that lacks one and the code it keeps). Minified bundles that keep annotations grow by the comments: the fetch handler is 0.6 kB larger minified, the same gzipped, and 84 B smaller with annotations stripped (`pnpm bench bundle`). `pnpm bench budget`'s minimal client went from 39.6 to 39.5 kB gzip, the full client from 43.7 to 43.8 kB.
- Lives in: `packages/*/package.json` (`sideEffects`), the annotated module-level values in `packages/*/src/`, `tooling/pack/side-effects.ts` and `tooling/pack/pack.test.ts` (`runsOnLoad`).
