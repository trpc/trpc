# Plain JSON is the default serializer; danSON is ported in and opt-in (human)

- Human, 2026-10-16 (Q11.1, decision round): "B". With no serializer, the handler and links use plain JSON (`jsonTransformer`); danSON is opt-in with `createSerializer()` on both ends. v11's default had no transformer either.
- Human, 2026-10-16 (Q11.2, decision round): "A". danSON's code is ported into `@trpc12/trpc/transformer` (Effect `Stream`s for the async format, [`../notes/danson-port-and-query-params.md`](https://github.com/trpc/trpc/blob/d5c34c43000547776ca234ac47edafd48370e6fd/next/.agent-docs/notes/danson-port-and-query-params.md)), not a dependency on the `danson` package; wire compatibility with standalone danSON isn't kept.
- Human, 2026-10-16 (Q11.3, decision round): "For rpc I think input should work best". RPC `GET` inputs are one `?input=<serialized JSON>` param for every serializer, keys sorted ([`wire-protocol.md`](./wire-protocol.md)). Bracket notation stays with OpenAPI and forms ([`openapi.md`](./openapi.md)).
- (agent) Built, 2026-10-16: `jsonTransformer` is the default of `createFetchHandler`, every link, `localLink` and `hydrationOptions`; `createSerializer()` is danSON; `defaultSerializer` is gone. Server stores that need rich types (durable call results, cache keys) keep danSON internally, whatever the wire serializer. Plain JSON can't carry a `bigint` or a file input; those fail before sending.
- (agent) Types that are already JSON (recursive JSON types, branded tuples, AI SDK chunks) are kept as written in the JSON form, instead of being re-mapped; a key typed `unknown` stays required. Validation error `path`s are `(string | number)[]` (symbol keys arrive as `String(key)`), so error data is plain JSON.
- Deserialized objects have `Object.prototype`, not a null prototype. The deserializer already rejects `__proto__`, `constructor` and `prototype` keys.
- (agent, 2026-10-19) The deferred values' streams are built from Effect's constructors ([`effect-internal-patterns.md`](./effect-internal-patterns.md)). Sending, a deferred `AsyncIterable` or `ReadableStream` is read with `Channel.fromAsyncIterable` and a file's bytes with `Channel.fromReadableStream`, one item per item read, instead of a loop in `Stream.callback` reading up to 16 ahead and an `async function*`; a `Promise` settles a `Deferred` from the moment it's found, which also handles its rejection. Receiving, the chunk queues are made in Effect (`makeChunkQueues`, shared by danSON and the framed serializers) by whichever comes first, a value's chunk or its reader, instead of with `Effect.runSync`; the `Promise`, `AsyncIterable` and `ReadableStream` handed to users run on the deserializing fiber's context (`Effect.runPromiseWith`, `Stream.toAsyncIterableWith`, `Stream.toReadableStreamWith`), and frames waiting for file bytes are fibers forked as its children instead of detached. An `AsyncIterable`'s `return()` now ends a `next()` still waiting for a chunk; the `async function*` queued it behind that read, so it hung. +301 B gzipped on the minimal client, +309 B on the full one.
- Why: the default should be the smallest thing that works with any client; rich types are one option away.
- Lost: native `Date`/`Map`/`File` outputs out of the box; legible RPC query strings (QP-C).
- Lives in: `packages/trpc/src/transformer/` (`danson/stream.ts`: `sourceOf`, `makeChunkQueues`); tests in `packages/trpc/src/transformer/transformers.test.ts` (an `AsyncIterable` returned while it waits).
