# The Experiments menu filters, folds each experiment's pages, and its state is in the URL (human asked)

- Human, 2026-10-19: "make the experiments menu a bit better now that there's a lot of stuff in it. also make its state owned by the url so we can link to it (don't scroll when toggling it and should still close on nav change etc)".
- (agent) The menu ([`docs-experiments.md`](./docs-experiments.md)) is wider, its header and footer stay put while its list scrolls, and its header says how many are on ("2 of 10 on"). A filter box, focused on opening (except by touch), matches an experiment's label, description and page titles. Each row is a small switch, the label and a one-line description; a row that's on is tinted. Its pages are folded behind an "N pages" button, and a filter shows the matching rows' pages. The footer has "Copy link", "Turn all on" and "Turn all off".
- (agent) `?experiments=open` opens the menu, and `?experiments=<id>` opens it with that experiment's pages showing, scrolled into view in the list. The "N pages" button switches between the two. Opening, closing (Escape, an outside click, the trigger), switching and picking an experiment all rewrite the query in place, with `replace`, no scroll reset and the hash kept, so they add no history entry and the page doesn't move. `?flags=` is kept on navigation and `?experiments=` isn't, so following any link closes the menu; the menu's page links drop it too. Back to a URL that had it opens the menu again.
- (agent) The menu opens once the page has hydrated: it's a popup in a portal, which only renders in the browser. The server renders the trigger closed for every URL, so a static page and an on-demand one ([`docs-flags-on-demand.md`](./docs-flags-on-demand.md)) hydrate without a mismatch. `?experiments=` alone doesn't send a request to the function. On the home page's v11 view, where the button is hidden, the param doesn't open it.
- Human, 2026-10-19: "the experiment button thing in the top menu should now render as a link (with prevent scroll reset)".
- (agent) The header's trigger is the router's link to this URL with `?experiments=open` toggled, keeping `?flags=` and the rest, with `replace` and no scroll reset like the menu's other rewrites. It's an `<a href>` in the server's HTML, so it can be middle-clicked or copied, and pressing it opens or closes the menu through that href; the popup's outside-press dismissal ignores presses on it. It keeps `aria-expanded`, `aria-haspopup="dialog"` and, while open, `aria-controls` naming the popup, which is anchored to it and returns focus to it. The hash joins its href after hydration, since the server doesn't know it.
- Human, 2026-10-19: "toggling stuff in the experiments menu shouldn't scroll to top", then "it seems like it's just scrolling a bit up... it shouldn't scroll at all".
- (agent) Pressing a row's name or description scrolled the page up about half a screen each time; the switch itself didn't. The row is a `<label>`, and base-ui's switch is a `<span>` beside a hidden checkbox, so the label focused the checkbox. That's `position: fixed` at the top, which keeps focusing it from scrolling, except under a transformed ancestor such as the popover's positioner, where Chrome scrolled to it (smoothly, from `scroll-behavior`). The shared `Switch` is a native `<button>` now (`nativeButton`), which a label clicks and focuses in place, everywhere it's used. `www/smoke.ts` (`pnpm smoke`, `SITE_URL` for a deployment) presses every kind of control in the menu while scrolled, on a docs page and the home page, and fails on a move.
- (agent) The router wasn't involved: the menu's rewrites already had `resetScroll: false`, the docs routes don't load on search changes, and the switches that add or drop pages (the sidebar scrolls on its own, a page's "Pages under" list) left the page where it was. Turning an experiment off on its own page drops its "Pages under" list, so a reader at the very bottom moves up by that much; that's the page getting shorter.
- Why: ten experiments with their descriptions and page links made the menu a tall list to read through, and sharing "turn on X and look here" needed a URL that opens the menu where X is.
- Lost: "no turn all on" ([`docs-experiments.md`](./docs-experiments.md)): there is one now, for reviewers who want everything at once. The filter text isn't in the URL. Every row's pages at a glance (they're one click away).
