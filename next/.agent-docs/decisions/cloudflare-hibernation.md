# Cloudflare WebSocket hibernation in v1 (human)

- Human, 2026-10-15 (issues review Q2, proposal Q14.7): "A". Hibernation ships in v1, not later.
- (agent) An adapter for the Durable Object handler style: `webSocketMessage(ws, message)` and `webSocketClose(ws, code, reason)` on the object call into the same socket core as `handler.websocket`. Per-connection state (the connection params and the request) lives in the socket's serialized attachment, so a woken object rebuilds it.
- (agent) Queries and mutations need nothing kept between messages. A subscription keeps the object awake while its generator runs, as Cloudflare requires for any pending work; hibernation helps idle connections, not open streams.
- Why: Workers are a first-class platform, and idle WebSocket connections on Durable Objects are billed unless they hibernate.
- Lost: oRPC's "durable iterator" (subscriptions that survive hibernation), which would need the publisher to replay into a rebuilt generator.
- (agent) The Open here (resuming subscriptions after the object wakes) is done: publisher subscriptions are kept on the socket and replay from `lastEventId` ([`hibernation-state-and-subscriptions.md`](./hibernation-state-and-subscriptions.md)).
- Human, 2026-10-18 (decision round, Cloudflare): "A - group all of that under one thing (i think it's all cloudflare stuff?)". Every value `@trpc12/trpc/cloudflare` exports is `experimental_`: `hibernatingPublisher` and `connectionToken` became `experimental_hibernatingPublisher` and `experimental_connectionToken`, with no deprecated aliases since nothing had shipped. The docs for the entry point are one hidden page, `docs/adapters/cloudflare.md` ([`docs-experiments.md`](./docs-experiments.md)).
- (agent, 2026-10-19) Internals on Effect's fiber ownership ([`effect-internal-patterns.md`](./effect-internal-patterns.md)): the adapter owns one `Scope` for the object's lifetime, and every callback's work (`accept`, `message`, `close`, a publisher's delivery) is a fiber in its `FiberSet`, through `FiberSet.makeRuntime`, instead of a bare `Effect.runFork`. Each socket's receiver is built inside that fiber, in a scope forked from the owner, so the per-socket `Effect.runSync` is gone. Deliveries are Effects (`Effect.exit`, `Effect.forEach` over the parked sockets) instead of `async` functions over `Effect.runPromiseExit`; the publisher joins the delivery's fiber, so a publisher interrupted while it waits doesn't stop the delivery, as before. The object's methods stay host-shaped (`void`, `Promise`). The `FiberSet` is a set of fibers, not a `FiberMap` keyed by socket: Effect's `MutableHashMap` hashes keys structurally, so two sockets with the same fields (every native one) would share a key.
- Lives in: `packages/trpc/src/cloudflare/hibernation.ts` (`@trpc12/trpc/cloudflare`), `src/cloudflare/publisher.ts`, `docs/adapters/cloudflare.md`.
