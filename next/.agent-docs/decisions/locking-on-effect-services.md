# `experimental_lock()` over an `experimental_Locker` Effect service (agent)

- Builds the locking row of [`orpc-v2-parity.md`](./orpc-v2-parity.md). Effect 4 has no distributed lock, so unlike [`rate-limit-on-effect-ratelimiter.md`](./rate-limit-on-effect-ratelimiter.md) there is a service of our own, shaped like Effect's: one key, layers per store.
- (agent) `experimental_Locker` has one method, `acquire(key, { ttl?, timeout? })`, an `Effect<{ waited }, experimental_LockTimeout, Scope>`: the lock is held until the scope closes or `ttl` (30 seconds) passes, and waiting fails after `timeout` (10 seconds). Store failures are defects.
- (agent) Layers: `experimental_memoryLocker()` (waiters queue in order, nothing polls), `experimental_redisLocker({ prefix?, retryInterval? })` on Effect's `Redis` service (`SET NX PX`, a token-checked Lua delete; tries again every 100 ms), and `experimental_durableLocker(namespace)` from `@trpc12/trpc/cloudflare`.
- (agent) The Durable Object store follows oRPC's: one object per key, and each caller holds a hibernatable WebSocket while it holds or waits, so a crashed holder's lock goes with its socket and waiters are told, not polling. The object delegates to `experimental_durableLockObject(ctx)` (`fetch`, `close`), the same shape as `experimental_createHibernatingWebSockets`, so the package imports no `cloudflare:workers`. The object answers a closing socket's close: without that the caller's invocation never ended on workerd.
- (agent) `experimental_lock<{ input }>({ key, ttl?, timeout? })` from `@trpc12/trpc/middleware` requires `experimental_Locker`, so a handler without a locker layer is a type error. It adds `ctx.lock: { waited }` and fails with `experimental_LockConflict` (`CONFLICT`, 409) after `timeout`.
- (agent, tentative) A key the call already holds, from an earlier `experimental_lock()` in its chain, isn't taken again; held keys live in a `Context.Reference`, so this also covers Effect code the resolver runs. oRPC dedupes the same way, per locker and key.
- (agent, tentative) `ttl` is a hard limit, as in oRPC: a holder that runs longer loses the lock while it's still running. A heartbeat (renewing every `ttl / 3`) would remove that trap; it's not built.
- (agent) Upstash isn't a separate layer: Effect's `Redis.make({ send, subscribe })` can wrap Upstash's REST client, and `experimental_redisLocker` runs on it. Not tested against Upstash.
- Why: the store is a layer like every other backend, Redis comes from Effect, and the only tRPC-specific code is the middleware and the error.
- Lost: oRPC's `waited` key in context is `ctx.lock.waited`; the lock covers the resolver, not a streamed output or subscription that keeps running after it returns.
- Lives in: `packages/trpc/src/server/lock.ts`, `src/cloudflare/lock.ts`, `src/middleware/index.ts`, `test/integration/lock.test.ts` (memory; Redis when `REDIS_URL` is set, as in CI), `examples/cloudflare` (a seat locked across two room objects, run on workerd by `pnpm example`), `docs/procedures.md`, `docs/platforms.md` (Locks in Durable Objects).
