# Client-side validation is an opt-in link over a contract (agent)

- Human, 2026-10-15 (Q5.5, in [`client.md`](./client.md)): "Yes later. I don't like packaging the contract in the clients if we don't need to". So validation is opt-in, and only apps that add it ship schemas to the browser.
- (agent) `validationLink({ contract, input = true, output = true | 'json' })` from `@trpc12/trpc/client`, placed before the transport link. oRPC splits it into `RequestValidationPlugin` and `ResponseValidationPlugin`; links already compose, so one link with two switches is enough.
- (agent) Inputs: every static `.input()` schema runs against the input before anything is sent, failing with the server's `BAD_REQUEST` (`data.issues`), so a form can render the same errors either way. The original input is sent, not the parsed one: the server parses it again and expects the encoded form. Function (context-aware) inputs need server ctx and are skipped.
- (agent, Effect-native first) Outputs are checked against `Schema.toType(output)`: the server already decoded them, so running transformations again would fail (oRPC documents this as a limitation; Effect Schema separates the type side, so @trpc12/trpc doesn't have it). Standard Schema outputs are validated as they are, with oRPC's limitation.
- (agent) `output: 'json'` decodes with `Schema.toCodecJson(Schema.toType(output))` for transports that send plain JSON (`experimental_openApiLink`), restoring `Date`, `bigint` and classes. This answers "response validation in `experimental_openApiLink`" ([`openapi.md`](./openapi.md)).
- (agent) A mismatch fails with `BAD_RESPONSE` (`defined: false`, like other responses the client can't read), message "Response validation failed: …" and the issues on its `cause` ([closed-client-errors](./closed-client-errors.md): built-in errors have no `data`). Subscription events are checked one by one; `tracked()` envelopes check their `data`. `stream()` outputs are not checked on the client.
- (agent) The link reads schemas from a contract or a router (any tree of `'~trpc'` definitions). Paths it doesn't have pass through.
- Lost: validation without shipping schemas; checking `stream()` items and context-aware inputs on the client.
- Lives in: `packages/trpc/src/client/links/validation.ts`, `src/client/index.ts`, `packages/trpc/src/client/links/validation.test.ts`, `docs/client/validation.md`.
