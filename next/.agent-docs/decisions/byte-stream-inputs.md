# `ReadableStream<Uint8Array>` inputs are `experimental_byteStream()`, the request body read as an Effect `Stream` (human)

- Human, 2026-10-19 (decision round, which partial oRPC-parity rows to defer past 12.0): "C) but they should all be experimental_ and hidden by default in the docs".
  - Options were: A) defer all three (`ReadableStream<Uint8Array>` inputs, the Upstash and Cloudflare rate-limit stores, type-check speed); B) only work on type-check speed; C) do all three before 12.0. The stores are in [`rate-limit-on-effect-ratelimiter.md`](./rate-limit-on-effect-ratelimiter.md).
- (agent) oRPC's RPC link sends a root `ReadableStream` input as the request body itself (`rpc-link-codec.ts`), and its batch plugin leaves such calls out (`plugins/batch.ts`). v12 keeps that wire and makes the types Effect-native ([`effect-native-by-default.md`](./effect-native-by-default.md)).
- (agent) `experimental_byteStream({ maxBytes? })` from `@trpc12/trpc/server` is an Effect Schema: `ReadableStream<Uint8Array>` encoded (what the client passes) and `experimental_ByteStream` decoded, a `Stream<Uint8Array, experimental_ByteStreamError>` over the body. The stream fails with `PAYLOAD_TOO_LARGE` past `maxBytes` (no limit by default; `maxBodySize` doesn't apply, as the body is read only as fast as the resolver pulls it) and with `BAD_REQUEST` when the body can't be read or is read a second time. Those failures are in the procedure's error union.
- (agent) The handler takes an `application/octet-stream` body only for a procedure with an `experimental_byteStream()` input step (an annotation on the schema), and only with the `trpc-version` header, as for multipart; `UNSUPPORTED_MEDIA_TYPE` otherwise. The body is handed over unread. On Node, a stream the resolver stops early is drained instead of destroyed, as `maxBodySize` does, because Node drops the connection before the response otherwise; a body nobody reads is left to the server. A body `express.raw()` read is replayed. Lambda's buffered body is read from memory.
- (agent) `httpLink` sends a root `ReadableStream` input alone, outside batches, as a `POST` with the stream as the body (`duplex: 'half'` through `FetchHttpClient`). Such a call isn't resumed, and `retryLink`'s default never retries it: the stream is read once. Socket links fail it with `BAD_REQUEST`; `localLink` and `createRouterClient` pass it through. A mutation can stream its output while the body arrives (checked on Node).
- (agent) Documented on Byte stream inputs (`docs/server/byte-streams.md`), the only page of a new `byte-streams` experiment, so it's hidden by default ([`docs-experiments.md`](./docs-experiments.md)); no listed page links it.
- (agent) `examples/media-pipeline` uploads a photo's original as a byte stream (`photos.uploadOriginal`).
- Why: oRPC's parity row was the last half of "typesafe `ReadableStream<Uint8Array>`"; outputs already stream. A schema keeps the client type (`ReadableStream`) and the resolver type (`Stream`) apart the way Effect Schema's encoded and decoded sides do, and a raw body is the one wire that streams on every runtime without buffering.
- Lost: a stream next to other fields (`{ name, body }`): only the whole input can be one, so metadata goes in headers or another call. Streaming request bodies in browsers that lack them (fetch fails before sending), and full duplex in browsers that have them (half duplex, HTTP/2 only).
- Open: a stream nested in an input, as a streamed multipart part, needs a streaming multipart reader in the handler; the OpenAPI handler and `experimental_generateOpenApi` don't know byte stream inputs; the v11 interop handler still buffers `application/octet-stream` into a `Blob`, as v11 did.
- Lives in: `packages/trpc/src/server/validation/byte-stream.ts`, `src/server/handler/fetch.ts` (`readInput`, `takesByteStream`), `src/server/handler/body.ts` (`bodyStream`), `src/client/links/http/transport.ts`, `src/client/links/events.ts` (`isByteStreamInput`), `src/client/links/basic.ts` (`retryLink`), `src/client/links/local.ts`, `src/server/validation/byte-stream.test.ts`, `src/server/handler/body.test.ts`, `src/http/serve.bun.test.ts`, `docs/server/byte-streams.md`, `www/src/experiments.ts`, `examples/media-pipeline/`.
