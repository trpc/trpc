# Docs pages that wait for review are grouped experiments, hidden from the site's navigation and from search engines, but found by its search (human)

- Human, 2026-10-18: "ok so i want to start trimming stuff down from what we've done now and hide certain parts that we've just "vibe ported" from orpc etc on the site … it's overwhelming to review all of this stuff and its overwhelming to know what to use and not … can you prompt me on things to hide? i also want those things to be hidden from search engines".
- Human, 2026-10-18 (decision round, what hidden means): "B": unlisted, plus an experiment that shows the hidden pages.
- Human, 2026-10-18: "let's make the partner placements a core thing, so remove that feature flag / and i want experiments to be grouped so you can hide specific feature / when you visit it directly, it should likely be auto enabled / it doesn't need to say it's a hidden page or have special visibility in the sidebar, just that it's experimental features / we can also link stuff in the experiment menu directly". The partners part is in [`docs-sponsors.md`](./docs-sponsors.md).
- (agent) `experiment: <id>` in a page's frontmatter puts it in one of the experiments `www/src/experiments.ts` lists, each with a label and a line saying what it covers. The build rejects an id that isn't there. The groups follow the decision rounds below: Contracts and OpenAPI (`contracts`, which takes NestJS because `@trpc12/experimental-nest` serves contracts), Publisher, Rate limits, locks and durable calls (`middleware`), Cloudflare, More adapters (`adapters`), TanStack Query beyond React (`tanstack-query-frameworks`), TanStack DB, React without TanStack Query (`experimental-react`) and AI SDK and Better Auth (`integrations`).
- (agent) Each experiment is a flag in `?flags=` (comma-separated, kept by every navigation as before). While it's off, its pages are still built and served at their URLs, but the sidebar, prev/next links, "Pages under" lists and the breadcrumb's section link leave them out, and the version switcher doesn't land on them from v11. Turned on, its pages show in the sidebar and pagination like any other.
- (agent) Opening an experiment's page turns its experiment on (`useEnableOnVisit` in `www/src/flags.ts`), whether by link or by typed URL, by adding it to `?flags=` with a `replace` navigation. This happens only on arrival, so a reader who turns the experiment off from the menu while on the page keeps it off.
- (agent) An experiment's page has an "Experimental" badge above its title, with the experiment's label and "might change or go away in any release" (the human's definition of experimental, 2026-10-19), linking Stability in `www/docs/packages.md`. The menu's description says the same. The sidebar shows it like any other page. The "Hidden page" note and the crossed-out eye are gone.
- (agent, 2026-10-19) Every experiment flag maps to prefixed names: what only its pages document is `experimental_*` or in an `@trpc12/experimental-*` package (the human, [`stability-jsdoc-tags.md`](./stability-jsdoc-tags.md)), which `trpc/jsdoc` and `tooling/pack/docs.test.ts` check. The `integrations` and `tanstack-db` experiments are recipes over stable exports, so they have none.
- (agent, 2026-10-19) Unstable features aren't experiments: their pages are listed and indexed, with an "Unstable" badge from `stability: unstable` in the frontmatter ([`stability-jsdoc-tags.md`](./stability-jsdoc-tags.md)).
- (agent) The header's Experiments menu lists each experiment with its switch, its line, and links to its pages. A link turns the experiment on and closes the menu.
- Human, 2026-10-20: "btw i do now think that experimental pages should be hdiden from seo but we should still show them in search". It takes back 2026-10-19's "it's fine to enable seo for experimental stuff"; the site as a whole stays unindexed until it's trpc.io ([`site-noindex-until-trpc-io.md`](./site-noindex-until-trpc-io.md)).
- (agent) Search engines don't index an experiment's page, whatever the flags say. It has `<meta name="robots" content="noindex">` and the sitemap leaves it out. Until the site is trpc.io every response says `X-Robots-Tag: noindex`; from then on, on Vercel, the page and its `.md` still do (`build/vercel-output.ts` reads the pages' robots meta once the build is indexable). A home page feature card whose page is in an experiment isn't shown.
- (agent) The site's search finds an experiment's page and its headings whether the experiment is on or not, with a flask beside each result, ranked a little below listed pages; opening one turns its experiment on. The empty dialog's suggestions are listed pages only. How search works is in [`docs-search.md`](./docs-search.md).
- (agent) Agents still find it: `llms.txt` and `llms-full.txt` list it, its `llms.txt` line reading "Experimental.", and its markdown says under the description that its experiment might change or go away in any release. An agent asked about the feature should reach its page and see where it stands, and `llms.txt` is read on request, not ranked in search results.
- (agent) The build fails when a listed page links to an experiment's page or nests under it in the sidebar, so browsing with every experiment off never reaches one. An experiment's pages may link anywhere, including other experiments' pages. Hiding a page means trimming what the listed pages say about it.

- Why: the v12 docs grew a page for every oRPC parity row and every agent call, which is too much to review and makes it hard to tell what to use; hiding keeps the work (and its tests) while the site shows what's been reviewed. Grouping lets a reader, or a reviewer, show one feature at a time, and a link to a page shows its feature without a trip to the menu.
- Lost: experiments are invisible to readers who don't open the menu or a link to their pages; their pages' links from listed pages, which go until a page is shown again; one switch for every experiment's pages ("Turn all off" remains, but there's no "turn all on"). Search traffic to experiments' pages, and a search result an agent's answer could cite.
