# Zod and Effect Schema input issues keep their library's shape (human asked)

- Human, 2026-10-17: "Ok, would it possible to infer shapes on zod and effect schemas at least?", then "Do it. We want first class support for both".
- (agent) Library-wide, not per schema: neither library records checks in a schema's type (zod's `z.string().min(3)` is a `ZodString`, Effect's `.check()` keeps the type; zod's `_zod.isst` types only the issues a schema raises itself, not its checks'), so a per-schema union would leave out issues the schema sends. Each issue is the library's full union, with `path` typed from the input ([`typed-input-issue-paths.md`](./typed-input-issue-paths.md)).
- (agent) `.input(schema)` adds `InputValidationError<inferInputIssue<schema>>`, with `inferInputIssue` picking by library:
  - Zod 4 (`ZodInputIssue`): zod's issue fields (`code`, `minimum`, `format`, `keys`, `values`, `params`, …), narrowed by `code`. `invalid_union` keeps its nested `errors`, `invalid_key`/`invalid_element` their nested `issues`, with untyped relative paths. The union is read from the schema's type (`_zod.run` reports raw issues; `invalid_union`'s nested `errors` are the finished ones), so @trpc12/trpc doesn't import zod. At runtime, `~standard.vendor === 'zod'` keeps the fields Standard Schema's validate already returns.
  - Effect Schema (`EffectInputIssue`): the leaves of Effect's issue tree, walked like `SchemaIssue.makeFormatterStandardSchemaV1` (same messages and paths), with the leaf's `_tag` and `check: { id, payload }` from a failed filter's `representation` (`'effect/schema/isMinLength'`, `{ minLength: 3 }`). A filter with no representation (a custom `makeFilter`) gives `check: {}`.
  - Other Standard Schema libraries (`InputIssue`): `message` and `path`.
- (agent) Effect inputs decode with `{ errors: 'all' }`, like zod, so a form gets every field's issue, not only the first.
- (agent) Issues are JSON on the server, the same under every serializer: zod's `input` is dropped (it echoes what the caller sent), `bigint`s and symbols become strings, `undefined` in arrays becomes `null`, `undefined` keys are dropped. Values that are open in the libraries' types (zod's `params` and an `invalid_element`'s `key`, Effect's `payload`) are `unknown`: a recursive JSON type sent Vue's deep `UnwrapRef` past its depth limit in `useInfiniteQuery`.
- (agent) Because they are JSON already, `InputValidationErrorData` has a type-only `'~issues'?: true`, and the client's `ErrorData` keeps such data as written instead of mapping it through `JsonOf`. Without it, plain-JSON clients rebuild the zod union field by field, and the nested issue lists (an interface, so the recursion is lazy) aren't arrays to `JsonOf`.
- (agent) Kept: zod's `pattern` (a regex's source) and Effect's check payloads (`isPattern`'s source too). The schemas' JSON Schema in the OpenAPI document publishes the same patterns.
- (agent) The OpenAPI document keeps its generic `issues` schema for `BAD_REQUEST`; `experimental_generateOpenApiFromTypes` skips the inferred input error's data instead of converting the recursive zod union.
- Why: forms read zod's `code`/`minimum` or Effect's `_tag`/check without casts, as they would calling the library directly.
- Lost: zod's `input` on issues, also when `reportInput` is on. Exact `bigint` types in zod issues (`minimum` is `number | string`). Zod 3 schemas keep `{ message, path }` types (no `_zod`), though their runtime fields pass through. Typecheck cost, measured against typed paths alone: `pnpm --filter @tooling/bench bench typecheck` (3,000 Standard Schema procedures) 1,217,050 → 1,265,824 instantiations (+4%), check time unchanged (0.93s → 0.91s); the same 3,000 procedures with zod 2,141,332 → 2,173,908 (+1.5%), check time 1.65s → 1.69s (medians of 3).
- Open: zod's `_zod.run` is internal API; a zod release that changes its payload type falls back to `{ message, path }` types (`never` from the inference), which `input-issues.test.ts` would catch.
- Lives in: `packages/trpc/src/server/schema.ts` (`inferInputIssue`, `ZodLike`, `ZodInputIssue`, `EffectInputIssue`, `normalizeZodIssue`, `effectIssues`), `src/client/types.ts` (`ErrorData`), `src/openapi/typescript.ts`, `packages/trpc/src/server/input-issues.test.ts`, `docs/server/procedures.md`.
