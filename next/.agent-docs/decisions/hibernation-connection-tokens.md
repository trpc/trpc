# Signed connection tokens for Durable Objects (agent)

- (agent) Built for the "signed tokens are later" in [`hibernation-state-and-subscriptions.md`](./hibernation-state-and-subscriptions.md). `connectionToken(schema, { secret, ttlSeconds? })` in `@trpc12/trpc/cloudflare` returns `{ sign, verify }` as Effects. The Worker that authenticated the user signs claims, the client sends the token in `connectionParams`, and the object's `createContext` verifies it.
- (agent) The format is ours, not JWT: `base64url(JSON { c: claims, exp }) . base64url(HMAC-SHA256)`, with WebCrypto (`crypto.subtle`, on every runtime). Claims go through the given Effect `Schema` (`Schema.fromJsonString`), so `Date`s or branded ids round-trip and bad claims fail to decode. A JWT library would be a dependency, and nothing else reads these tokens.
- (agent) `verify` fails with `TrpcError` `UNAUTHORIZED` (missing, malformed, bad signature, expired, bad claims), so a failed `createContext` becomes the call's 401. Time comes from Effect's `Clock`, so tests move it with `TestClock`. `secret` takes a `Redacted` too.
- (agent) Expiry is checked when `createContext` runs, not while a subscription is parked; a parked subscription isn't re-authenticated per event. Documented rather than solved: re-checking would wake the object for every event.
- Compared: oRPC's Durable Iterator signs a token per iterator (`chn`, `tags`, `att`) and refreshes it from the client. Here the token is only the auth handoff; channels and tags are ordinary `ctx` and `Publisher` options.
- Why: Durable Objects can't share the Worker's session store cheaply; a signed token is the usual handoff, and Effect `Schema` plus WebCrypto keeps it typed and dependency-free.
- Lost: token refresh on a live connection (reconnect with a new token instead) and per-method RPC grants.
- Lives in: `packages/trpc/src/cloudflare/token.ts`, `src/cloudflare/index.ts`, `test/integration/hibernation.test.ts`, `docs/platforms.md` (Signed connection tokens).
