# Handler internals and per-call sinks are Effect services (human asked)

- Human, 2026-10-18: the `WeakMap` registries should be Context services or Layers where it fits, and code reading the request with `Effect.withFiber` plus `Context.get` should yield the service. The outcome is theirs; the details below are the agent's.
- (agent) The frame sink `experimental_durable()` hands a streamed output's frames through is `CurrentFrameSink`, a `Context.Reference` the HTTP handler provides to an unbatched call through `runEffect`'s `services`, as hibernation's `HibernationSlot` is. The middleware yields it and `callProcedure` reads it from the call's services. Before, it was a `WeakMap` keyed by the call's `ResponseHandle`.
- (agent) A handler's internals are services in one `Context` per handler: `HttpApp` (its `effect/http` app and middleware), `UpgradeServer` (how it serves an upgraded socket) and `SocketCore` (what socket transports share), each a `Context.Service` key. `createFetchHandler()` and the v11 handler build that `Context`; `toHttpEffect()`, `serveSocket()` and the hibernating Durable Object read their service from it. Before, these were three `WeakMap`s.
- (agent) `fetch.ts`'s app and `routes.ts`'s upgrade route `flatMap` the `HttpServerRequest` service instead of `Effect.withFiber` plus `Context.get`, and the call's parent span is `Effect.serviceOption(Tracer.ParentSpan)`.
- (agent) Kept as a lookup: `toHttpEffect(handler)`, `serveSocket(handler)` and `experimental_createHibernatingWebSockets(handler)` are handed the user's plain handler object, so the handler's `Context` is found by the object's identity, in one `WeakMap` (`server/handler-context.ts`). A `Context` passes services through effects; it can't hang them off an object, and a symbol property would show on the handler's public type.
- (agent) Kept: `server/execution/execute.ts`'s `Effect.withFiber` calls take the fiber's whole context (middleware services, the tracer) to run steps with it, not one service.
- Why: services have typed keys and travel with the call or handler they belong to, instead of side tables keyed by objects.
- Lost: nothing users see.
- Lives in: `packages/trpc/src/server/handler-context.ts`, `src/server/execution/frame-sink.ts` (`CurrentFrameSink`), `src/server/fetch.ts` (`HttpApp`, `parentSpan`), `src/server/sockets/upgrade.ts` (`UpgradeServer`), `src/server/sockets/socket.ts` (`SocketCore`), `src/server/routes.ts`, `src/http/index.ts`, `src/socket/index.ts`, `src/cloudflare/hibernation.ts`, `src/interop/handler.ts`, `src/middleware/durable.ts`, `src/server/execution/execute.ts`; tests in `packages/trpc/src/http/adapters.test.ts`, `src/socket/socket.test.ts`, `src/cloudflare/hibernation.test.ts` and `src/middleware/durable.test.ts`.
