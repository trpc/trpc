# Docs pages nest under a parent page, and sections open with an overview (human asked)

- Human, 2026-10-18: "I feel like I'm missing overview pages or multiple levels in navigation, for instance there's maaaany built links but they don't have specific navigation".
- Human, 2026-10-18: "Make sure every package has good structured docs and that navigation is simple enough to go through".
- (agent) A page names its parent with `parent: <slug>` in its frontmatter, a page of the same section. The build fails on a parent that isn't a page, is in another section, or forms a cycle (`readingOrder` in `www/build/content.ts`). Children follow their parent in reading order (previous and next links, `llms.txt`), sorted by `order`, so a nested page's `order` counts among its siblings.
- (agent) The sidebar is a tree: a parent has a chevron that folds its children, and the branch holding the current page starts open (also in the prerendered HTML). A parent page shows its ancestors in the breadcrumb and ends with "Pages under …" cards of its children.
- (agent) Sections fold too: the sidebar shows section headings, and only the section holding the current page starts open (the first section off the docs pages, and in the prerendered HTML). Opening another doesn't close it; navigating opens the new page's section.
- (agent) Every built-in link has a page under Client > Links (`www/docs/client/links/`: `httpLink`, `wsLink`, `splitLink`, `switchLink`, `retryLink`, `dedupeLink`, `loggerLink`, `localLink`), with Custom links nested there too (`experimental_validationLink`'s page moved to the Contracts and OpenAPI section, [`docs-experiments.md`](./docs-experiments.md)). `client/links.md` is the overview: the chain, and a table of the terminating links and the links in the middle. Publisher backends nest under Publisher.
- (agent) TanStack Query is an overview (frameworks table, the helpers, call options) with a page per adapter (React, Preact, Vue, Solid, Svelte, Angular, Lit), then topic pages shared by all of them: keys and filters, subscriptions, streamed mutations, hydration and offline, TanStack DB. Each adapter's examples compile in `www/samples/docs`, which installs the frameworks.
- (agent) "React and Next.js" is a parent page that says which React package to pick, over RSC, Server Actions, `experimental-react` and `experimental-react-atom`.
- (agent) Migrating from v11 is an overview of four steps, each a page: serve v11 clients, run the codemod (`@trpc12/upgrade`), your v11 links, API changes.
- (agent) Server, Middleware, Integrations and OpenAPI open with an overview page (`label: Overview`, `order: 0`), as Client, Subscriptions and Adapters already did. Middleware's overview is the list of built-in middleware and the layer each needs, which `server/middleware.md` used to carry.
- (agent) Links whose v12 page is small, or which live elsewhere (`experimental_socketLink`, `experimental_messagePortLink`, `experimental_openApiLink`, `experimental_durableLink`), stay a row of the Links tables pointing at the page that covers them, rather than a page each.
- (agent) The v11 copy nests the same way, as trpc.io's sidebar does ([`old-docs-copy.md`](./old-docs-copy.md)).
- Why: one long Links page, or one TanStack Query page for eight packages, made each topic hard to find and link to; a tree keeps the sidebar short while every topic has its own URL, title and social card. Folded sections take the sidebar from about 2,250px of links to a list of headings.
- Lost: a flat sidebar where every page is one click away; a section can't hold a nested group without a parent page (no label-only folders); pages in other sections take a click to reveal.
- Lives in: `next/www/build/content.ts` (`Frontmatter.parent`, `readingOrder`, `llmsTxt`), `next/www/src/content/docs.ts` (`ancestors`, `childrenOf`), `next/www/src/components/docs-nav.tsx` (`NavSection`), `next/www/src/components/doc-page.tsx`, `parent:` in `next/www/docs/**/*.md`, `next/www/docs/client/links/`, `next/www/docs/integrations/tanstack-query/`, `next/www/docs/integrations/react.md`, `next/www/docs/migrations/from-v11/`.
