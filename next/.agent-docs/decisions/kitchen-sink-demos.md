# Kitchen-sink demos run tRPC in the page, beside the docs that explain them, in the `kitchen-sink` experiment (human asked)

- Human, 2026-10-19: "take https://github.com/trpc/examples-kitchen-sink and modernize it into some sort of more modern version of it for the website where you can have interactive demos and docs. raf-query has some cool stuff for interactive demos. i want it like that but better. effect has some cool demos with web containers to demo stuff too. you can start by just having an example with react-hook-form and good patterns of sharing input validators across / frontend backend and inferring errors. use tanstack-router. queries should follow the raf-query pattern of fetching in the loader, write our own hook if needed to make it nice. it should be under and experimental flag".
- Human, 2026-10-20: "I think the kitchen sink schema can be even better en leverage refine for the username thing. Also remember we can do transforms if one enables raw true on rhf".
- (agent) A demo is a docs page with a ` ```demo ` fence naming it (`www/src/kitchen-sink/demos.ts`): beside the page's text at `xl`, in its place below that, it shows the demo's files in an editor (CodeMirror), the running app in a pretend browser, and the requests between them. Editing a file rebuilds the app at once; a syntax error shows its file and line. The pages are in the Kitchen sink section and the `kitchen-sink` experiment (`www/src/experiments.ts`, [`docs-experiments.md`](./docs-experiments.md)).
- (agent) tRPC runs in the page, not in a WebContainer: the demo's `httpLink` posts to `/trpc` through a pretend network (`network.ts`) that calls the real `createFetchHandler`, so the wire protocol, serialization and errors are tRPC's own. The files are compiled with Sucrase and linked by a small `require` (`modules.ts`) against the site's own copies of React, TanStack Router and Query, react-hook-form, zod and `@trpc12/*`. The network has switches for slow responses and a failed next request, so loading states and `NETWORK_ERROR` can be tried.
- (agent) Each demo is a sample app (`www/samples/kitchen-sink-<name>/`) that typechecks on its own with its own `Register`; the docs page's `sample` fences show its `#region`s, so the code on the page is the code that runs and is type-checked.
- (agent) The router runs on a memory history inside the site's router. Loaders fetch with `queryClient` through a small hook of the demo's (`loader-query.ts`: `prefetch()`, `ensure()`, `useLoaderQuery()`), the raf-query pattern; it stays in the demo until a second one wants it.
- (agent) The forms demo's schema is shared by the form and the procedure. `profileSchema(isTaken)` takes the username lookup: its `.refine()` is the same check on both sides, the browser asking `profile.isTaken` through the query cache and the server its database. A taken username is the input's `BAD_REQUEST` issue on `username`, so `matchError()` needs no extra code for it. The regex aborts first, so a malformed username isn't looked up.
- (agent) The schema transforms: usernames are trimmed and lowercased, and topics are typed as `"trpc, effect"` and stored as `['trpc', 'effect']`. The form resolver's `raw: true` makes the form submit what it holds, the schema's input, which is what `mutate()` takes. The docs page shows both types with Twoslash (`samples/kitchen-sink-forms/docs/types.ts`).
- Why: in-page tRPC loads instantly, needs no COOP/COEP headers or install step, shares the page's React and router, works offline and in every browser the site supports, and still runs the real server and wire protocol. A WebContainer would take seconds to boot and install on every visit, for a terminal and Node APIs the demos don't need. Injecting the lookup keeps one schema while only the server knows the data, and the refine's issue is already typed into the client's errors.
- Lost: a terminal, Node APIs and installing packages; type checking in the editor (types are checked at build time only); Tailwind classes the reader adds that the site doesn't already have; isolation, since the demo's code runs in the page's realm. The refine looks the username up on every parse, so the server asks its database once per call, and a valid form makes one `isTaken` request per new username.
- Open: a lazy TypeScript worker for errors and hovers in the editor; a sandboxed iframe if demo code is ever shared by URL; more demos from examples-kitchen-sink. Subscriptions, files and optimistic updates have shipped, as [Real-time](https://v12.trpc.io/v12/docs/kitchen-sink/realtime), [Files](https://v12.trpc.io/v12/docs/kitchen-sink/files) and [Optimistic updates](https://v12.trpc.io/v12/docs/kitchen-sink/optimistic).
