# The client is typed by inference, with link options on the call (human)

- Human, 2026-10-15 (Q16.2): "Yes, but they don't have to live under context, they can just be on the options". Links declare typed per-call options, and they sit directly on the call options: `query(input, { signal, dedupe: false })`. Built-in names (`signal`, `lastEventId`) are reserved; a link declaring one is a type error.
- (agent) Links still read them from `op.context`. Two layers keep a `context` bag: the untyped client (its options also carry `type`, `path` and `input`) and the TanStack option bags (`queryOptions({ input, context })`), where flat fields would collide with TanStack's own options.
- Human, 2026-10-15 (Q16.6): "A but they should also be inferrable and affect what's available". `links: [...]` stays an array, and what the links declare shapes the client's types.
- (agent) Links affect more than options: a link declares `{ errors: E }` (its own failures, e.g. a `TrpcError.Tagged` instance) and they join every call's typed union as `defined: true`, and `{ unsupported: 'subscription' }` removes `.subscribe()` (any procedure type works). `splitLink`/`switchLink` are unsupported only for what every branch is. Built-in links declare nothing: their failures (`NETWORK_ERROR`, …) are `BuiltinError`s, one member per built-in code ([closed-client-errors](./closed-client-errors.md)), so `defined` keeps meaning "declared somewhere in your types". The client types gained a fourth parameter (`TrpcClient<R, C, F, LinksTypes<links>>`), threaded through `EffectClient` and every TanStack context helper. Lost: typed data on built-in link errors.
- Human, 2026-10-15 (Q16.3): "Ship both". `safe(promise)` and `createSafeClient(client)`, whose calls return the same dual `[data, error]` / `{ data, error }` result.
- Human, 2026-10-15 (Q14.1): "A, we should also allow an Effect native api where we can handle all errors and interruptions etc". Subscriptions are `AsyncIterable` first. `createEffectClient` in `@trpc12/trpc/effect` returns an `Effect` per call and a `Stream` per subscription, with typed errors in the error channel; interrupting the fiber aborts the request.
- Human, 2026-10-15 (Q16.5): "Ideally not but might be needed as a lower level thing for each client wrapping like the react libs". `createUntypedClient` is not in `@trpc12/trpc/client`; it is in `@trpc12/trpc/extend` ([`entry-points.md`](./entry-points.md)).
- Human, 2026-10-15 (Q5.5): "Yes later. I don't like packaging the contract in the clients if we don't need to, stuff should be inferrable". Decoding outputs with schemas on the client is a later opt-in. By default clients ship no contract and get types from `routerType<AppRouter>()`. `experimental_openApiLink` is the exception: it needs each procedure's method and path at runtime.
- (agent) The opt-in is `experimental_validationLink({ contract })` ([`client-validation-link.md`](./client-validation-link.md)).
- Lost: v11's `context: Record<string, unknown>`; a single composed `link` (oRPC); callback-first subscriptions.
- (agent, CS-A) `query(input, opts)`, `mutate(…)`, and `subscribe(input, { signal, lastEventId })` returning an `AsyncIterable`.
- (agent, D-C) `createTrpcClient({ router: routerType<AppRouter>(), links })`. `router:` takes a contract or an `experimental_toContract()` value too. It's the only form: the explicit generic `createTrpcClient<AppRouter>({ links })` went with its overloads ([`links.md`](./links.md), Q17.3; [`router-type-from-values.md`](./router-type-from-values.md)). The carrier is `routerType<T>()`, not proposal 17's `type<T>()`, which [`validation.md`](./validation.md) bans.
- (agent) Outputs are typed as `Deserialized<Output>`: generators become `AsyncIterable`s and thenables `Promise`s at any depth; built-ins (`Date`, `Map`, `URL`, …) are left alone. Custom serializer types are mapped structurally, so methods stay but private fields are lost.
- First-release review, question 7: "`links: []` type-checks and fails at runtime: require a non-empty tuple. `routerType<any>()`, which a broken `AppRouter` import produces, gives an unusable client type: map it to the untyped client's type."
- Human, 2026-10-19 (first-release review, question 7): "sgtm".
- (agent) `links` is an `AtLeastOneLink<TRouter>` (exported from `@trpc12/trpc/client`): a tuple with a link at its start or its end, so `[...shared, httpLink({ url })]` passes and `[]` or an `AnyLink[]` variable fails with `Type '[]' is not assignable to type 'AtLeastOneLink<…>'. Source has 0 element(s) but target requires 1.` It is the `TLinks` constraint of `createTrpcClient`, `createEffectClient`, `TypedClientOptions`, the React and atom clients, and the type of `createUntypedClient`'s `links` and of each `splitLink`/`switchLink` branch. A check type intersected into the options, like `UnmetNeedCheck`, broke inference of the links themselves, so it's the constraint. The runtime is unchanged: an empty chain still fails each call with `CLIENT_ERROR` ("The last link must send the request").
- (agent) An `any` router (`routerType<any>()`, or a router value typed `any`) makes `createTrpcClient` return `TrpcUntypedClient`, the type `createUntypedClient` returns, instead of a union of path nodes where every access failed with TS4111. The first `client.post` is then `Property 'post' does not exist on type 'TrpcUntypedClient'`, which names the problem. The typed client's proxy now answers `request()` and `subscribe()` at its root through the untyped client, so the type is true at runtime; a procedure or router named `request` is still reached as `client.request.query()`. `createEffectClient` has no untyped twin, so an `any` router still gives it the old type.
- (agent) Measured with `pnpm bench shapes` (instantiations, deterministic, with the client): `links` 993,257 to 993,416 (+0.02%), `plain` 957,235 to 957,381 (+0.02%). `pnpm bench budget`: +34 B on the minimal client and +32 B on the full one, all of it the root `request()`/`subscribe()` branch ([`../notes/benchmarks.md#budgets`](../notes/benchmarks.md#budgets)).
- Why (question 7): an empty chain can't send anything, so it should fail where it's written, not on the first call. A broken `AppRouter` import should say the router type is missing, not fail every access with an index-signature error.
- Lost (question 7): a chain in a variable typed as an array (`const links: AnyLink[] = …`) no longer passes; write it `as const` or type it as a tuple. A function that passes a chain through constrains it with `AtLeastOneLink` instead of `ReadonlyArray<AnyLink>`.
- Lives in: `packages/trpc/src/client/client.ts`, `types.ts` (`ChainTypes`, `LinksTypes`), `link.ts` (`LinkDecl`, `AtLeastOneLink`), `links/basic.ts` (`BranchesDecl`, `Chain`), `src/effect/index.ts`, `src/internal/types.ts`; tests in `packages/trpc/src/client/links/typed-links.test.ts`, `packages/tanstack-react-query/src/index.test.tsx`; docs in `www/docs/client/overview.md` ("Call options", and an `any` router) and `www/docs/client/links.md` (at least one link).
