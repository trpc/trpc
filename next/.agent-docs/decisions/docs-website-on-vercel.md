- Human, 2026-10-18: "pull and set the vercel deployment up at next.trpc.io or v12.trpc.io", then "it should only deploy on the v12 branch".
- (agent) It's raf-query's setup. `www/vercel.json` has the install, build and ignore commands. `pnpm build` ends with `build/vercel-output.ts`, which writes the prerendered site to `.vercel/output` as Build Output v3, with routes that `vercel.json` can't express: a page's URL answers `Accept: text/markdown` with its `.md` twin, `/v12/docs/client/links/index.html` is served at `/v12/docs/client/links`, trailing slashes and `.html` redirect (308), `/v12/docs` redirects (307) to the first page `llms.txt` lists, each copied version's root (`/docs`, `/v10/docs`, `/v9/docs`) to its first page, and the v11 copy's old address `/v11/docs/*` to `/docs/*` (308). Vercel deploys that directory as is.
- (agent) "Only on v12": `vercel.json` sets `git.deploymentEnabled` to `{ "**": false, "v12": true, "v12-*": true }`. A branch matching several rules deploys if any is `true` (minimatch globs), so `v12` deploys to production, a `v12-<name>` branch and its pull request get a preview, and no other branch does. That only applies to commits that have the file, and `main` is the v11 tree, with no `next/www`. Today's `main` is skipped by project settings: "skip unaffected projects" skips a commit that changes nothing under the root directory, which no `main` commit can.
- (agent) "v12 is the main branch": production deploys from `v12`. The ignore step (`tooling/vercel-ignore`) diffs a deployment against its previous one (`VERCEL_GIT_PREVIOUS_SHA`), or, on a branch's first deployment, against where it left `v12` (fetched from `trpc/trpc`). It builds when `www`, a workspace package it depends on (through `workspace:`, transitively), `docs/` or a workspace install input changed, and on `v12`'s first deployment. Any failure, such as a previous commit missing from Vercel's shallow clone, builds. The workspace is `next/`, not the git root, so paths are relative to the nearest `pnpm-workspace.yaml`.
- (agent) The settings that live on the project, not in the repo, for whoever creates it: GitHub `trpc/trpc`; production branch `v12`; root directory `next/www`, with files outside it included; Node 24; `ENABLE_EXPERIMENTAL_COREPACK=1` in every environment, so `next/package.json`'s `packageManager` picks pnpm 12; "skip unaffected projects" on; no Vercel Authentication; the domain for `site.url` (`https://v12.trpc.io`).
- Why: the same setup as the human's other Vercel sites, so it deploys with nothing new to learn; and deployments only build when something the site renders changed.
- Lost: deploying anywhere else without a new output step (the routes are Vercel's); a `.vercel/output` copy of the site on every local `pnpm build`.
- (agent) The project is `trpc-v12` in the `trpc` team, created 2026-10-18 with those settings, plus preview deployments turned off, and `v12.trpc.io` as its domain.
- (human) Human, 2026-10-19 (via the coordinator): "make preview links work 🙏... maybe we can have as a rule to prefix all v12 branches with `v12/` and have that as the rule for the vercel thing?" So every branch cut from `v12` is named `v12-<name>` (`AGENTS.md`, `next/AGENTS.md`), `v12-*` deploys previews, and other branches stay skipped. - (agent) The prefix is `v12-`, not `v12/`: git can't hold `refs/heads/v12/<name>` beside the `v12` branch, since a ref is a file and `v12/<name>` needs `v12` to be a directory (GitHub rejects the push with "directory file conflict", and so would a rename). Human, 2026-10-19 (via the coordinator): "ok figure out something else for the branch prefixes, i trust you". `v12-*` is a minimatch glob whose `*` stops at `/`, so `v12-bundle-cut-4` deploys a preview and a `v12-a/b` branch doesn't.
- (agent, 2026-10-19) The output also has one function, `_ssr`, the server build, which renders the URLs whose query turns on flags; everything else is still a file ([`docs-flags-on-demand.md`](./docs-flags-on-demand.md)).
- (agent, 2026-10-19) The build command gives Node a 4 GB heap (`NODE_OPTIONS=--max-old-space-size=4096`). Node sizes its default heap from the machine's memory, about 2 GB on Vercel's 8 GB standard build machine against about 4 GB on a 16 GB GitHub runner. A build that compiles most Twoslash blocks (an empty or stale `node_modules/.cache/twoslash`) keeps their TypeScript programs until the prerender, which runs in the same process, so with 2 GB it died with "JavaScript heap out of memory" (reproduced locally). With 4 GB it passes with a peak of about 6.1 GB of resident memory, and a build from a warm cache needs much less. That's the likeliest cause of the production deployments that failed from 2026-10-18 20:05, when the v11 docs' blocks started compiling, while the `www` job passed on the same commits (no one has read their Vercel logs from here). From 2026-10-19 21:16 every one failed: Vercel only saves its build cache when a build succeeds, so each failure left the next build with a staler Twoslash cache.
