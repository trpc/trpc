# At trpc.io, v12 is hidden until it's released, and the copies are the originals (human asked)

- Human, 2026-10-20: "Would we be ready to switch over to trpc.io for the v12 branch? If so, could we make it so v12 remains hidden and unindexed unless actually visiting those routes directly?"
- (agent) One switch: `site.url` in `www/src/site.ts`. Set to `https://trpc.io`, the build is the site trpc.io is (`atTrpcIo`), and v12 is hidden (`v12.hidden`). v12.trpc.io keeps offering v12, as the preview it is: hiding it there too would hide the only place to read it before the cutover. Unhiding v12 at trpc.io once it's released is `hidden: false`.
- (agent) Hidden is what [`hidden-decisions-pages.md`](./hidden-decisions-pages.md) made `/v12/decisions`, for `/v12/docs` too (`hiddenPaths`): `noindex, nofollow` in each page's meta and on every response under the path (pages, markdown, `llms.txt`), `Disallow:` in `robots.txt`, out of the sitemap, and no page outside the hidden paths links there (until the session has been to v12, below: the home page shows only v11, with no version pill or v12 panel; the version switcher lists v12 only on v12's pages; v11's pages have no banner, as trpc.io's have none; the footer doesn't call v12 a preview). The hidden pages have no canonical link. v12's `llms.txt` moves under its docs, `/v12/docs/llms.txt`, and v11's takes `/llms.txt`, as on trpc.io; its markdown keeps no canonical `Link` header. The search dialog searches the version the reader is on, so v11's pages never find v12's. `build/hidden-paths.ts` fails the build on a page outside them that links there (`href` or a meta tag's `content`), a text file that lists them, a page there that isn't `noindex, nofollow`, a route that doesn't answer them with the header, or `robots.txt` not disallowing them; `robots.txt` is written from `hiddenPaths` (`build/site-files.ts`), not kept in `public/`.
- Human, 2026-10-20: on trpc.io, everything v12-ish stays hidden unless the visitor lands on a `/v12/...` route or a URL with `?version=12`; once they have, it's remembered in `sessionStorage` and v12's UI shows for the rest of the session. Hidden by default in the HTML, revealed client-side without layout shift or hydration mismatch, and crawlers never see v12 links.
- (agent) The HTML at trpc.io has all of v12's UI (the home page's v12 panels, its version bar, the experiments menu, the header's v12 links, the v11 page banner, the footer's preview line), but none of it links anywhere: its links render disabled (`<a aria-disabled="true">` with no `href`), and the UI that isn't in a home panel has `data-v12-ui`, which `styles.css` hides while `<html>` lacks `data-v12`. The home page's inline script (`homeVersionScript`, before paint) sets `data-v12` when the URL is `/v12` or under it, or has `?version=12` (or `v12`), or the session has `trpc-docs:v12` in `sessionStorage`, and stores the key; it then picks the panel as on v12.trpc.io. React reads the reveal through `useV12Shown` (`useSyncExternalStore`, whose server snapshot is the HTML's, so hydration matches) and enables the links after hydrating; a client-side navigation into `/v12` reveals too. The room the version bar takes above the home page's code (`data-v12-room`) collapses while hidden, so nothing moves on reveal except the bar appearing. `hidden-paths.ts` still finds no `href` into the hidden paths, so its guard holds. v12.trpc.io's `<html>` has `data-v12` from the server.
- Human, 2026-10-20: all v12 content stays noindex everywhere (trpc.io `/v12/*` and v12.trpc.io) until the first npm release of v12, as one explicit, named switch with a guard test.
- (agent) `v12Indexable` in `www/src/site.ts`, `false`, flipped at v12's first npm release. While it's false, `unindexedPaths` is `['/v12']`: every response under `/v12` on every host has `X-Robots-Tag: noindex` (a route with no host condition), v12's pages have `noindex` in their meta, and the sitemap leaves them out; `/v12/decisions` and, at trpc.io, `/v12/docs` stay hidden as well. `build/hidden-paths.ts` (`unindexedPathProblems`) fails the build on a route that doesn't answer a path under it with `noindex`, a page there without `noindex` meta, or a sitemap that lists one. `src/site.test.ts` fails while `v12Indexable` is true and `packages/trpc` is still `private`, so the switch can't flip before the package can be published.
- (agent) Hidden isn't secret: `robots.txt` names the path, and a crawler that may not fetch a page never sees its `noindex`, so Google can still list a blocked URL it finds linked elsewhere, without a snippet. Nothing on trpc.io links there, so that takes a link from outside.
- (agent) At trpc.io, the copies of v11's, v10's and v9's docs and the blog are trpc.io's pages: their canonical links, social cards and breadcrumbs (now on the copies too) point at the site's own URLs, they're in the sitemap, "(v11)" leaves v11's titles, and the "Read this on trpc.io" links go. A copy's first page keeps its own path (`/docs/introduction`): trpc.io's `/docs`, `/docs/v10` and `/docs/v9` redirect there with a 308, the permanent redirect that hands search engines the URL's standing.
- (agent) What trpc.io serves that the site had no copy of is served here: `/media` (a page with the logos), `/search?q=` (the v11 docs' results, rendered on request, `build/on-demand.ts`), `/opensearch.xml`, `/llms-v10.txt`, `/llms-v9.txt` and their `-full`, and `static/img` and `static/logos` as they are (`old-docs:copy` copies them to `public/img` and `public/logos`, for the READMEs and sites that embed them). `/index.html` and a page's `/index.html` redirect to the page.
- (agent) Not served here: v11's API reference at `/docs/typedoc/*`, which trpc.io's own build generates. Those URLs redirect to trpc.io's own site, `oldSite.url` in `www/src/site.ts`: trpc.io until the cutover, then the `www` Vercel project's production URL, `https://www-trpc.vercel.app`, which Vercel answers with `noindex`, so the API reference leaves search results unless that project gets a domain of its own (`v11.trpc.io`) and `oldSite.url` names it. The build fails when `oldSite.url` is the site itself.
- Why: one edit flips the site, the indexing and the hiding together, and the build checks each, so the cutover can't leave v12 indexed at trpc.io or v11's pages pointing elsewhere.
- Lost: at trpc.io, a version pill and v12 panel on the home page for a session that hasn't been to v12; the HTML's v12 UI without links, for clients that don't run JavaScript; search results for v12 until its npm release, on every host.
- Open: the cutover itself, the human's call: moving the domains from the `www` Vercel project to `trpc-v12`, where `oldSite.url` points then, and syncing the copies with `main` first.
