# Each package has its own version; a bump releases every package that depends on it (human)

- Human, 2026-10-18: "i'd like it to be independent versioning but like if you do bump a package another package depends on, it should also bump". Replaces the agent's call in [`npm-names.md`](./npm-names.md) that the preview packages share one version and release together.
- Each `@trpc12/*` package in `packages/` has its own `version`. A release bumps the packages a changeset names, plus every package that depends on one of them through `dependencies` or `peerDependencies`, transitively. Bumping `@trpc12/trpc` releases the eleven packages that use it; bumping `@trpc12/tanstack-query` releases the seven adapters; `@trpc12/upgrade` depends on neither.
- (agent) The tool is Changesets (`@changesets/cli` 3) in `next/.changeset/`: no `fixed` or `linked` groups, and `updateInternalDependents: "always"` so a dependent bumps even when the new version still satisfies its range. With `workspace:*` every bump is out of range anyway (pnpm publishes it as the exact version); the option keeps the rule if a range becomes `workspace:^`. Changesets 3 gives a peer dependent a patch like any other dependent; 2.x gave it a major, which on `0.x` would have published `1.0.0`.
- (agent) A dependent gets a patch. A breaking bump (a minor on `0.x`) breaks each dependent too, since the dependent pins the exact version, so the changeset names each dependent with the same bump. `tooling/release/release.test.ts` fails on pending changesets that don't, and on any `major`: there's no preview `1.0.0` ([`npm-names.md`](./npm-names.md)).
- (agent) `privatePackages: { version: true, tag: false }` versions the packages while they're still `"private": true`; `changeset publish` skips private packages, so `private` stays the switch that turns publishing on. Examples, suites and tooling have no `version`, so they are never released; `@trpc12/www` is in `ignore`.
- (agent) No changesets before the first release: it publishes each package's `0.1.0` as it stands, and a changeset now would turn that into `0.1.1` or `0.2.0`. After it, a user-facing change comes with `pnpm changeset`.
- (agent) Changelogs are each package's `CHANGELOG.md`, from the default generator (no GitHub token). No git tags: `tag: false`, and `changeset publish --no-git-tag` once packages are public ([`no-git-tags-in-preview.md`](./no-git-tags-in-preview.md)). `format: false`, since detection would find the repo root's v11 Prettier config; `pnpm fix` formats what `changeset version` writes.
- Why: a fix in one package doesn't republish the other twelve, and each version says when that package changed. Bumping dependents keeps each one's exact pin on a version that is the latest, so the newest release of every package installs together.
- Lost: one version number for the whole preview ("tRPC 0.3"): users match versions per package. A core release republishes eleven packages whose changelog only says "Updated dependencies".
- Open: publishing. Every package is still `"private": true`, there's no release workflow, and no npm token or trusted publisher for `@trpc12` (only the human can set those up). The workflow would build, run `changeset version`, and publish with `changeset publish --no-git-tag`.
- Open: peers on `@trpc12/trpc` are `workspace:*`, which pnpm publishes as an exact peer (`"@trpc12/trpc": "0.1.0"`). Bumping dependents keeps the newest releases matching, but an app that updates only `@trpc12/trpc` gets a peer conflict until it updates its integrations. `workspace:^` would publish `^0.1.0`; ask before changing.
- Open: `packages/upgrade/src/bin.ts` hardcodes `--version` as `0.1.0`, which goes stale at the codemod's first bump.
- Lives in: `next/.changeset/config.json`, `next/package.json` (`@changesets/cli`), `next/tooling/release/`, `packages/*/package.json` (`version`, dependency ranges), `next/README.md` (Releases).
