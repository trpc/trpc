# Invalidation declared on mutations is later (human)

- Human, 2026-10-15 (issues review Q4, #5264, #3468, #6715): "B, but maybe this could be a link and/or plug in somehow? Idk. Seems like a later thing".
- Not in v1. Invalidation stays in app code (`queryClient.invalidateQueries(trpc.post.pathFilter())` in `onSuccess`).
- (agent) The shape's candidates were a link that reads paths the server sends back (for example in a response header) and invalidates them, or a TanStack plugin that reads `.meta()`. The spike below built the first.
- (agent) Lean on the shape, if it comes: a `.meta({ invalidates: [...paths] })` read on the server, sent back as a `trpc-invalidate` response header, and an `invalidationLink({ queryClient })` in `@trpc12/tanstack-query` that invalidates those path filters after the mutation settles. A link keeps servers framework-free and works for every TanStack adapter. Not built, per "Not in v1".
- Human, 2026-10-16 (decision round): "Spike some sort of plug in for this that you can use together with a special link or something (that requires you to pass in the query client to the link I'm guessing)". Still not v1; a spike of a server plugin plus an `invalidationLink({ queryClient })`.
- (agent) Spiked, 2026-10-16 ([`../notes/invalidation-plugin.md`](../notes/invalidation-plugin.md)): an `invalidation()` root extension (an `invalidates` meta key and a middleware that sends a `trpc-invalidate` header) and `invalidationLink({ queryClient })`, which awaits `invalidateQueries` before the mutation resolves. It works over HTTP; links can't read responses, so it needs a `fetch` wrapper and a ref header, and extension middleware can't see the parsed input. Still not v1.
- Human, 2026-10-16 (decision round, whether to ship the spike): "Can't the invalidation link somehow require that another link with specific stuff on context is added and then read those things from the link? If so http link could always contain more stuff like response headers that decorate the chain. Spike it further". Not shipped; spiked further.
  - (agent) Spiked, 2026-10-16 ([`../notes/invalidation-plugin.md`](../notes/invalidation-plugin.md), second round): links declare what they need and provide (`Capabilities`), `chain(...links)` checks that a provider sits after each need, and a provider reports each call's response to an `onResponse` callback in `op.context`. The ref header and `fetch` wrapper are gone.
- (agent) Skipped in the decision round, 2026-10-17 (the human: "Skip"); the agent shipped the core change and left `invalidation()` and `invalidationLink` as a spike. Why: reading a call's response from a link is useful on its own (versions, rate-limit headers), the chain check is how links already declare things, and invalidation itself stays "a later thing".
  - `onResponse` is a built-in call option. `httpLink` calls it with `{ status, headers }` for each response before the value goes up: a batched call gets its own line's status and the batch's headers, a resumed stream or reconnected subscription gets one per response, and an error it throws fails the call with `CLIENT_ERROR`. A link that sets it calls the one already in `op.context`, so the caller's own still runs.
  - `LinkDecl` gains `provides` and `needs`. `httpLink` declares `provides: 'response'`; `createTrpcClient` makes a `links` array a type error when a link needs what no link after it provides. `splitLink` and `switchLink` provide only what every branch does. Type-only: the untyped client doesn't check.
- Open: sockets need a provider too (a per-frame meta field in `wsLink`); per-call headers in a batch need per-line headers; needs inside a `splitLink` branch aren't checked; and extension middleware needs the parsed input, or the app places it after `.input()`.
- Lives in: `packages/trpc/src/client/link.ts` (`BuiltinCallOptions.onResponse`, `ResponseMeta`, `LinkDecl`), `src/client/types.ts` (`UnmetNeedCheck`), `src/client/links/http.ts`, `src/client/links/basic.ts` (`BranchesDecl`), `src/client/links/http.test.ts`, `www/docs/client/overview.md` ("Call options"); `invalidation()` and `invalidationLink` in `spikes/invalidation/` (spike only).
