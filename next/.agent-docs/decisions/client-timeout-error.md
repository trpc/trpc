# A call whose signal times out fails with `TIMEOUT`, not `CLIENT_CLOSED_REQUEST` (human)

- Human, 2026-10-20 (Q24.6): "B": a signal that aborts with a `TimeoutError` fails the call with `TIMEOUT`.
- (agent) No new option. A call given `{ signal: AbortSignal.timeout(ms) }` fails with `TIMEOUT` ("The request timed out") once it times out; any other abort (`controller.abort()`) stays `CLIENT_CLOSED_REQUEST` ("The request was aborted"). A signal joined with `AbortSignal.any()` fails with whichever aborted first. The signal's reason is the error's `cause`, for cancels too (they had none). It keys off the reason's `name`, `TimeoutError`, which is what `AbortSignal.timeout()` aborts with.
- (agent) One helper, `abortedError(reason)` in `internal/error.ts`, makes both errors, wherever an aborted call becomes its error:
  - `clientErrorFromCause(cause, signal)`: a Promise client call (and `createRouterClient`'s) interrupted by its signal, on any link. Its new `signal` parameter is optional.
  - `toHttpError` (`httpLink`) and `experimental_openApiLink`: a `fetch` that rejects with the signal's reason. That covers a custom `fetch` that times out with its own `AbortSignal.timeout()`, which was `NETWORK_ERROR`.
  - The Effect client races each query and mutation with its `signal` (`abortedBy`, `Effect.raceFirst`). Before, only the links that read `op.signal` stopped: a signal did nothing on a batched `httpLink` call or a socket link, and a timeout on an unbatched `httpLink` call was `NETWORK_ERROR`.
  - `call()` on the server, whose `signal` the caller passes.
- (agent) Types don't change. `TIMEOUT` was already in every call's union as a built-in error (the catch-all), on the Promise, Effect and safe clients and in the TanStack hooks' `error`. It stays out of `LinkErrorCode`, since a server's `408` sends it too ([link-errors](./link-errors.md)), so it goes to `matchError()`'s `unexpected` and needs no key; `Effect.catchTag('TIMEOUT')` takes it. No type changed, so the shapes bench wasn't rerun.
- (agent) Its status stays `408`, so `retryLink`'s and `experimental_durableLink`'s defaults (`serverFailure`: a 5xx or status 0) don't retry it.
- (agent) A subscription whose `signal` aborts still ends quietly, whatever the reason. The Effect client's `subscribe()` leaves its `signal` to the links, as before.
- Why: a handler that ignores cancels also swallowed timeouts, since both arrived as `CLIENT_CLOSED_REQUEST` with the same message and no `cause`. This is the smallest change that tells them apart, with the web-standard API people already use; Effect client users also have `Effect.timeout` around a call ([effect-native-by-default](./effect-native-by-default.md)).
- Lost:
  - A) Keep it as it is: a timeout is an abort like any other. Nothing to build, but a timeout and a cancel can't be told apart.
  - C) B plus a `timeout` call option and client default (a `Duration.Input`, run as `Effect.timeoutOrElse` around the whole link chain, so it covers retries). One setting would cover every link, and a client-wide default `AbortSignal.timeout()` can't give; but it's a second way to stop a call next to `signal`, and new public surface v11 doesn't have. Without it there is no client-wide default: a per-request one is an `httpLink` `fetch` that adds `AbortSignal.timeout()`.
- Open: C, if users ask for a client-wide timeout. The Effect client's `subscribe()` stopping with its `signal` on every link, as its queries now do.
- Lives in: `packages/trpc/src/internal/error.ts` (`abortedError`, `isAbortReason`), `src/client/link.ts` (`clientErrorFromCause`, `abortedBy`), `src/client/client.ts`, `src/client/links/http/transport.ts` (`toHttpError`), `src/openapi/link.ts`, `src/effect/index.ts`, `src/server/caller.ts` (`call`); tested in `src/client/links/timeout.test.ts` (every link, the Promise, Effect and safe clients, `matchError()`, `call()`) and `packages/tanstack-react-query/src/link-errors.test.tsx` (`useQuery`); documented in `www/docs/client/errors.md#timeouts-and-cancels`, `www/docs/client/effect.md` and `www/docs/integrations/tanstack-query.md#errors`.
