# The home page opens on the version the reader last browsed (human asked)

- Human, 2026-10-18: "make it so that the site remembers if you were last browsing the v12 docs or similar last time you went to it and forward to `?version=v12` directly. Local storage is fine".
- (agent) What's remembered is the home page's version ([`docs-v11-by-default.md`](./docs-v11-by-default.md)), in `localStorage` under `trpc-docs:version`, next to `trpc-docs:theme`. Browsing v12's docs (`/v12/docs/*`) or `/?version=v12` stores `v12`; v11's docs (`/docs/*`) or `/` showing v11, the v11 pill included, clears it on trpc.io, so switching back sticks; off trpc.io, where `/` opens on v12, v11 is stored and v12 clears it ([`docs-home-version-by-host.md`](./docs-home-version-by-host.md)). v10's and v9's docs and the blog leave it as it is: they have no home page version.
- (agent) Landing on `/` without `?version=` while `v12` is stored rewrites the URL to `/?version=v12` with `history.replaceState`, keeping the hash and adding no history entry. The rewrite happens in the blocking head script that already applies `?version=` (`homeVersionScript`), so it runs before the first paint and before the router reads the URL, the same as following a `/?version=v12` link. An explicit `?version=` wins and is what gets remembered. Blocked storage (private mode) opens on v11.
- Why: a reader trying v12 shouldn't have to pick it again on every visit, and a URL-only switch keeps the prerendered page and its links unchanged.
- Lost: forwarding the docs too. `/docs/*` stays v11's even with v12 remembered, because a docs URL names its version in the path and a shared or search-result link should land on the page it names.
- Open: what to remember once v12 is the default.
- Lives in: `next/www/src/home-version.ts` (`homeVersionAt`, `rememberHomeVersion`, `landingHomeVersion`), `next/www/src/content/docs.ts` (`useRememberHomeVersion`), `next/www/src/routes/__root.tsx`, `next/www/src/home-version.test.ts`.
