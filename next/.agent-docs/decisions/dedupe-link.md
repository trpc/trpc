# `dedupeLink` lets a call join an identical one that hasn't sent anything back yet (human asked)

- Human, 2026-10-18: "I just read the code that is on the branch now and it's horrid. We need to simplify it. It should be just be if a request matching hasn't gotten anything back yet, we should tee its stream". Earlier the same day: "if a request hasn't come back yet, just latch on to it - if it's a stream, tee it - if it's a subscription, tee it but consider last event id equality as part of the input". One rule for queries and subscriptions, each a `Stream` at the link: a call joins one in flight with the same key, a deeply equal input, equal call options and the same `lastEventId`, while that one hasn't sent a value. A joiner gets every value, the end and any error. Once a value arrives, a later call sends its own. Mutations and `dedupe: false` pass through.
  - (agent) Callers read the request through Effect's `Stream.share` (unbounded, no replay): it runs once while any caller reads it, every subscriber sees the end or error, and it stops after the last one leaves. A request with no caller left isn't joinable. The `signal` passed down the chain aborts only once every caller's signal has: a query's caller stops reading after its one value, and aborting then would cut a stream in the output that's still being read.
  - Human, 2026-10-18: "reimplementing effect internals seems dumb no matter the reason, so get rid of that, that's the wrong optimisation". The hand-made queue per caller and the interrupt bookkeeping went for `Stream.share`; a caller whose `onResponse` throws is failed through `Stream.interruptWhen`.
  - (agent) 2026-10-19: the joinable requests are an `RcMap` keyed by a `Key` class whose `Equal` compares the name, `lastEventId`, input and call options deeply (it hashes only the name), instead of a `Set` scanned with `find`. A caller holds its entry with `RcMap.get` in its stream's scope; the entry's scope holds the `Stream.share`, so the request stops when the last caller leaves, where each request had a `Scope.makeUnsafe()` that was never closed and an `Effect.runSync` to share it. The first value or the end invalidates the entry once (a flag, since `RcMap.invalidate` goes by key and would drop a newer equal request). The `Set` of callers stays, to tell each one's `onResponse`. +1,352 B gzipped on `dedupeLink` with `httpLink`; the budgeted clients don't include it.
  - (agent) 2026-10-19: the `signal` aggregation stays a raw `abort` listener (now `once`), not `Effect.callback`: the request's signal must still abort a streamed output after every caller's stream has ended, so no fiber or scope outlives it.
  - (agent) Each caller's `onResponse` is called. A joiner also gets the responses that came before it joined, since a response's headers arrive before its value. One that throws fails only that caller.
- Human, 2026-10-18: "I guess all it needs to do is to keep track of the inputs and do a deep equal check like above? It doesn't need to sort". Inputs compare deeply, in any key order. They aren't serialized, so a `File` or a type only `httpLink`'s serializer knows doesn't throw.
  - (agent) Only data compares by content: plain objects, arrays, `Map`s, `Set`s, `Date`s, `URL`s, `URLSearchParams`, `Headers`, `RegExp`s, typed arrays. Anything else equals only itself, and a missing key differs from `undefined`. A wrong "no" costs a request, a wrong "yes" hands a caller another call's result.
  - (agent) The link keeps a reference to the first caller's input, not a copy: changing an input while its call is in flight isn't supported (with batching, `httpLink` serializes it later anyway).
- Human, 2026-10-18 ("2 seems good"): calls must also have equal call options. `headers` and `init.headers` compare as `Headers`; `dedupe` and `onResponse` are left out.
- Human, 2026-10-18: "Fresh requests for streamed queries if it has started seems good, but if it hasn't we can tee it?". Replaced by the rule above: the link no longer looks inside a value, so it neither copies a stream in a query's output per reader nor sends the query again for a late reader.
- Why: one rule replaces separate query and subscription paths, a walk through every result to copy its streams, and late readers sending their query again (620 lines, now about 200). The serialized key before that missed equal inputs in another key order and threw on inputs the serializer can't write. Ignoring call options gave a caller a response sent with another caller's headers. Subscriptions that start together, such as components mounting at once, share one connection.
- Lost: a stream (`AsyncIterable`, `ReadableStream`) in a query's output is one value for every caller, so callers that read it split its items; callers that each read it pass `dedupe: false`.
- Lost: `key(op)` replaces only the input comparison; call options and `lastEventId` are compared under it too. A subscription that must have its own connection needs `dedupe: false`.
- Open: letting a call join after the first value when it would miss nothing (an output without streams, a subscription that sends no snapshot), which the link can't tell today.
- Open: copying a stream in a query's output per caller, if `dedupe: false` turns out to be easy to forget.
