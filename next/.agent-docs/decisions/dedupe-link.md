# `dedupeLink` compares inputs deeply and copies streams to their readers (human asked)

- Human, 2026-10-18: "I guess all it needs to do is to keep track of the inputs and do a deep equal check like above? It doesn't need to sort". Calls share a request when the path matches and the inputs are deeply equal, in any key order. The input isn't serialized any more, so a `File` or a type only `httpLink`'s serializer knows no longer throws.
  - (agent) Only data compares by content: plain objects, arrays, `Map`s, `Set`s, `Date`s, `URL`s, `URLSearchParams`, `Headers`, `RegExp`s, typed arrays. Anything else equals only itself, and a missing key differs from `undefined`. A wrong "no" costs a request, a wrong "yes" hands a caller another call's result.
  - (agent) The link keeps a reference to the first caller's input, not a copy: changing an input while its call is in flight isn't supported (with batching, `httpLink` serializes it later anyway).
- Human, 2026-10-18 ("2 seems good"): calls must also have equal call options. `headers` and `init.headers` compare as `Headers`; `dedupe` and `onResponse` are left out. Each caller's `onResponse` is called, including for responses that came before it joined, and one that throws fails only that caller.
- Human, 2026-10-18: "Fresh requests for streamed queries if it has started seems good, but if it hasn't we can tee it?". An `AsyncIterable` or `ReadableStream` in a shared result is read once and copied to every caller that starts reading before an item has been read. A caller that starts later, or after every reader stopped, sends its query again and reads that response's stream.
  - (agent) Items are buffered per reader until it reads them; a caller that never reads costs nothing. When the last reader stops, the source is closed. Once every caller holding the result has aborted, the shared request is aborted, so an unread stream doesn't keep it open.
  - (agent) Promises in the result stay shared. Streams are found in plain objects and arrays, not in `Map`s, `Set`s or inside a stream's items.
- **Why:** the serialized key missed equal inputs in another key order and threw on inputs the default serializer can't write; ignoring call options gave a caller a response sent with another caller's headers; a shared stream split its items between readers and could hang.
- **Lost:** `key(op)` used to replace the whole comparison; call options are now compared under it too. A late reader's stream comes from a second run of the query.
- **Open:** sharing subscriptions the same way (join while nothing has been emitted). Human, 2026-10-18: "For subscriptions same thing could apply maybe?". Not built: it saves little on `wsLink`, and resuming with `lastEventId` and per-call `reconnect` need rules of their own.
