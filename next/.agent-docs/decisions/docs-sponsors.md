# The site shows trpc.io's sponsors, and its biggest as partners (human asked)

- Human, 2026-10-18: "Port the sponsors section and cloud from old www but feel free to rebuild both to make it nicer".
- Human, 2026-10-18: "add things like tanstack query has for more "punchy" big sponsors and put our biggest sponsors in that. Make it unobtrusive but front them well. Feel free to pull/create new assets. On that put it behind some sort of feature flag that we can enable with a dev menu in preview and dev mode. On prod, have a "secret" query param or something to toggle those things".
- Human, 2026-10-18: "Make sure to port the sponsors sync script too (I know you can't test it) but you can make tests. Feel free to make that script better too freely".
- (agent) `next/www` owns the list: `pnpm --filter @trpc12/www sponsors:sync` (`www/build/sponsors-sync.ts`, with `TRPC_GITHUB_TOKEN`, KATT's) reads KATT's and the trpc organization's sponsorships from GitHub's GraphQL API and writes `www/sponsors.json` and the sponsors section of the repo's `README.md`; `sponsors:readme` rewrites the README from `sponsors.json` without GitHub. It replaces the v11 site's `script.pull.ts` and `script.push.ts` on this branch, and `old-docs:copy` no longer copies their output.
- (agent) A sponsor's weight is what GitHub says they've paid the two accounts in all (`lifetimeReceivedSponsorshipValues`), as a share of whoever paid the most (1 to 100), instead of the old guess (current tier × months since they started, a hand-kept list of yearly sponsors, minus 10% for organizations). A new sponsor GitHub hasn't charged yet counts their monthly tier. Sponsoring both accounts makes one sponsor, not two bubbles. Direct sponsors (SerpApi, invoiced yearly) and money GitHub can't attribute (Greptile's three months from a private account) are `sponsorsConfig` in the script.
- (agent) The README's tiers are the site's: the partners (`partnerLogins` in `www/src/sponsors.ts`) in big avatars, then everyone else as backers, each by weight, avatars fetched at twice their size. Names and links are HTML-escaped (the old script `encodeURI`'d names, so alt texts read `Dr.%20B`).
- (agent) The sync decodes every response, follows every page, skips deleted sponsors, and writes nothing when the token can't see tiers, sponsors or payments, saying whose token it needs, so a wrong token can't empty the site. The fetch goes through Effect's `HttpClient`, so the tests run it against a fake GitHub (`www/build/fake-github.ts`); the queries were checked against GitHub's live schema with a token that isn't KATT's, which can't read tiers or payments.
- (agent) `main`'s sync still writes the README's sponsors there. After a merge of `main` that changes `README.md`, the `post-merge` hook runs `sponsors:readme`, so the section is this branch's again.
- (agent) The home page has trpc.io's two placements, rebuilt: "Supported by" under the hero (the five who gave the most, then "+N more" to `/#sponsors`) and a Sponsors section at the end, with the cloud and a "Become a sponsor" button (GitHub Sponsors).
- Human, 2026-10-18: "btw sponsors should link to https://github.com/sponsors/trpc".
- (agent) "Become a sponsor" (`sponsorUrl` in `www/src/sponsors.ts`) goes to the trpc organization's GitHub Sponsors page, not KATT's; the sync still counts sponsorships of both. The cloud is the same circle packing (`d3-hierarchy`, area by weight), computed once and drawn in percentages, so it's prerendered and crawlable without measuring the page; the bubbles pop in when it scrolls into view (not with reduced motion), and each has a tooltip with the name and since when. The footer links `/#sponsors`.
- (agent) Partners, like TanStack's: trpc.io's tiered sponsors (Greptile, CodeRabbit, SerpApi; `partnerDetails` in `www/src/sponsors.ts`) get their wordmarks (from their sites, drawn in the text color so they work in both themes) instead of avatars under the hero, cards with a line each at the top of the Sponsors section, a "Partners" column under "On this page" beside every docs page, and a strip at the end of the page where that column doesn't fit. A partner who stops sponsoring drops out with the next sync.
- Human, 2026-10-18: "When having flags active on prod let's have that dev menu allow you to disable them".
- Human, 2026-10-18: "Ok I actually want that thing available in all environments and that you retain the flags in the url rather than local storage as you're navigating."
- (agent) The URL is the only place flags live: `?flags=<name>` turns the flag on (comma-separated for several; unknown names are dropped), and a URL without it has every flag off. The root route's `retainSearchParams(['flags'])` keeps the param on every router navigation (header, sidebar, doc links, search, footer), and in-page `#` links keep the query string anyway, so the flags stay on while browsing and a copied link shares them. Nothing is stored in the browser.
- Human, 2026-10-18: "maybe the flags experiment thing should be in the top bar alongside other stuff? it can show as experiments".
- (agent) An "Experiments" button in the site header, between search and GitHub, in every environment (production included), opens the menu: every flag with a switch, and "Turn all off". Below `lg` it's the flask icon alone. A switch rewrites `?flags=` in place (`replace`, no scroll), and the button shows how many flags are on; a badge names the environment (`VERCEL_ENV`, defined at build time). The button is prerendered; the count and the flagged content appear after hydration, since the prerendered page has no query string.
- Human, 2026-10-18: "experiments shouldn't be visible in the top bar when looking at v11 either btw".
- (agent) The button shows with v12 only: on the v12 docs and on the home page while it shows v12 (`[data-home-panel]`, like the header's links). On v11's, v10's and v9's pages, the blog and the home page's v11 view it's gone; `?flags=` still carries over, so switching to v12 brings it back.
- Human, 2026-10-18: "let's make the partner placements a core thing, so remove that feature flag". The partners show for everyone and are in the prerendered HTML; the `partners` flag is gone, and the flags are now the docs' experiments ([`docs-experiments.md`](./docs-experiments.md)).
- Why: the sponsors keep the visibility they have on trpc.io; the sync lives with the site that shows the list, so it outlives the v11 site; weighing by what was paid is what GitHub knows rather than a guess that needs overrides; keeping flags in the URL makes a flagged view a link to share rather than a browser's hidden state.
- Lost: one sync for both branches (until `v12` replaces `main`, `main`'s script and this one each keep their own list, synced separately); weights comparable to the old ones (long-time sponsors weigh more, organizations no longer weigh 10% less); flags that survive a link without `?flags=` (an external link, a typed URL, or the footer's `/llms.txt` turn them off); a production page with no developer UI on it (the header's Experiments button shows to every visitor).
- Open: running `sponsors:sync` with KATT's token, the first run against the real data (the tests and the live schema check can't see tiers or payments); running it on a schedule in CI with the token as a secret; partner tiers beyond the three; sponsors' own logo assets if they want something else shown.
