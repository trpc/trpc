# One trace across client and server, through Effect's tracer (agent)

- Follows [`effect-integration.md`](./effect-integration.md) (server spans) and [`effect-native-by-default.md`](./effect-native-by-default.md): tracing is Effect's `Tracer`, exported by `@effect/opentelemetry` or any `Tracer` layer, not a @trpc12/trpc plugin.
- (agent) Client spans: every call runs in `Stream.withSpan('trpc.<path>', { kind: 'client' })` with `rpc.system: 'trpc'`, `rpc.method` and `trpc.type`, and annotates `trpc.error.code` on failure. Spans opened by links nest under it.
- (agent) Propagation: when a non-native tracer is installed and `Tracer.DisablePropagation` is off, the operation carries `op.trace` (`traceparent` and `b3` from `HttpTraceContext.toHeaders`) and `httpLink` sends them as headers on the first operation of a request. With Effect's native tracer nothing is sent, so plain clients never add headers that would turn a simple request into a CORS preflight.
- (agent) Promise clients run on the native tracer, so they don't propagate (and, since the opt-in answer below, open no spans). Exporting needs the Effect client (`@trpc12/trpc/effect`) run with a tracer layer, or an Effect program that provides one.
- (agent) Server: calls are parented to the request's `http.server` span (Effect's `HttpEffect` creates it from `traceparent`), or, on a bare `handler.fetch`, to the incoming `traceparent`/`b3` header. Calls run in the handler's runtime, so the parent is passed explicitly (`RunOpts.parent`).
- (agent) WebSocket calls aren't parented: one connection carries many calls and there is no per-message header. Later: a `trace` field on WS messages if someone needs it.
- (agent) That `trace` field is built ([`socket-trace-field.md`](./socket-trace-field.md)).
- (human) Observability is opt-in: "I just care that good observability is opt in and possible. If it has cost for requests, don't do it by default but make it opt in." So client and server open their `trpc.<path>` spans only when a tracer other than Effect's native one is installed; installing it is the opt-in. The server span was the largest single per-request cost (about 1.2 µs, [`../notes/benchmarks.md`](../notes/benchmarks.md)). With a tracer, middlewares and the resolver run inside it.
  - (agent) So the Promise client runs its links with `runLinks`, without `runOperation`'s tracer check and span, which shakes out of its bundle (1.7 kB gzipped); the Effect client keeps `runOperation`.
- Lost: `Effect.currentSpan` in a resolver is the request's span, not `trpc.<path>`, under the native tracer.
- Why: one trace from browser to resolver with Effect's own APIs; the only @trpc12/trpc code is span naming and header plumbing.
- Lost: always-on propagation like Effect's `HttpClient` default, and tracing on the Promise client without Effect.
- Lives in: `packages/trpc/src/client/link.ts` (`runOperation`), `src/client/links/http.ts`, `src/server/core.ts`, `src/server/fetch.ts` (`parentSpan`), `src/server/socket.ts` (`traceParent`), `src/client/links/socket.ts`, `packages/trpc/src/server/tracing.test.ts`, `docs/server/effect.md` (Tracing), `docs/client/tracing.md`.
