# One builder for Promise and Effect code; services are inferred (human)

- Q2.1: A1. One builder detects `Effect`, `Stream`, `AsyncIterable` and `Promise` returns at runtime.
- Q2.2: S1, inferred services, against proposal 02's S2. With plain-object routers ([`routers.md`](./routers.md)) nothing carries a declared set, so S2 would need the handler to be given `t`. Under S1 the router type carries `R`, and the handler's `layer` must provide `inferRouterServices<typeof router>`.
- Q2.3: d.ii. A resolver whose `Effect` or `Stream` can fail with something other than a `TrpcError` is a compile error ("Map Effect failures to a TrpcError (e.g. Effect.catchTag) before returning them"); the same goes for Effect middleware bodies and `.provide()` factories. At runtime d.i stays as a safety net: an unmapped failure becomes a masked `INTERNAL_SERVER_ERROR`.
- `t.call(procedure, input, { ctx, layer })` takes a `layer`; `createRouterClient(router, { ctx, runtime })` and `localLink({ runtime })` take a caller-owned `ManagedRuntime` ([`router-client-runtime.md`](./router-client-runtime.md)).
- (agent, 02 (e)) Tracing: `callProcedure` runs every call in `Effect.withSpan('trpc.<path>', { kind: 'server' })` with `rpc.system: 'trpc'`, `rpc.method` and `trpc.type`, and annotates `trpc.error.code` on failure. A tracer in the handler's `layer` exports them. Superseded in part: with no tracer (Effect's native one) calls open no span ([`tracing-across-client-and-server.md`](./tracing-across-client-and-server.md)). Client spans and `traceparent` propagation: [`tracing-across-client-and-server.md`](./tracing-across-client-and-server.md).
- (agent) Effect code in a query or mutation gets a `Scope`, as `effect/rpc` handlers do (`RpcServer` runs each request in its own and `RpcGroup` leaves `Scope` out of a handler's requirements): an Effect resolver, `.provide()` factory or Effect middleware that needs one has it closed when its step ends, so `Effect.acquireRelease` works with no `Effect.scoped`, and `Scope` isn't a service the `layer` must provide. Before, the handler asked for a `Layer<Scope>`, and a call failed with "Service not found: effect/Scope" over HTTP but not in-process. Only Effect steps pay (`Effect.scoped`, about 0.1 µs); a subscription gets none, since its scope would have to outlive the call, so there `Scope` stays a requirement. +2 instantiations per procedure ([`type-check-shapes.md`](../notes/type-check-shapes.md)).
- Lost: S2 (a declared service set on `t`); d.i alone (failures silently masked).

- (agent) Effect's own APIs check failures the same way, against a declared error schema where tRPC has one error class. In `effect/rpc` (`@effect/rpc` in Effect 3), `Rpc.make(tag, { payload, success, error })` declares each Rpc's errors, and the handler must return `Effect<Success, Error, R>`: any other failure is a compile error, and defects travel as defects. `HttpApi` (`effect/http-api`) declares them per endpoint with `HttpApiEndpoint.get(name, path, { error })` (`.addError(schema, { status })` in Effect 3), plus its middleware's errors; a handler's type allows only those, and an undeclared failure dies when its error fails to encode. Rule 3 is that check with `TrpcError`, the wire error, as the one declared error, so a procedure needs no error schema; mapping (`Effect.catchTag`) is where a tagged failure gets its code, and the masked `INTERNAL_SERVER_ERROR` is the defect path.
