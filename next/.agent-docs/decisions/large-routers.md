# Large routers: clients read the server's declarations, and procedure types stay cheap to read (human asked)

- Human, 2026-10-18: "i would like you to explore how people with mega big routers can use trpc to get down typescript cechking time / it may impact api decisions / may be that people need to be multiple smaller clients in several packages but don't get too inspired by me".
- Measured with `spikes/big-routers/` (generated monorepos of 1000 and 5000 zod procedures over a fake ORM). Numbers in [`large-routers-typeperf.md`](../notes/large-routers-typeperf.md).
- (agent) The guidance is project references, not smaller clients. A client that reads the server's built `.d.ts` (`tsc -b`, `composite` server packages) costs the same whatever the router's size: with 5000 procedures, 43k instantiations and 0.07s against 4.1M and 6.5s from source. The client's mapped types resolve only the procedures a file calls, so `Pick<AppRouter, …>` or a client per domain gains nothing more once the server is read from declarations. They are worth it only when the server can't be built first (one `tsconfig` over everything), where a domain slice is 16× cheaper than the whole router.
- (agent) Contract-first domains (`@trpc12/trpc/contract`) give a client that never loads server code. Their cost is their schemas, so a contract package built to `.d.ts` too is as cheap as the server's.
- (agent) Name the root router's type from the domains' types (`type AppRouter = { posts: PostsRouter; … }`, then `const appRouter: AppRouter = { … }`). An inferred object literal inlines every domain's types into the api package's declarations, and past a few thousand procedures it fails with TS7056 ("exceeds the maximum length the compiler will serialize"). It must be a `type`, not an `interface`: an interface has no index signature, so it isn't an `AnyRouter`.
- (agent) API changes the measurements called for:
  - Every whole-router read (`inferRouterContext`, the errors and services unions, the client's decoration) reads a procedure's def by index (`P['~trpc']['~types']`) rather than inferring `Procedure<infer D>`, which checks `D` against `ProcedureDef` and so resolves every field of every procedure. A fetch handler over 1000 procedures read from `.d.ts`: 543k → 126k instantiations.
  - `.query()`, `.mutation()` and `.subscription()` return a spelled-out `Procedure<{ … }>` (no `BuildProcedure` alias). Declaration emit prints an alias with its arguments (the whole builder state and the zod schemas), so every package reading the declarations worked the procedure out again. Spelled out, it prints the resolved input and output.
  - `.input(schema)` adds `SchemaValidationError<schema>`, whose `issues` are `inferInputIssue<schema>` worked out when read ([`zod-and-effect-input-issues.md`](./zod-and-effect-input-issues.md)). With the flat terminals alone, declarations printed the expanded zod issue union for every procedure (3× the size). Together: a client from `.d.ts` 73k → 22k instantiations at 1000 procedures, the fetch handler 126k → 64k.
  - `tooling/pack` keeps `import type {} from '@trpc12/trpc/internal'` in the built entry declarations ([`type-portability.md`](./type-portability.md)); without it, a base procedure exported from its own package failed declaration emit with TS2883.
  - `@trpc12/trpc/contract` loads `@trpc12/trpc/server` the same way, so a contract package that imports nothing else emits declarations (TS2883 for `TrpcError` before; found building `examples/monorepo/`). `tooling/portability` compiles a contract-only fixture in its own program.
- Why: a client should cost what it calls, not what the server has; declarations are where that holds, so the procedure types have to print small and read cheap.
- Lost: one generic alias for the three terminals (each spells out its def). Source-mode checking is about unchanged (the builders' inference dominates it, 4.7M instantiations at 5000 procedures; `pnpm bench typecheck` 1,266,138 → 1,249,661).
- Open:
  - Editors resolve a project reference to its source by default, so the editor pays source cost even when `tsc -b` doesn't. `disableSourceOfProjectReferenceRedirect: true` in a client's `tsconfig` makes it read the `.d.ts` (exists in TypeScript 7), at the cost of go-to-definition landing in declarations and needing `tsc -b --watch`. Not measured in an editor.
  - `AnyRouter` could accept interfaces (no index signature), which would let the root router be an `interface`, which TypeScript caches by name.
  - `lazy()` routers print their resolved type in declarations; printing by reference would keep the api package's declarations smaller.
- Lives in: `packages/trpc/src/server/procedure.ts` (`ProcedureDefOf`), `src/server/router.ts` (`DefField`), `src/client/types.ts` (`DecorateProcedure`), `src/effect/index.ts`, `src/server/builder.ts` (terminals), `src/server/validation/schema.ts` (`SchemaValidationError`, `SchemaInputErrorData`), `src/contract/index.ts`, `tooling/pack/pack.ts`, `spikes/big-routers/`, `examples/monorepo/`.
