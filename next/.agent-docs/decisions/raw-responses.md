# Procedures may return an `HttpServerResponse` on unbatched HTTP calls (human)

- Human, 2026-10-15 (decisions round 3, Q11 = proposal 04 Q4.3): "Do c". Neither tRPC v11 nor oRPC lets a procedure return a response.
- A resolver may return Effect's `HttpServerResponse` (the core's response type, [`http-core-on-effect-http.md`](./http-core-on-effect-http.md)); a web `Response` is accepted and converted with `HttpServerResponse.fromWeb`. It is sent as is: status, headers, body (redirects, proxied upstreams, streams).
- (agent) Only unbatched HTTP calls carry it. In a batch, over WebSockets or MessagePorts, or in-process, the call fails with `BAD_REQUEST`. Clients get a web `Response` as the output (the type is `Response`), so a batching `httpLink` must send such procedures alone. The response carries `trpc-response: 1` so the link returns it instead of decoding it.
- (agent) OpenAPI routes send it as the route's response; the document describes it as an untyped response.
- Why: proxies, redirects and pre-built responses without leaving tRPC for a separate route.
- Lost: one transport-independent output type for every procedure.
- (agent) The client learns it from types, through a call option: `batch: false` (read by `httpLink`) sends a call alone, and `httpLink({ batch: batching() })` declares `{ batches: true }`, so on that chain a call to a procedure whose output may be a response (`Extract<Output, Response | HttpServerResponse>`) must pass `{ batch: false }`, a type error otherwise. No runtime contract, as `client.md` asks. `httpLink` uses overloads, not a generic, so it infers inside `switchLink`/`splitLink` options. Lost: automatic routing; a `batch` that may be `undefined` declares no batching.
- Lives in: `packages/trpc/src/server/execution/execute.ts` (`isResponseValue`, `allowResponse`), `src/server/handler/fetch.ts`, `src/client/links/http/` (overloads, `batch: false`), `src/client/types.ts` (`ProcedureCallArgs`), `src/internal/types.ts` (`ProcedureResponse`); tests in `packages/trpc/src/http/core.test.ts`; docs in `docs/server/responses.md`.
