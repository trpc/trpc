# The codemod playground runs `@trpc12/upgrade` in the browser, in an experiment (agent)

- (agent) `www/docs/migrations/from-v11/try-the-codemod.md` (Try the codemod, under Migrating from v11) has two CodeMirror panes: v11 code on the left, editable, and what `upgradeSource()` makes of it on the right, rewritten on each edit, with the `file:line:column` steps it leaves below. A step puts the cursor on its line. Four samples (server, client, React, adapter) start it, each keeping its own edits until "Reset code". It's in the `codemod-playground` experiment ([`docs-experiments.md`](./docs-experiments.md)).
- (agent) The parser is `oxc-parser`'s WebAssembly build (`@oxc-parser/binding-wasm32-wasip1`, its `browser` export), which needs no cross-origin isolation, so the site adds no COOP or COEP headers. The spike: its browser loader starts napi-rs' WASI runtime with `asyncWorkPoolSize: 0` and a non-shared `WebAssembly.Memory`, so there are no worker threads and no `SharedArrayBuffer`; headless Chrome loaded it and parsed in about 70 ms on a page where `crossOriginIsolated` is `false`. The precomputed before-and-after pairs, the fallback, weren't needed.
- (agent) Its own page rather than panes on `codemod.md`: an experiment hides whole pages, and a listed page can't link an experiment's ([`docs-experiments.md`](./docs-experiments.md)). The page links `codemod.md`; `codemod.md` gets a link back when the experiment goes.
- (agent) The parser loads only on that page: a `codemod-playground` fence becomes a slot, which a lazy chunk fills on the client (`import.meta.env.SSR` keeps it out of the prerender, as the server bundle inlines its dependencies). The chunk is about 71 kB gzipped and the `.wasm` about 490 kB.
- (agent) The binding is a direct dependency of `www`, deduplicated in `vite.config.ts`: as `oxc-parser`'s optional dependency it's marked `cpu: wasm32`, which pnpm skips on every machine it installs on.
- (agent) `www/codemod-playground-check.ts` (`pnpm --filter @trpc12/www codemod-playground:check`, in CI after the build) checks it in headless Chrome: no COOP or COEP and not cross-origin isolated, an edit rewrites the v12 pane, the tabs keep their edits, a step moves the cursor, it fits 360px and 1280px, and no console errors. `samples.test.ts` checks each sample is rewritten and leaves steps.
- (agent) The experiment documents no API, so it has no `experimental_` names; `tooling/pack/docs.test.ts` exempts it with the recipe experiments.
- Why: the migration guide says what the codemod does; the playground shows it on code the reader edits, with the steps it leaves, without installing anything.
- Lost: the playground on `codemod.md` itself; type-aware rewrites (the codemod is syntactic, so the page is too); a whole project's cross-file renames, as it runs one file at a time.
- Open: the human's review, then dropping `experiment: codemod-playground` and its entry in `www/src/experiments.ts`, and linking the page from `codemod.md`. Pasting several files at once.
- Lives in: `www/docs/migrations/from-v11/try-the-codemod.md`, `www/src/codemod-playground/` (`playground.tsx`, `slot.tsx`, `samples.ts`, `samples.test.ts`), `www/src/components/doc-page.tsx`, `www/build/markdown.ts` (`remarkCodemodPlayground`), `www/build/content.ts` (`pageMarkdown`), `www/src/styles.css` (`.codemod-playground-slot`), `www/src/experiments.ts`, `www/vite.config.ts`, `www/codemod-playground-check.ts`, `tooling/pack/docs.test.ts`.
