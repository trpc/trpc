# The benchmarks page charts a committed snapshot of `pnpm bench`, in an experiment until it's reviewed (agent)

- (agent) `www/docs/benchmarks.md` (Benchmarks and comparison, in Getting started) charts throughput, type-check time, instantiations and memory, and bundle sizes for tRPC v12, tRPC v11 and oRPC v2, the rows oRPC v2's comparison measures ([`../notes/benchmarks.md`](../notes/benchmarks.md)), and lists the feature rows of [`../reference/orpc-parity.md`](../reference/orpc-parity.md). It's in the `benchmarks` experiment ([`docs-experiments.md`](./docs-experiments.md)): `noindex`, out of the sitemap and the sidebar until the experiment is on.
- (agent) The experiment documents no API, so it has no `experimental_` names; `tooling/pack/docs.test.ts` exempts it with the recipe experiments.
- (agent) It waits for the human's review of how it presents oRPC before its `experiment` goes. Until then its prose says only what the numbers show, says oRPC v2 leads on every measured row, and gives the bundle gap in full rather than leaving it out.
- (agent) The numbers are a snapshot, `www/benchmarks.json`, written by `pnpm bench runtime|typecheck|bundle --snapshot` (a section each, with the commit, date, machine, Node and the versions measured), not measured at build time: the runtime bench needs a quiet machine and a minute, and Vercel's builders aren't one. Each section shows the commit it was measured at. Re-run and commit it when the numbers could have moved, as the parity matrix's Maintenance asks for the Performance rows.
- (agent) The type benchmarks run on TypeScript 7.1 alone ([`typescript-versions.md`](./typescript-versions.md)): the build fails when the snapshot's `typecheck` ran on another version.
- (agent) A `benchmark` fence (`runtime`, `typecheck`, `bundle`) expands at build time into `chart` fences, JSON bar charts that render as static HTML figures with each value printed beside its bar, and into tables in the page's markdown for agents. Each chart's note gives v12's ratio to the others, computed from the snapshot, so the prose needs no numbers that go stale. Static HTML over a React component: the chart is in the prerendered page and its `.md` without a hydration step, and no chart library joins the bundle.
- (agent) An empty `parity` fence expands into the matrix's feature tables, by its headings, with the oRPC, v11 and v12 columns. The Where column stays out: it links decisions, which the site never links ([`hidden-decisions-pages.md`](./hidden-decisions-pages.md)). The page says the oRPC and v11 columns are oRPC's, and that several v12 rows are `experimental_` exports. The build fails when the matrix has no table in that shape.
- Why: the comparison numbers lived only in a note; the page shows them with the method next to them, so readers and the human reviewing them can check them against oRPC's own.
- Lost: numbers measured on each deploy; the Where column's detail; interactive charts (hover, toggles).
- Open: the human's review of the page and its tone towards oRPC, then dropping `experiment: benchmarks` and its entry in `www/src/experiments.ts`. Regenerate the snapshot after the client bundle cuts land.
- Lives in: `www/docs/benchmarks.md`, `www/benchmarks.json`, `www/build/benchmarks.ts`, `www/build/charts.ts`, `www/build/markdown.ts` (`remarkCharts`), `www/build/content.ts` (`parseSource`, `pageMarkdown`), `www/src/styles.css` (`.bench-chart`), `www/src/experiments.ts`, `tooling/bench/bench.ts` and `tooling/bench/kit.ts` (`--snapshot`), `tooling/vercel-ignore/src/bin/ignore.ts`.
