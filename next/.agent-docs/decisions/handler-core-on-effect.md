# The handler core runs calls and builds services as Effects (human asked)

- Human, 2026-10-18: refactor code that isn't Effect-like to Effect-native APIs. The outcome is theirs; the details below are the agent's.
- (agent) The layer's services are the `ManagedRuntime`'s own: `runtime.contextEffect`, which builds the layer once on one fiber however many calls arrive first, read through `runtime.cachedContext` once built. Before, `server/handler/core.ts` kept them in a `Promise` with a second, synchronous copy. A layer that can't be built is a defect, so the call fails as `INTERNAL_SERVER_ERROR`, as before.
- (agent) A call is one Effect (`call` in `core.ts`): the services, the request and per-call services put in place of the running fiber's, then `callProcedure`. `run` is `Effect.exit` of it, run in the caller's fiber, so interrupting the caller interrupts the call. A layer that fails to build ends the call with a failed `Exit`, and a call after `dispose()` dies with "ManagedRuntime disposed" instead of running on the closed layer's services.
- (agent) `makeContext` is `createContext` as an Effect, failing with the `TrpcError` it threw or an unexpected error, the mapping every Effect caller wrote around the old Promise `makeContext` by hand.
- (agent) `HandlerCore` has no Promise `run` or `makeContext` any more: every caller is an Effect, so the Effect forms, first named `runEffect` and `makeContextEffect`, took those names. `SocketCoreShape`, which hands them to socket transports, has the same two. The socket calls (`server/sockets/socket.ts`, `interop/handler/socket.ts`), `fetch.ts`'s `createContext` and the v11 HTTP handler moved first ([`websocket-sessions-on-effect-socket.md`](./websocket-sessions-on-effect-socket.md)), and the OpenAPI handler last. Kept as Promises, at the edge: `createContext` is the user's Promise-shaped callback ([`internals-use-effect.md`](./internals-use-effect.md)); `dispose()` backs the handlers' public `dispose()`.
- (agent) The OpenAPI handler's request path is Effects in its app's fiber: routing, lazy loads, the body, the input, `makeContext` and `run`, with what fails or dies reported to `onError` and sent as the error response, as its `try`/`catch` did. With it:
  - The body is read from the `HttpServerRequest` by the RPC handler's `readBytes` (`server/handler/body.ts`), and forms are parsed from those bytes, so a body that fails mid-read is a 400 `BAD_REQUEST` instead of an unexpected 500. `readFormData` in `internal/protocol.ts` had no other caller and is gone.
  - An aborted request interrupts the call through the app's fiber (`HttpEffect.toWebHandler` interrupts it on `request.signal`). Before, the Promise `run` was interrupted by the same signal on its own fiber. A subscription's `AbortController` still follows `request.signal`, as its events are read after the fiber ends.
  - The unprefixed lazy subtrees load on a fiber forked when the handler is made, which the first request joins, instead of a Promise.
  - The per-request `WeakMap`s keyed by the web `Request` (its `HttpServerRequest`, platform and `serve()` call) are gone; the app passes them along.
- (agent) A handler's lifetimes are one `Scope`, made by `createHandlerCore`: the `ManagedRuntime`'s release, a `FiberSet` of socket sessions, and (given the handler's `drains`) the final drain, so `dispose()` is `Scope.close`: drain, interrupt the sessions still running, release the layer. Sessions fork on it with `core.fork` ([`websocket-sessions-on-effect-socket.md`](./websocket-sessions-on-effect-socket.md)). Before, `createFetchHandler`'s `dispose()` drained, disposed a second runtime (`HttpRouter.toWebHandler`'s, for `fetch`) and the layer one after the other, and sessions ran on `Effect.runFork` where nothing could reach them. `fetch` now runs the app through `HttpEffect.toWebHandler`, which holds nothing: `Effect.interruptible` around the app, as `HttpRouter`'s routes are, so an aborted request still interrupts its call. The HTTP request fibers stay the server's: `dispose()` doesn't interrupt a request in flight, as before.
- (agent) `createFetchHandler` was one ~880-line closure. It is modules in `server/handler/` over one `HttpHandler` record (`http-handler.ts`: the router, the core, the serializer, the endpoint, the limits): `input.ts`, `responses.ts`, `call.ts`, `subscription.ts`, `batch.ts`, `app.ts`, `sessions.ts`, assembled by `fetch.ts`, which keeps the public types. Generator steps are `Effect.fnUntraced`. The hand-rolled `chain` (continue at once from an `Exit`) is `Effect.flatMapEager`, and synchronous input decoding returns an `Exit` from one `Effect.try`-shaped helper (`decodeNow`), so a call that needs no async step still runs without a scheduler turn. `SocketCoreShape.deserializeInput` returns an `Effect`, so the socket core no longer wraps it in `Effect.try` itself.
- (agent) A call's `AbortSignal` comes from one place, `withCallSignal` in `signal.ts`, over `interruptSignal()` from `internal/effects.ts` as the socket and v11 calls use it: it aborts when the call is interrupted (the client left) or, when the call answers with lines it goes on producing (`linesResponse`: JSON lines, frames, SSE), when that stream is. Before, single calls, batches and subscriptions each made a controller and handed it to `linesResponse` to abort. A `Blob` or a procedure's own streamed response doesn't hold the signal, as before. A scope per call, closed with the call or handed to the lines' stream, would say the same and cost every call a `Scope`.
- (agent) A path with a malformed percent escape is a 404 `NOT_FOUND` reported to `onError`, through `fetch` and `toHttpEffect()` alike. `toHttpEffect()` answered it with a 500 (the `URIError` of `decodeURIComponent`); `fetch`'s router answered 404 without reaching the app, as `handler.routes` still does.
- (agent) A byte stream input's web stream (`bodyStream` in `body.ts`) reads with the request fiber's context (`Effect.runPromiseWith`), not an empty one. It stays a hand-made `ReadableStream`: `Stream.toReadableStream` pulls once it starts and interrupts on cancel, where the input must not read before the procedure does, and a cancelled body is drained so Node keeps the connection for the response.
- (agent) Kept as they were: `HandlerCore` and `SocketCoreShape` are plain records passed to their callers, not `Context.Service`s. Every request would add them to its context for a lookup each call does anyway, and their callers (the OpenAPI and v11 handlers, the socket transports) build them per handler.
- Why: one way to run a call and one place the services are built, with the runtime's memoization instead of a hand-rolled cache; no Promise round trip out of and back into Effect inside the OpenAPI handler.
- Lost: nothing users see, beyond the 400 for an unreadable REST body.
- Lives in: `packages/trpc/src/server/handler/core.ts` (`createHandlerCore`), `src/server/handler/fetch.ts` and the modules it assembles, `src/server/handler/signal.ts` (`withCallSignal`), `src/server/handler/routes.ts`, `src/openapi/handler.ts`; tests in `packages/trpc/src/server/handler/core.test.ts` (the layer built once by concurrent first calls; `dispose()` interrupting forked sessions), `src/server/handler/fetch-edges.test.ts` (a path with a malformed escape), `src/server/procedures/procedures.test.ts` (a layer that can't be built) and `src/openapi/openapi-edges.test.ts` ("a body that fails mid-read is a 400", "cancelling a stream, or aborting a request, interrupts the procedure").
