# The handler core runs calls and builds services as Effects (human asked)

- Human, 2026-10-18: refactor code that isn't Effect-like to Effect-native APIs. The outcome is theirs; the details below are the agent's.
- (agent) The layer's services are the `ManagedRuntime`'s own: `runtime.contextEffect`, which builds the layer once on one fiber however many calls arrive first, read through `runtime.cachedContext` once built. Before, `server/handler/core.ts` kept them in a `Promise` with a second, synchronous copy. A layer that can't be built is a defect, so the call fails as `INTERNAL_SERVER_ERROR`, as before.
- (agent) A call is one Effect (`call` in `core.ts`): the services, the request and per-call services put in place of the running fiber's, then `callProcedure`. `runEffect` is `Effect.exit` of it, run in the caller's fiber, so interrupting the caller interrupts the call. A layer that fails to build ends the call with a failed `Exit`, and a call after `dispose()` dies with "ManagedRuntime disposed" instead of running on the closed layer's services.
- (agent) `makeContextEffect` is `createContext` as an Effect, failing with the `TrpcError` it threw or an unexpected error, the mapping every Effect caller wrote around a Promise `makeContext` by hand.
- (agent) `HandlerCore` has no Promise `run` or `makeContext` any more: every caller is an Effect. The socket calls (`server/sockets/socket.ts`, `interop/handler/socket.ts`), `fetch.ts`'s `createContext` and the v11 HTTP handler moved first ([`websocket-sessions-on-effect-socket.md`](./websocket-sessions-on-effect-socket.md)), and the OpenAPI handler last. Kept as Promises, at the edge: `createContext` is the user's Promise-shaped callback ([`internals-use-effect.md`](./internals-use-effect.md)); `dispose()` backs the handlers' public `dispose()`.
- (agent) The OpenAPI handler's request path is Effects in its app's fiber: routing, lazy loads, the body, the input, `makeContextEffect` and `runEffect`, with what fails or dies reported to `onError` and sent as the error response, as its `try`/`catch` did. With it:
  - The body is read from the `HttpServerRequest` by the RPC handler's `readBytes` (`server/handler/body.ts`), and forms are parsed from those bytes, so a body that fails mid-read is a 400 `BAD_REQUEST` instead of an unexpected 500. `readFormData` in `internal/protocol.ts` had no other caller and is gone.
  - An aborted request interrupts the call through the app's fiber (`HttpEffect.toWebHandler` interrupts it on `request.signal`). Before, `run` was interrupted by the same signal on its own fiber. A subscription's `AbortController` still follows `request.signal`, as its events are read after the fiber ends.
  - The unprefixed lazy subtrees load on a fiber forked when the handler is made, which the first request joins, instead of a Promise.
  - The per-request `WeakMap`s keyed by the web `Request` (its `HttpServerRequest`, platform and `serve()` call) are gone; the app passes them along.
- Why: one way to run a call and one place the services are built, with the runtime's memoization instead of a hand-rolled cache; no Promise round trip out of and back into Effect inside the OpenAPI handler.
- Lost: nothing users see, beyond the 400 for an unreadable REST body.
- Lives in: `packages/trpc/src/server/handler/core.ts` (`createHandlerCore`), `src/openapi/handler.ts`; tests in `packages/trpc/src/server/handler/core.test.ts` (the layer built once by concurrent first calls), `src/server/procedures/procedures.test.ts` (a layer that can't be built) and `src/openapi/openapi-edges.test.ts` ("a body that fails mid-read is a 400", "cancelling a stream, or aborting a request, interrupts the procedure").
