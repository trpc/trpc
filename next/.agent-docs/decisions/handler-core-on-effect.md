# The handler core runs calls and builds services as Effects (human asked)

- Human, 2026-10-18: refactor code that isn't Effect-like to Effect-native APIs. The outcome is theirs; the details below are the agent's.
- (agent) The layer's services are the `ManagedRuntime`'s own: `runtime.contextEffect`, which builds the layer once on one fiber however many calls arrive first, read through `runtime.cachedContext` once built. Before, `server/handler/core.ts` kept them in a `Promise` with a second, synchronous copy. A layer that can't be built is a defect, so the call fails as `INTERNAL_SERVER_ERROR`, as before.
- (agent) A call is one Effect (`call` in `core.ts`): the services, the request and per-call services put in place of the running fiber's, then `callProcedure`. `run` is `Effect.exit` of it, run in the caller's fiber, so interrupting the caller interrupts the call. A layer that fails to build ends the call with a failed `Exit`, and a call after `dispose()` dies with "ManagedRuntime disposed" instead of running on the closed layer's services.
- (agent) `makeContext` is `createContext` as an Effect, failing with the `TrpcError` it threw or an unexpected error, the mapping every Effect caller wrote around the old Promise `makeContext` by hand.
- (agent) `HandlerCore` has no Promise `run` or `makeContext` any more: every caller is an Effect, so the Effect forms, first named `runEffect` and `makeContextEffect`, took those names. `SocketCoreShape`, which hands them to socket transports, has the same two. The socket calls (`server/sockets/socket.ts`, `interop/handler/socket.ts`), `fetch.ts`'s `createContext` and the v11 HTTP handler moved first ([`websocket-sessions-on-effect-socket.md`](./websocket-sessions-on-effect-socket.md)), and the OpenAPI handler last. Kept as Promises, at the edge: `createContext` is the user's Promise-shaped callback ([`internals-use-effect.md`](./internals-use-effect.md)); `dispose()` backs the handlers' public `dispose()`.
- (agent) The OpenAPI handler's request path is Effects in its app's fiber: routing, lazy loads, the body, the input, `makeContext` and `run`, with what fails or dies reported to `onError` and sent as the error response, as its `try`/`catch` did. With it:
  - The body is read from the `HttpServerRequest` by the RPC handler's `readBytes` (`server/handler/body.ts`), and forms are parsed from those bytes, so a body that fails mid-read is a 400 `BAD_REQUEST` instead of an unexpected 500. `readFormData` in `internal/protocol.ts` had no other caller and is gone.
  - An aborted request interrupts the call through the app's fiber (`HttpEffect.toWebHandler` interrupts it on `request.signal`). Before, the Promise `run` was interrupted by the same signal on its own fiber. A subscription's `AbortController` still follows `request.signal`, as its events are read after the fiber ends.
  - The unprefixed lazy subtrees load on a fiber forked when the handler is made, which the first request joins, instead of a Promise.
  - The per-request `WeakMap`s keyed by the web `Request` (its `HttpServerRequest`, platform and `serve()` call) are gone; the app passes them along.
- (agent) A handler's lifetimes are one `Scope`, made by `createHandlerCore`: the `ManagedRuntime`'s release, a `FiberSet` of socket sessions, and (given the handler's `drains`) the final drain, so `dispose()` is `Scope.close`: drain, interrupt the sessions still running, release the layer. Sessions fork on it with `core.fork` ([`websocket-sessions-on-effect-socket.md`](./websocket-sessions-on-effect-socket.md)). Before, `createFetchHandler`'s `dispose()` drained, disposed a second runtime (`HttpRouter.toWebHandler`'s, for `fetch`) and the layer one after the other, and sessions ran on `Effect.runFork` where nothing could reach them. `fetch` now runs the app through `HttpEffect.toWebHandler`, which holds nothing: `Effect.interruptible` around the app, as `HttpRouter`'s routes are, so an aborted request still interrupts its call. The HTTP request fibers stayed the server's: `dispose()` didn't interrupt a request in flight (until the second pass, below).
- (agent) `createFetchHandler` was one ~880-line closure. It is modules in `server/handler/` over one `HttpHandler` record (`http-handler.ts`: the router, the core, the serializer, the endpoint, the limits): `input.ts`, `responses.ts`, `call.ts`, `subscription.ts`, `batch.ts`, `app.ts`, `sessions.ts`, assembled by `fetch.ts`, which keeps the public types. Generator steps are `Effect.fnUntraced`. The hand-rolled `chain` (continue at once from an `Exit`) is `Effect.flatMapEager`, and synchronous input decoding returns an `Exit` from one `Effect.try`-shaped helper (`decodeNow`), so a call that needs no async step still runs without a scheduler turn. `SocketCoreShape.deserializeInput` returns an `Effect`, so the socket core no longer wraps it in `Effect.try` itself.
- (agent) A call's `AbortSignal` comes from one place, `withCallSignal` in `signal.ts`, over `interruptSignal()` from `internal/effects.ts` as the socket and v11 calls use it: it aborts when the call is interrupted (the client left) or, when the call answers with lines it goes on producing (`linesResponse`: JSON lines, frames, SSE), when that stream is. Before, single calls, batches and subscriptions each made a controller and handed it to `linesResponse` to abort. A `Blob` or a procedure's own streamed response doesn't hold the signal, as before. A scope per call, closed with the call or handed to the lines' stream, would say the same and cost every call a `Scope`.
- (agent) A path with a malformed percent escape is a 404 `NOT_FOUND` reported to `onError`, through `fetch` and `toHttpEffect()` alike. `toHttpEffect()` answered it with a 500 (the `URIError` of `decodeURIComponent`); `fetch`'s router answered 404 without reaching the app, as `handler.routes` still does.
- (agent) A byte stream input's web stream (`bodyStream` in `body.ts`) reads with the request fiber's context (`Effect.runPromiseWith`), not an empty one. It stays a hand-made `ReadableStream`: `Stream.toReadableStream` pulls once it starts and interrupts on cancel, where the input must not read before the procedure does, and a cancelled body is drained so Node keeps the connection for the response.
- (agent) Kept as they were: `HandlerCore` and `SocketCoreShape` are plain records passed to their callers, not `Context.Service`s. Every request would add them to its context for a lookup each call does anyway, and their callers (the OpenAPI and v11 handlers, the socket transports) build them per handler.
- Human, 2026-10-20 (second pass): public APIs may change toward Effect; only router and procedure declaration must need no Effect knowledge ([`effect-first-public-apis.md`](./effect-first-public-apis.md)). The handler options and lifetimes below are the agent's.
- (agent) Handlers take `runtime`, a caller-owned `ManagedRuntime`, as `createRouterClient` does: `createFetchHandler`, `experimental_createOpenApiHandler` and `createV11Handler` take `LayerOption | RuntimeOption`, so a server and an SSR router client share one build (one pool). `dispose()` leaves a caller's runtime running; `layer` stays the handler-owned convenience. They're exclusive at the type level: `LayerOption` gained `runtime?: undefined`, and `RuntimeOption` already had `layer?: TypeError<…>`. Lost: `Parameters<typeof createFetchHandler<R>>[0]['layer']` is now a union with `undefined`, so tests that read the needed services from it read `inferRouterServices<R>` instead (`middleware/durable.test.ts`, `lock.test.ts`, `ratelimit.test.ts`).
- (agent) `dispose()` ends the HTTP requests `fetch` is serving. `HandlerCore.request` wraps the app: the request's fiber joins a `FiberSet` in the handler's scope, and so does the fiber that streams its body (the response's `HttpBody.Stream` is rewrapped so the stream joins as it starts), so a JSON-lines response is awaited to its end. `close` (the Effect behind `dispose()`) interrupts event streams (SSE) first, since they never end and their clients reconnect; then, concurrently, drains the sockets and waits for the other requests up to the drain timeout (`websocket.drainTimeout` on `createFetchHandler`, a new `drainTimeout` on the OpenAPI and v11 handlers, 10 seconds by default); then closes the scope, which interrupts what's left (a request still running answers 503, `toWebHandler`'s server-interrupt status) and releases the layer. A request after `close` runs untracked. A second `dispose()` waits for the first (a `Deferred`) instead of returning at once. `core.fork` keeps its shape: sessions forked before `close` are tracked, as before. Why: a server stopping with `dispose()` gave requests in flight no deadline and released the layer under them. Lost: `dispose()` takes as long as the slowest request, up to the drain timeout; a test that leaves a response body unread now waits that long (`durable.test.ts` cancels its reader).
- (agent) The OpenAPI app runs `Effect.interruptible` inside `toWebHandler`, as the RPC and v11 apps already did, so `dispose()` (and an aborted request) can interrupt its call. The v11 handler's sockets drain through the same `close`, beside its HTTP requests, since its `websocket()` forks on `core.fork` ([`v11-interop-handler.md`](./v11-interop-handler.md)).
- (agent) All three handlers have `[Symbol.asyncDispose]`, the same function as `dispose()`, so `await using handler = createFetchHandler(…)` disposes it at the end of the block. `ManagedRuntime` already has one, so a test can own both with `await using`.
- (agent) `makeFetchHandler(opts): Effect<FetchHandler, never, Scope | inferRouterServices<TRouter>>` (`server/handler/fetch.ts`) is `createFetchHandler` as a scoped Effect: procedures read their services from the Effect's context (minus `Scope`) instead of a `layer` or `runtime` (`MakeFetchHandlerOptions` has neither), and the end of the `Scope` runs `close`. `Layer.unwrap(Effect.map(makeFetchHandler(opts), serve))` is then one layer with the server and the services provided under it, released handler first. `createFetchHandler` plus `dispose()` stays the Promise path. Not added for the OpenAPI and v11 handlers yet: the same shape fits, but each has its own options type and no Effect user has asked.
- (agent) Not changed: `onError` stays a synchronous callback. As an Effect hook it would run outside the request's fiber from the socket, v11 and OpenAPI paths that call `report`, so it would lose the spans and annotations that make it worth being an Effect; an Effect user can log from an Effect middleware or the tracer. `serve(handler, opts)` and `toHttpEffect(handler, opts)` are a `Layer` and an `Effect` already, and their options (`endpoint`) are plain data; `serve()` drains but doesn't dispose a handler it didn't make, which `makeFetchHandler` + `serve` covers.
- Why: one way to run a call and one place the services are built, with the runtime's memoization instead of a hand-rolled cache; no Promise round trip out of and back into Effect inside the OpenAPI handler.
- Lost: nothing users see, beyond the 400 for an unreadable REST body.
- Lives in: `packages/trpc/src/server/handler/core.ts` (`createHandlerCore`), `src/server/handler/fetch.ts` and the modules it assembles, `src/server/handler/signal.ts` (`withCallSignal`), `src/server/handler/routes.ts`, `src/openapi/handler.ts`, `src/interop/handler/handler.ts` (`runtime`, `drainTimeout`, `request`); tests in `src/server/handler/lifetime.test.ts` (a shared runtime, exclusivity, what `dispose()` ends and when, `await using`, `makeFetchHandler`), `src/http/adapters.test.ts` (`makeFetchHandler` under `serve()`), the last tests of `src/openapi/openapi-edges.test.ts` and `src/interop/handler/handler-edges.test.ts`; tests in `packages/trpc/src/server/handler/core.test.ts` (the layer built once by concurrent first calls; `dispose()` interrupting forked sessions), `src/server/handler/fetch-edges.test.ts` (a path with a malformed escape), `src/server/procedures/procedures.test.ts` (a layer that can't be built) and `src/openapi/openapi-edges.test.ts` ("a body that fails mid-read is a 400", "cancelling a stream, or aborting a request, interrupts the procedure").
