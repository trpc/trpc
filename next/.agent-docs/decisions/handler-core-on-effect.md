# The handler core runs calls and builds services as Effects (human asked)

- Human, 2026-10-18: refactor code that isn't Effect-like to Effect-native APIs. The outcome is theirs; the details below are the agent's.
- (agent) The layer's services are the `ManagedRuntime`'s own: `runtime.contextEffect`, which builds the layer once on one fiber however many calls arrive first, read through `runtime.cachedContext` once built. Before, `server/core.ts` kept them in a `Promise` with a second, synchronous copy. A layer that can't be built is a defect, so the call fails as `INTERNAL_SERVER_ERROR`, as before.
- (agent) A call is one Effect (`call` in `core.ts`): the services, the request and per-call services put in place of the running fiber's, then `callProcedure`. `runEffect` is `Effect.exit` of it, and `run` is `Effect.runPromiseExit` of it with the call's `signal`, so the two can't drift. A layer that fails to build now ends `run` with a failed `Exit` instead of a rejected Promise, and a call after `dispose()` dies with "ManagedRuntime disposed" instead of running on the closed layer's services.
- (agent) `makeContextEffect` is `createContext` as an Effect, failing with the `TrpcError` it threw or an unexpected error, the mapping every Effect caller wrote around `makeContext` by hand.
- (agent) Kept as Promises, at the edge: `createContext` is the user's Promise-shaped callback ([`internals-use-effect.md`](./internals-use-effect.md)); `dispose()` backs the handlers' public `dispose()`. `run` and `makeContext` stay for the OpenAPI handler, their last Promise caller; the socket calls (`server/socket.ts`, `interop/socket.ts`), `fetch.ts`'s `createContext` and the v11 HTTP handler use `runEffect` and `makeContextEffect` ([`websocket-sessions-on-effect-socket.md`](./websocket-sessions-on-effect-socket.md)).
- Why: one way to run a call and one place the services are built, with the runtime's memoization instead of a hand-rolled cache.
- Lost: nothing users see.
- Open: dropping `run` and `makeContext` from `HandlerCore` once the OpenAPI handler doesn't await them.
- Lives in: `packages/trpc/src/server/core.ts` (`createHandlerCore`); tests in `packages/trpc/src/server/core.test.ts` (the layer built once by concurrent first calls) and `src/server/procedures/procedures.test.ts` (a layer that can't be built).
