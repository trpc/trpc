# Type-check cost by procedure shape

2026-10-19. What does each way of writing a procedure cost to type-check in a large router, and what can be cut without loosening the types? Asked by the oRPC-parity answer on type-check speed ("C", [`../decisions/byte-stream-inputs.md`](../decisions/byte-stream-inputs.md)), starting from the thrown-errors work's +22% with `.errors()` ([`../decisions/thrown-errors-and-exhaustive-declarations.md`](../decisions/thrown-errors-and-exhaustive-declarations.md)).

## Method

`pnpm bench shapes [--procedures 1500] [--runs 3] [--only plain,errors]` (`next/tooling/bench/shapes.ts`; `pnpm build` first). For each shape it generates 1,500 procedures in files of 10 (half queries, half mutations, every field name unique so nothing is shared), a fetch handler over the router, and a client file per router file calling each procedure with its result annotated. Each project is checked with `tsc --extendedDiagnostics --singleThreaded` (TypeScript 7.0.2, v12 from its `.d.ts`, `skipLibCheck`), first the server half (routers and handler) and then everything. "Per procedure" subtracts an empty router.

| shape           | each procedure                                                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `plain`         | `t.procedure.input(S).query((opts) => cond ? error({ code: 'NOT_FOUND' }) : { v })`                                                 |
| `output`        | the same with `.output(S)`                                                                                                          |
| `errors`        | `.input(S).errors({ NOT_FOUND: {}, CONFLICT: { data: S } })`, returning `opts.errors.NOT_FOUND()`                                   |
| `errors+output` | both                                                                                                                                |
| `middleware`    | `authed` (three `.use()`, one returning `UNAUTHORIZED`) plus an inline `.use((opts) => opts.next({ ctx: { … } }))`, then `.input()` |
| `effect`        | `plain` with an `Effect.gen` resolver that `yield*`s the error                                                                      |
| `contract`      | `c.input(S).output(S).errors({ … }).query()` in a contract, implemented through `t.implement(contract)` and `impl.router()`         |

Instantiations, types and memory are the same on every run. Check time moves by about 10% between sessions on this VM (v11's fixed number read 1.15s to 1.30s on the same day), so compare times within one table. Median of 5 runs (3 for `errors` and `effect`, which this work doesn't change).

## Findings

- **`.output()` cost was union distribution.** The terminals check the resolver's return as `$Ret & OutputConstraint`, and the constraint was `MaybePromise<O | AnyTrpcError> | Effect<O | AnyTrpcError>`. A resolver that returns a value or an error has a union `$Ret`, so the intersection became |`$Ret`| × 4 members per procedure. TypeScript orders union members with `Effect` first, so each returned `TrpcError` (itself a `YieldableError`, an `Effect`) was compared structurally against a fresh `Effect<O | AnyTrpcError>`, pulling in `EffectUnify`, `Variance` and the iterator types. Removing the constraint entirely cut `output` from 227k to 168k instantiations and 0.33s to 0.19s at 300 procedures.
  - A first fix (`84b35ea69`) checked each member of `$Ret` against the one form it can be. It kept `$Ret & …` in the return position, and that is also why an `async` resolver lost its literals (`async () => ({ status: 'a', n: 1 })` against `{ status: 'a' | 'b' }` was a type error, and so was `yield { kind: 'x' }` in an `async function*` subscription or a `stream()` query, in the builder and in contracts).
  - Now (`perf(types): a typed output bounds the resolver's return`): with a typed output, the resolver is `(opts) => $Ret | Returns<O, E>` with `$Ret extends Returns<O, E>`, where `Returns` is the output or an error as they are, in a `Promise`, or in an `Effect` that fails only with those errors (`E` is the declared errors once `.errors()` has any, else `AnyTrpcError`; a contract's errors for an implementation). The bound is the check; the union in the return position gives `async` bodies and `yield`s their contextual type, and `$Ret` still carries what the procedure type needs (errors, services). Subscriptions use `Yields` (an `AsyncIterable` or `Stream` of the events, or an error). Without an output, or with one that accepts an `AsyncIterable` (`unknown`, `{}`), nothing literal can be typed, so the checks stay on the return as before.
  - What made it work, from a scratch file: any `$Ret & X` in the return position drops the literal context in `async` functions and generators, even for a plain union `X`. A bound alone keeps it. But a bound plus any check on `$Ret` that TypeScript can resolve before inference (`[Extract<Awaited<R>, E>] extends [never] ? …`, an `infer` wrapper, a union-to-intersection, a rest-parameter check) fixes `$Ret` to its bound when the resolver has a context-sensitive `opts`, and per-member checks (`R extends E ? TypeError : unknown`) can't fail a union because `unknown` absorbs the failing member. So every check moved into the bound: declared errors (`E`), unmapped `Effect` and `Stream` failures (the failure channel), `ok()` values (the bound becomes the `TypeError` when they don't fit the output) and streams for a plain schema (`StreamWithoutStreamSchema`, a member no generator matches, which names the hint). `yield` needs the contextual return type itself to be a union: TypeScript filters it to its iterable members, which it doesn't do through the type parameter, so `$Ret | Returns` and not `$Ret` alone.
  - A resolver that fails the bound is inferred as the bound, whose `Effect` member requires `any`; `ServicesOf` treats an `any` requirement as none so the router doesn't then need a layer.
  - Error messages show what was written and what's allowed, under a header naming the bound (`Returns<Status, TrpcError<"NOT_FOUND">>`). The hints are interfaces nothing real matches, each keyed by its text so the message ends on "Property '<hint>' is missing" (`fix(types): a typed output's undeclared error and unmapped failure name their fix again`). TypeScript reports a failed union assignment against the members whose literal properties the value matches (discriminants), then against the one sharing the most keys, so the hints are shaped to be those members. `UnlistedError` (in the value and the failure channel) has every key of a `TrpcError` but `data`, with `code: string`, so a `TrpcError<"CONFLICT">` matches its `code` and no declared one; leaving out `data` keeps it out of `error()`'s inference (with `data` the message read `TrpcError<"CONFLICT", any>`). `UnmappedFailure` (the failure channel only) extends `Error`: a `TrpcError`'s `name` is the literal `'TrpcError'`, so any other error, tagged or not, is ruled out of the `TrpcError` members and lands on it, whatever order the union is in. The four cases, before the bound (`7672f9cd2`), after it (`46375cd66`) and now, last line of each:

    | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Cost against the bound alone: `output` −1.8% instantiations, `errors+output` and `contract` +1.8% and +1.6% (the extra member), same time; a cheaper `UnlistedError` with only `code`, `_tag` and `Error`'s keys costs the same and loses the `name` discriminant.

  - Server half against `7672f9cd2`, median of 5: `output` 1,162,580 → 896,951 instantiations (−23%), 294 → 243 MB, 1.34 → 0.96s; `errors+output` 1,521,168 → 1,230,741 (−19%), 361 → 292 MB, 1.75 → 1.23s; `contract` 2,112,145 → 1,859,265 (−12%), 386 → 345 MB, 2.02 → 1.70s. With the client half: `output` 358 → 305 MB and 1.73 → 1.34s, `errors+output` 436 → 359 MB and 2.19 → 1.73s, `contract` 457 → 418 MB and 2.42 → 1.99s. Shapes without an output pay the dispatch: `plain` +2.0%, `errors` +1.1%, `middleware` +0.7%, `effect` +2.6% instantiations, same types and memory, and the same time over two alternating runs of each (plain 0.48–0.50s against 0.49s, middleware 1.16–1.19s against 1.17–1.19s). A wrapping conditional for the whole resolver (`Resolver<TDef, $Ret>`) cost twice that; the dispatch is now a conditional on the return only, testing `Unset` first.
  - Precomputing the bound into `BuilderDef` (a `returns` field the terminal reads, `query<$Ret extends TDef['returns']>`) doesn't pay. Of the no-output overhead, the bound is 4 instantiations per procedure (`plain` 522,972 with it, 516,961 with no bound at all); the rest is the dispatch on the return, which a precomputed bound still needs. A `returns: unknown` field on the root def, read but never recomputed, already costs more than it saves where it would have to be recomputed: `plain` and `effect` −3,011 (−0.6%), `middleware` −2,979, `errors` +9,021 (+0.9%, the field is read through two `With` layers). Recomputing it at `.output()`, `.errors()`, every `.use()`, `concat`, `extend` and `t.implement()` (the bound reads the output, the declared errors and the `ok()` values) only adds to that, and spreads one rule over seven places.
- **A ctx-only middleware reopened the error union (a type-safety bug, fixed in `fix(middleware): a middleware that only calls next() adds no errors`).** When every branch of a middleware returns `next()` or `ok()`, TypeScript infers the whole return type into the one naked type variable left in the target union, `$Err` (at the lowest priority, but it is the only candidate). The candidate failed the `AnyTrpcError` bound, so `$Err` became `AnyTrpcError`. Every procedure after `.use((opts) => opts.next({ ctx }))`, or even `opts.next()`, had `AnyTrpcError` in its errors, so the client union took any code, against [`../decisions/granular-errors.md`](../decisions/granular-errors.md). `t.implement(contract).use(ctxOnly)` was a type error unless every leaf declared `AnyTrpcError`.
  - `$Err` is now bounded by `MiddlewareErrors` (`AnyTrpcError` or what `next()` and `ok()` return) and the builder keeps `Extract<$Err, AnyTrpcError>`, in `.use()`, `t.middleware`, `middleware()` and `impl.use()`. Middleware returning anything else is still a type error, and real errors are still inferred (`procedures.test.ts`).
  - It costs the `middleware` shape +19% instantiations (the junk candidate is now carried through the check), with the same check time and slightly less memory. A non-distributive fast path (`[$Err] extends [AnyTrpcError] ? …`) and the bound alone without `Extract` cost the same.
- **The thrown-errors work, re-measured:** against `946729e18`, `.errors()` costs +13% instantiations and +10% memory, `errors+output` +8%, `plain` +4%. `DeclaredCheck` is about a third of the time `.errors()` adds: dropping it gives 0.158s against 0.189s at 300 procedures. Deferring it until `$Ret` is known (`unknown extends $Ret ? unknown : …`) is no cheaper; it's the check itself. With the output change, `errors+output` is now under its pre-thrown-errors time and memory.
- **`pnpm bench typecheck` grew 31% in instantiations** since [`benchmarks.md`](./benchmarks.md) recorded 1,105,592 (`219c819fa`); this work doesn't change it (1,445,822 before and after; its procedures have no `.output()` or middleware). - **Tried, no gain:** respelling `With` (`Omit`, homomorphic and `Pick` forms) and a spelled-out `OutputDef` (alias arguments are evaluated eagerly, so worse); an empty-`declared` fast path in `Overwrite` (−2%); changing `ResolverOpts` members; `.output()` checked through a `$Ret extends OutputConstraint` bound with the other checks still on the return (fewer types, 37% more instantiations; the bound with the checks folded in is the change above); `Pick<Terminals, type>` on a contract leaf replaced by a conditional (same); a single `[$Ret] extends [union] ? unknown : …` check (literal outputs lose their contextual type).

## Open

- The contract terminal costs more than the builder's (670 against 518 per procedure, before the bound); without an output, `UndeclaredCheck` and `StrictErrors` both compute `SplitReturn<$Ret>`.
- The client half: the link codes and the closed union cost about 53 instantiations per call in `pnpm bench typecheck`.
- An inline `.use()` after a base procedure costs 60% more than on `t.procedure` (211 against 131): `Overwrite` of the accumulated ctx.
