# raf-query on TanStack Start with Effect

[![Open in CodeSandbox](https://codesandbox.io/static/img/play-codesandbox.svg)](https://codesandbox.io/p/devbox/github/KATT/raf-query/tree/codesandbox/examples/tanstack-start-effect?file=/apps/tanstack-start-effect/src/routes/prefetch/issues/index.tsx)

Live at [tanstack-start-effect.raf-query.katt.dev](https://tanstack-start-effect.raf-query.katt.dev).

A small issue tracker built with [raf-query](https://github.com/KATT/raf-query#readme), written with [Effect](https://effect.website) end to end: the API is an Effect RPC group, the `queryFn`s return Effects (typed errors and services), form actions are `Effect.fn`s, and the router's search params are Effect Schemas. Loaders use the same Promise `prefetch`, `ensure` and `fetch` as the non-Effect apps; `queryClient.runPromise` runs the actions. [`examples/tanstack-start`](https://github.com/KATT/raf-query/tree/main/examples/tanstack-start) is the same app written with Promises.

The markup all four example apps share (issue rows, the status menu, comments, skeletons, the settings controls) is in [`examples/.shared/kit`](https://github.com/KATT/raf-query/tree/main/examples/.shared/kit). Every query, loader, and save stays in this app.

The RPC group, its schemas and its typed errors are in `src/rpc.ts`; `src/rpc-handlers.ts` implements them over the fake database, and the server route `src/routes/rpc.ts` serves them. `src/issues.ts` is the `Issues` service, the group's typed client. The query client's `layer` (`src/router.tsx`) provides it, so query factories (`src/queries.ts`) and actions `yield* Issues`. `ErrorOf` / `ServicesOf` on a factory name the query's error and service types. Failures keep their type across SSR: the router integration sends them with `keepErrors`, and `src/start.ts` registers a serialization adapter for `IssueNotFound`. During SSR the client calls the handlers in process; in the browser it posts to `/rpc` (see `#rpc-transport` in `package.json`). The data comes from an in-memory fake database that waits the latency picked in the top bar (or `DB_LATENCY_MS`, default 400) ± 50% per call and resets when the server restarts.

The top bar's **Loader** select switches the URL's verb and keeps the page you are on; its other settings live in cookies, so the server renders with them too. **Prefetch links** sets the router's `defaultPreload` (`src/settings.ts`) and starts **off** (`false`): on intent, in the viewport, on render, or off. **Stale time** is the query client's `staleTime` (5 seconds until you pick another). **Latency** is a cookie the RPC handlers read, as a real server reads its session: the browser sends it, and during SSR the `Issues` layer forwards the page request's `cookie` header (`src/forwarded-headers.ts`). The handlers pass it to the database call. **Reset** clears the cookies, drops every query and the router's match cache, and reloads, so the cache starts empty.

## Run it

From the root of this repo:

```shell
pnpm install
pnpm dev:effect
```

Then open <http://localhost:3005>.
