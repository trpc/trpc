# raf-query on React Router

[![Open in CodeSandbox](https://codesandbox.io/static/img/play-codesandbox.svg)](https://codesandbox.io/p/devbox/github/KATT/raf-query/tree/codesandbox/examples/react-router?file=/apps/react-router/app/routes/prefetch/issues/route.tsx)

Live at [react-router.raf-query.katt.dev](https://react-router.raf-query.katt.dev).

A small issue tracker built with [raf-query](https://github.com/KATT/raf-query#readme) on [React Router](https://reactrouter.com) Framework Mode. [`examples/tanstack-start`](https://github.com/KATT/raf-query/tree/main/examples/tanstack-start) and [`examples/nextjs`](https://github.com/KATT/raf-query/tree/main/examples/nextjs) are the same app on TanStack Start and the Next.js App Router, so the integrations can be compared side by side.

The markup all four example apps share (issue rows, the status menu, comments, skeletons, the settings controls) is in [`examples/.shared/kit`](https://github.com/KATT/raf-query/tree/main/examples/.shared/kit). Every query, loader, and save stays in this app.

Query factories are in `app/queries.ts`. Their `queryFn`s, and the form actions, call a REST API through its typed [Hono](https://hono.dev) client. The API lives in [`examples/.shared/api`](https://github.com/KATT/raf-query/tree/main/examples/.shared/api), shared with the other apps, and the resource route `app/routes/api.$.ts` serves it. The root route's `middleware` creates a `QueryClient` for each request and puts it in a React Router context (`app/query-client.ts`), so every loader of the request shares it. Each loader starts the route's queries with its verb and returns `dehydrate(qc)`; the route wraps its tree in `HydrationBoundary` from `@raf-query/react`, which writes that state into the browser's client. The data comes from an in-memory fake database that waits the latency picked in the top bar (or `DB_LATENCY_MS`, default 400) ± 50% per call and resets when the server restarts.

The top bar's **Loader** select switches the URL's verb and keeps the page you are on; its other settings live in cookies, so the server renders with them too. **Prefetch links** sets `<Link prefetch>` on every link in the app (`app/components/app-link.tsx`) and starts **off**: on intent, in the viewport, on render, or off. **Stale time** is the query client's `staleTime` (5 seconds until you pick another). **Latency** is a cookie the API reads, as a real API reads its session: the browser sends it, and loaders forward the page request's `cookie` header (`app/settings.ts`). The API passes it to the database call. **Reset** clears the cookies, drops every query, and reloads, so the cache starts empty.

## Run it

From the root of this repo:

```shell
pnpm install
pnpm dev:react-router
```

Then open <http://localhost:3006>.
