# Typed errors → Result in React; throwOnError opt-in (human asked, agent designed)

- Human: Effect docs should show inferred errors; an option to handle failures inline in `useQuery`; Result (not a custom wrapper); settable on `QueryClient` with default not to throw for Effect; Promise/`unknown` should not get a useless Result option.
- **Inferred, then caught with Effect**: an Effect `queryFn`'s error type is the query's (`ErrorOf<TFactory>`), and every cache verb fails with it. Apps narrow with `Effect.catchTag(s)` in a loader / action run by `queryClient.runPromise`.
- **React default with a `layer`**: `QueryClient.throwOnError` defaults to `false` when `layer` is set, `true` otherwise. For a typed `ErrorOf`, `useQuery` then returns `Thenable<Result<Data, ErrorOf>>` (or the `Result` itself for a handle with data) so callers `Result.match`. `use()` suspends while pending and never throws. Pass `throwOnError: true` on the client, the query's options or the call for a rejecting promise / error boundary (precedence in `query-throw-on-error.md`).
- **Promise `queryFn`s**: `ErrorOf` is `unknown`, so Result would not help. Types always treat them as throwing; `throwOnError` is not a meaningful option for them. The runtime matches: each entry records whether its last `queryFn` call returned an Effect (`Entry.returnsEffect`, read through `Query.returnsEffectUnsafe`), dehydration sends it (`DehydratedQuery.effect`), and `throwsOnError` in `controls.ts` makes bindings throw for `false`. Unknown (no `queryFn` has run here or on the sender, e.g. only `setData`) follows the flag. Lost: a marker on the factory (`queryOptions` can't see what `queryFn` returns without calling it). Known gap: an Effect whose error type is `unknown` is typed as throwing but reads as a `Result`.
- **No effect-query-style wrapper** (`EffectQueryFailure | EffectQueryDefect` with `error.match`): `state.error` is `Cause.squash`ed, SSR errors arrive as `RedactedError` (unless `keepErrors`), and class instances don't survive serialization. `controls.error` stays `unknown`; narrow with `Schema.is`. Success stays success in the success channel — don't showcase `User | null` / `Option<User>` for typed failures.
- Lost: a typed `controls.error` / error-boundary error (can't be sound across SSR and shared defaults); inferring the omit-`throwOnError` return type from the live client's flag (types default typed factories to Result when neither the read nor the query sets the flag, matching the `layer` default; set `throwOnError` on the query or the read when the client throws).
- Lives in `www/content/effect-errors.md`, `packages/react/src/use-query.ts`, `packages/core/src/controls.ts`, `packages/core/src/client.ts`.
