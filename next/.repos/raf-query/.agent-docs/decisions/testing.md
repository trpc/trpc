# Tests (agent)

- React tests: render, rerender and click inside **async** `act` (`await act(async () => …)`); a sync `act` (RTL's bare `render`) never resumes a suspended tree after its promise resolves, boundary or not. It's React's, not raf-query's: the retry sits on the sync act's dropped queue as `fakeActCallbackNode`, and later pings reuse that node instead of scheduling (`react-dom-client.development.js`, `ensureRootIsScheduled`). Pinned by `use-query.test.tsx` ("a root with no Suspense boundary"); documented in `www/content/testing.md`. Responding to a fake request needs a macrotask wait inside the act. Effect tests that fork a stream before a cache write need `Effect.forkChild(x, { startImmediately: true })`.
- Don't unit test the docs site's presentation (human): the build catches broken samples and markdown.
- Behavior tests of the Promise API (`client`, `hydration`, `infinite`) live in `packages/core` next to `QueryClient`; `QueryCache`'s tests drive it with `it.effect`. Type tests of `useQuery` (`types`, `register`) stay in each binding.
