# Homepage framework mode toggle (human asked)

- A **pill docked above the hero code**: `position: absolute` in `#hero-code`'s reserved `padding-top`, centered on the code. While you scroll (desktop) it drifts toward the viewport center; when its spot reaches the header (`header.bottom + 8`, under the sticky menu, `z-30` vs header `z-40`) it snaps to `position: fixed` there. At the **bottom of `#how-it-works`** its `top` is capped so it stops sliding down and leaves with that section — no fade. On small screens it stays centered on the code, with the same snap. The math is the pure `frameworkModeBarLayout` (`www/src/framework-mode-bar-layout.ts`). Lost: a full-width sticky bar (heavy), an always-centered sticky pill under the header (left the code without a control), a `fixed` overlay inset into the code (covered its first lines), and fading out at `#principles` (felt like it vanished).
- The choice is `?mode=nextjs` or `?mode=react-router` on `/`; TanStack Start omits the param. `stripSearchParams(homeSearchDefaults)` keeps `/` from rewriting to `?mode=tanstack-start` when Zod fills the default. Mode switches use `resetScroll={false}` so the page doesn't jump.
- Each mode's samples are `sample:` imports from `www/samples/tanstack-start`, `www/samples/nextjs` or `www/samples/react-router`; the route picks which set to show. Prose for the walkthrough steps switches with the mode.
- **Next.js samples** live under `src/app/(blog)/`, so the code titles show real App Router paths. `posts/[slug]/page.tsx` is the server component: it prefetches, and renders `<Post>` and `<Comments>` each in their own Suspense boundary inside `HydrationBoundary`. Those two are client components in `components/post.tsx` and `components/comments.tsx`. Comments is an infinite query. They use `prefetch` + Suspense — not `ensure` (that verb fits loaders; in RSC, prefer `prefetch` for streamed client reads and `fetch` when the server component renders the data itself). `<Post>` keeps a visible `useQuery()`. The hero folds the comments file (`comments.tsx#hero`); the walkthrough and the Next.js page use `#component`, which is the same code unfolded. Lost: one client `post.tsx` that owned the Suspense tree (the boundaries belong on the server, human).
- **TanStack Start homepage samples** are one file (`blog.$slug.tsx`: both `prefetch`, `<Post>` + collapsed `<PostComments>`). The hero shows that whole file; walkthrough steps zoom `#route` / `#component` of it. `posts.$slug.tsx` keeps ensure+prefetch for the guides. Next.js stays split — the server page, plus a client file per component — because of `"use client"`.
- The site is static HTML: `/` is prerendered once. Every mode's panels ship in that HTML; a blocking `frameworkModeScript` sets `data-framework-mode` from `?mode=` before paint, and CSS shows the matching `[data-framework-panel]`. Client navigations call `syncFrameworkModeAttribute`. Lost: `useSyncExternalStore` forcing the default until hydration (flashed TanStack Start on `?mode=nextjs`).
- Lost: one sample with in-block tabs (harder to share a deep link), and a site-wide preference (this toggle is homepage-only until more docs samples need it).
