# Query `meta` (human asked for TanStack parity)

- **Query `meta`** (parent agent, 2026-10-12): `meta?: QueryMeta` is in `QueryBehavior`, so factories and `config.defaults` take it, matching TanStack (a query's own `meta` replaces the default whole). `Entry.metaOf` resolves it: the options' `meta`, else the default's; before any factory call, the dehydrated `meta` (`entry.hydratedMeta`, set by `hydrateEntries` only while `entry.options` is unset, as TanStack only applies it when hydrate creates the query). It's passed in the `queryFn` / page function context (`requestEffect`), read with `Query.metaUnsafe(query)`, shown in devtools, and dehydrated (resolved, so it includes the sender's default, like TanStack's `query.meta`); omitted from `DehydratedQuery` when `undefined`. `QueryMeta` follows TanStack's `Register` pattern (`options.ts`): `Register extends { queryMeta: infer T } ? T : Record<string, unknown>`. Augmenting `@raf-query/react` works through its `export *` (`packages/react/src/register.test.ts`, which also narrows `QueryMeta` for every react test). The human asked for TanStack parity over the earlier no-defaults / not-dehydrated design; meta must therefore be serializable (the docs say so).
