# Services channel for queries (agent, human asked)

Human: make the codebase Effect-native, inspired by [voidhashcom/effect-query](https://github.com/voidhashcom/effect-query). Ported the effect-atom experiment's services design onto the own-engine core.

- **`queryFn` Effects may need services**: the `services` member of the types bag (`QueryFnResult<{ data, error, services }>`), threaded through `QueryOptions` / `InfiniteQueryOptions` / `queryOptions` / `infiniteQueryOptions`; `ServicesOf<TFactory>` reads them (`never` for promises and for the erased `QueryFactory`).
- **The options carry a type-only `[servicesType]` field** (like handles' `[factoryType]`). The `queryFn` return type can't carry the requirement: with `unknown` data, `QueryFnResult<{ data: unknown }>` is `unknown`, so anything is assignable. `QueryFactory<TServices = unknown>` returns only `kind` / `queryKey` (plus the phantom when `TServices` isn't `unknown`): TS infers an inline factory's `queryOptions` type arguments from the constraint's return type, and a `queryFn` or phantom returning `unknown` there inferred `unknown` services.
- **Which services a request gets**: the cache's build-time context (`make` captures it), merged with the context of the latest verb that called for the entry (`Entry.provide`, stored on the entry, caller wins). Verbs that set it, and require `ServicesOf<TFactory>`: `ensure`, `fetch`, `prefetch`, `getQuery`, `watch`, `Query.fetch`. Everything else that starts a request (`getQueryUnsafe` + `readUnsafe`, commands, polling, focus/reconnect, `invalidate`, `reset`) reuses the stored context. The caller's `Scope` is omitted (a request outlives its caller); its `ParentSpan` is kept, so the `raf-query.request` span nests under the latest caller's span — a later restart nests under that (ended) span too.
- `runRequest` (`request.ts`) wraps each `queryFn` request: `tapDefect` + `logError`, `withSpan("raf-query.request", { attributes: { "raf_query.hash" } })`, `provideContext(entry.services)`. Entries erase `R` with the data type; `fromQueryFn<unknown, unknown, never>` names the erasure.
- **`QueryClient<TServices = never>`** takes `layer?: Layer<TServices>`, built with `Layer.buildWithScope(Layer.provide(QueryCache.layer(config), layer), scope)` via `runSync` (so the layer must be synchronous). Every factory-taking verb is constrained to `QueryFactory<TServices>`; the verbs pass no context at runtime (the cache already captured the layer), so `provided()` drops `R` with a cast. `dispose()` closes the scope.
- **Erased client is `QueryClient<unknown>`** in `QueryClientProvider` / `useQueryClient` / `useQuery`: a hook can't know the provider's layer, and components must be able to `invalidate` a services-using factory. Clients of any `TServices` are mutually assignable (method bivariance), so integrations typed `QueryClient` accept any client unchanged. Unchecked: `useQuery` on a client missing a service dies at request time.
