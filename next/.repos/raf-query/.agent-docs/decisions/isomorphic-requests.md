# Isomorphic requests: forward cookies, swap transports at build time (human asked, agent designed)

Human: the Next.js docs didn't explain how a factory's request works on both server and browser (headers, cookies); examples must follow the pattern so they fork as a real starting point.

- **No raf-query API change.** A factory's `queryFn` closes over a transport module. In Next.js App Router it runs in exactly two places: server components (`getQueryClient`) and the browser. `QueryProvider`'s server client starts no request, so client-component SSR never calls it, and nothing needs the app's own origin. Lost: a per-client context passed to `queryFn` (`QueryProvider`'s `config` must be serializable, so the server layout can't hand it a transport, and it adds a concept). Effect users already have `QueryClient`'s `layer`.
- **The API authenticates from its own cookies.** The browser sends them on same-origin `fetch`; the server forwards the page request's `cookie` header to its in-process call. Same as tRPC (`createTRPCContext` from `headers()` / the route handler's `req`) and oRPC (`createRouterClient(router, { context: async () => ({ headers: await headers() }) })`). Forward only `cookie` (or `authorization`), not every header. Lost: app code reading cookies on each side and re-sending them as custom headers (the old `x-db-latency`): a real session can be `HttpOnly`, so `document.cookie` can't see it.
- **Swap by export condition, not `typeof window`.** Next.js resolves `react-server` for server components (package `imports` too, Turbopack dev and build), so `#forwarded-headers` → `forwarded-headers.server.ts` can import `next/headers` statically; `default` (browser and client SSR) returns `{}`. `@examples/api/client` swaps in-process / HTTP with `browser` / `default`, shared with Start. A runtime check with a dynamic import would put the server module in a browser chunk. oRPC's `globalThis.$client` is the other way to get there.
- **Start**: `createIsomorphicFn().server(() => getRequestHeader("cookie"))`, `.client(() => ({}))`, since loaders run during SSR.
- Files: `examples/nextjs/src/forwarded-headers{,.server}.ts`, `examples/tanstack-start{,-effect}/src/forwarded-headers.ts`, `examples/.shared/api/src/app.ts` (`getCookie`), `tanstack-start-effect/src/rpc-handlers.ts` (`Cookies.parseHeader`). Docs: `www/content/react-server-components.md` and `tanstack-start.md` ("Server and browser requests"), with samples in `www/samples/nextjs/src/api-fetch{,.server}.ts` (`#api-fetch`) and `www/samples/tanstack-start/src/forwarded-headers.ts`.
- The experimental TanStack Query apps call `@examples/api/client`'s `api` without forwarding: they have no settings menu and aren't starting points.
