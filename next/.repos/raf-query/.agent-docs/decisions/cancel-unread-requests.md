# Unread requests are cancelled (agent)

- **Unread requests are cancelled** (parent agent, 2026-10-12), like TanStack's `removeObserver`. On the observers 1 → 0 transition, `subscribeUnsafe`'s unsubscribe defers `unobserved` (`entry.ts`) with `scheduleNotify`, so React's unsubscribe-then-resubscribe in one commit (StrictMode, a route swapping in a page that reads the same query) cancels nothing; `Effect.yieldNow` would wait for a macrotask. If the entry has data and the request read its signal (`signalRead`: a getter on the `queryFn` context, like TanStack's `abortSignalConsumed`; an Effect result counts, since interrupting it cancels it), the `request` fiber is interrupted, the state goes back to before the request (`failureCountBefore`), and the request's `Deferred` succeeds with the cached data; no `failed` event. Otherwise `retriesStopped` ends retries: a `Schedule.while` on the retry schedule, and a check after the delay and after the online wait (a retry already waiting for the network still waits, as in TanStack). The next `subscribeUnsafe` clears it (TanStack's `cancelRetry` / `continueRetry`). **First loads are never interrupted**, unlike TanStack: a render suspended on one isn't subscribed and waits on `entry.pending`, which an interrupted request leaves pending (only the request's `Deferred` settles) until a later read starts another request, so it could hang. TanStack's suspense waits on the fetch promise itself, which rejects and re-renders. Requests started with no readers (a loader's `prefetch`) aren't touched; server caches have no React subscribers.
