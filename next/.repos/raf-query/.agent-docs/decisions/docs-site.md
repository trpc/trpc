# Docs site (human asked; details agent)

- **`www/` is the documentation site** (human): markdown guides with live demos, built on raf-query itself, deployed on Vercel at `raf-query.katt.dev`, with good SEO, and credit to TanStack Query.
- **TanStack Start, fully prerendered** (agent): every page is static HTML in `www/dist/client`, so Vercel serves it from the CDN with no functions. The prerender crawler fails the build on any broken internal link. Lost: Next.js (the other integration), Astro / VitePress (wouldn't dogfood raf-query's loaders).
- **Pages are queries** (agent): `docQuery` loads a page's compiled chunk with `staleTime: Infinity`; the route loader `ensure`s it and `prefetch`es the page's demo modules in parallel (the manifest lists each page's demo ids), and `defaultPreload: "intent"` starts both on hover. Only `doc` entries are dehydrated, since demo modules hold components.
- **Markdown compiles at build time** (agent), in a Vite plugin (`www/build/content.ts`, `www/build/markdown.ts`): unified + Shiki dual themes, GitHub alerts, `./page.md` links rewritten to `/docs/page`, headings collected for the table of contents. No runtime markdown or highlighter ships to the browser. The client build also emits `llms.txt` and `/docs/<slug>.md`.
- **Demos are fenced `demo` blocks** naming `www/src/demos/<id>.tsx`; the plugin rejects unknown ids. Each demo runs against an in-page fake server (`www/src/demo-kit/server.ts`) with adjustable latency and injectable failures, its own `QueryClient`, a Queries panel (a row per query; requests find their row by the `queryKey` hash `respond` records), beside the demo when a container query says it fits, and an expanded dialog showing the same card plus the devtools panel (`@raf-query/react/devtools`, always mounted so it works in the deployed site). Demos use the same loader → handle → `useQuery` shape as apps, through a tiny router (`DemoBrowser`).
- A demo's session is kept per demo definition, like its fake server: a discarded render re-running `useState`'s initializer would otherwise create a second client and send the first requests twice.
- Frontmatter: `title`, `description`, `section` (one of `site.ts`'s `sections`), `order`. Every `.md` file in `www/content` is a page; code that a component renders outside a page is a `sample:` import (see [docs-sample-fences.md](./docs-sample-fences.md)).
- Lint: `www/src` gets the examples' JSX rules, and `www/src/routes` the examples' `sort-objects` exemption.
- Vercel: project root `www/`, settings in `www/vercel.json` (hashed `/assets` immutable, HTML revalidated at the edge).
- **Twoslash code blocks** (human asked; details agent): every `ts` / `tsx` fence uses `twoslash` (see [docs-twoslash-default.md](./docs-twoslash-default.md)). They compile at build time and show types on hover, pinned `// ^?` types and expected errors; unexpected errors fail the build. They run on `typescript6` (TypeScript 6 under an alias), passed to `twoslash/core` as `tsModule`, because TypeScript 7 has no JavaScript API and pnpm overrides don't reach peer dependencies. What blocks share lives in the TanStack Start sample app, `www/samples/tanstack-start`. Hover popups are `position: fixed`, placed by `DocBody`, so the code block's scrolling doesn't clip them.
- **Agents can request markdown** (human asked; details agent): each page's URL answers `Accept: text/markdown` with its markdown (`Vary: Accept`), next to `/docs/<slug>.md`, `llms.txt`, `llms-full.txt`, `<link rel="alternate" type="text/markdown">` and a "Copy page" button. The build writes Vercel Build Output (`www/build/vercel-output.ts`), because `vercel.json` rewrites run only after a file has failed to match, and every page is a file. Lost: Routing Middleware (a function call on every page view, in front of a static site).
