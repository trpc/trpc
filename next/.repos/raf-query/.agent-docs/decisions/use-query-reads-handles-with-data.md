# useQuery returns the data for a handle with data (human asked, 2026-10-15)

- **Overloads:** `useQuery(factory, QueryHandleWithData)` → `[data | Result, controls]` (`UseQueryResultWithData`); `useQuery(factory, QueryHandle)` → `[promise, controls]`. At runtime the hook checks `"data" in handle` and calls `use()` on the entry's thenable itself: fulfilled, so it returns at once; pending (entry gc'd or `reset` since the loader ran), so it suspends. Human: "do overload"; "at runtime we can just do a little `use()` inside".
- **Accepted hole:** `QueryHandleWithData` still extends `QueryHandle`, so a prop typed `QueryHandle` can receive one; its types say promise while the hook returns data, and `use(data)` throws. Rejected the alternative of a non-assignable tag (`ensured: true` / `ensured?: false`, the 2026-10-12 shape) to keep the extension relationship. Docs: `www/content/handles.md#typed-by-what-the-loader-did` tells readers to type such props `QueryHandleWithData`.
- **Audit trick for that hole:** temporarily give `QueryHandle` `readonly data?: never` and make `QueryHandleWithData` a standalone interface, then `tsc` in each app (dependents are skipped when core fails under `pnpm -r`). Every error outside the hook's overload / router `Serializable` / type tests is a widened data handle. Copy shadowed `www/samples` `.tsx` files (same base name as a `.ts`) to a unique name first, or `tsc` skips them.
