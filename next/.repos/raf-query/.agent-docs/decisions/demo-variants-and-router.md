# Demo variants and TanStack Router demos (human asked; details agent)

- **Variants** (human asked): a demo comparing approaches defines `variants`. Each has its own fake server and query client, and stays mounted in a hidden `<Activity>` once opened, so the network panel and page are per variant. A browser's Reload starts its variant over, on the same URL; there's no Reset (human). Lost: one shared server with requests tagged by the selected variant (an in-flight request or retry lands under the wrong one); lifting only the mode state above the session (fixes Reset, still mixes the network logs).
- **TanStack Router in demos** (human suggested, agent decided): `DemoRouter` runs a real route tree on a memory history, so loaders read like an app's (`context.queryClient`, `useLoaderData`, `Link`). Only `starting-queries` uses it; the other demos still use the hand-rolled `DemoBrowser` until they move over.
- `DemoRouter` sets `defaultStaleReloadMode: "blocking"`. With the default (`"background"`), a revisit renders the router's kept loader data and reruns the loader behind it, which hides what `fetch` waits for.
- The docs site's `Register` types every `Link` / route hook against the site's router. Demo routes pass their router type (`route.useLoaderData<Router<typeof tree>>()`, `Link<Router, string, TTo, string, "">`), keep routes in their own consts (inside `addChildren([...])` a route's `path` widens to `string` and its loader data turns `any`), and annotate route components' return types to break the type cycle.
- Files: `www/src/demo-kit/{define.ts,frame.tsx,session.ts,router.tsx,browser.tsx}`, `www/src/demos/starting-queries.tsx`.
