# Lint rules (human decided)

- Port the strict oxlint setup into this repo: type-aware oxlint with `correctness` + `suspicious`, React Compiler rules, perfectionist, no-only-tests, vendored `anti-slop` / `anti-slop-effect` / `nkzw` plugins, and generic workspace rules. Plugins live in `tooling/oxlint-plugins` and build with `vp pack`.
- **Enabled everywhere, including docs examples in spirit:** `workspace/no-overzealous-destructuring` (destructure only when a field is read ≥3 times), `anti-slop/require-safety-comment-for-type-assertion` (every non-const assertion has a `SAFETY:` comment immediately before it; a comment on a statement covers the assertion only when that assertion is the statement's value).
- **Dropped on purpose:** `workspace/no-use-state` (the docs' pattern needs `useOptimistic` / `useActionState`), `eslint/max-params` (3-arg APIs like `useQuery(factory, handle, options)`), `workspace/no-optional` (library options are optional), `typescript/consistent-type-assertions` (a `SAFETY:` comment is the justification), `anti-slop/no-chained-type-assertions` (a cast the types don't overlap on is `value as unknown as T` next to its `SAFETY:` comment). Also not ported: app-specific rules (Convex, react-hook-form, i18n literals, the old prefetch-handle rules).
