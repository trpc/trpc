# Docs build caches Twoslash results on disk (human asked for faster builds)

- Twoslash was most of every `www` build, dev server start, CI run and deploy: ~175 blocks, each a full type check of its program, about 46s of a 69s build. `build/twoslash-cache.ts` keeps each block's result as JSON in `www/node_modules/.cache/twoslash`. With Shiki's languages loading on first use (below): warm build 12s (client build 59s → 8s), cold 57s, dev's first page 57s → 6s. The output matches a cold build except for the build timestamps that always differ (`u:`, `updatedAt:`).
- Key: the block, its options (compiler options, every file of a sample's app), the project root, and `pnpm-lock.yaml`. The entry also lists every other file the block's program read, each with a hash (workspace packages such as `packages/react/src`), and a changed hash is a miss. Installed packages under `node_modules/.pnpm` and TypeScript's libs aren't hashed; the lockfile covers them.
- Seeing the program: twoslash empties a block's files from its environment when it's done, so `markdown.ts` passes twoslash its own environment `cache` Map and wraps `createFile` to read `languageService.getProgram()` before the first empty write. This depends on twoslash 0.3 internals; the render test in `twoslash-cache.test.ts` breaks if they change.
- Files under the project root outside `node_modules` are skipped as dependencies: they're the app's files, which the key covers, or files twoslash writes and empties.
- Lookups are synchronous because Shiki calls twoslash synchronously. `open` loads entries and re-hashes their dependencies first; `flush` writes after the render. Failing to write only logs a warning.
- Where it persists: Vercel restores `node_modules/**` under the root directory (`www`) on every build, and `pnpm install` leaves `.cache` alone. CI's Build www job uses `actions/cache` (key `twoslash-<lockfile hash>-<run id>`, prefix restore keys, same pattern as the Next.js cache). Entries no build has read for 14 days are deleted.
- Shiki: `@shikijs/rehype` loaded every bundled language per process (3.5s). `langs: ["ts", "tsx"]` plus `lazy: true` loads the rest on first use, and an unknown language fails the render. `ts`/`tsx` must load up front: a block whose language loads on first use highlights after the others, and `typeQueries` (the agent markdown's `// ^?` types) is matched to blocks by order. `markdown.test.ts` catches that.
- Lost: worker threads for cold builds (doesn't help warm builds, and Twoslash holds a TypeScript environment per worker); one cache file per page (any edit to a page would recompile all of its blocks); a key from hand-listed workspace dirs (drifts, as the Vercel ignore step's hand lists did).
