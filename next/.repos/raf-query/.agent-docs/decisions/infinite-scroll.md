# Examples load lists by infinite scroll (human)

- The examples' issue list and comments are paged queries loaded by infinite scroll. Filters and sort stay in the URL; the page doesn't (`IssueListInput` has no `page`, `IssuePageInput` adds the `cursor`). The docs show both: URL pagination in `www/content/url-state-and-pagination.md`, infinite scroll in `www/content/infinite-queries.md`. `use-query.test.tsx` has a `lists` block testing each.
- The trigger is `LoadMore` in `examples/.shared/ui/src/components/load-more.tsx`: a button with a ref-callback `IntersectionObserver` (no `useEffect`, which lint bans). It fires 300px before it's in view. Lists unmount it while `isFetchingNextPage` and remount it after, so a still-visible button loads again.
- No scroll jumps (human): while a page loads, the list shows skeletons for it, `min(last page size, total - shown)` of them. Issue rows and their skeletons share one fixed height (`h-12`), so a loaded page replaces its skeletons without moving anything. The "Showing N of M" line sits above the list, so nothing visible is below the growing part. Measured in headless Chrome: 0 layout shift on both apps. Comments vary in height, but their skeletons are at the bottom, so only content below them moves.
- Pages after the first fade in (`animate-in fade-in` from tw-animate-css). Issue pages are wrapped in a group per page. Comments fade in when they aren't on the first page.
