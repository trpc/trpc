# Test the single import in an RSC framework the docs don't cover (human asked)

Human: "Make sure these things actually work as expected across the different libraries … Some rsc libraries might not have support for that thing so add a test for another one even if it's not in the docs. The whole point is to make a simpler api, while still having it fool proof."

- **`tooling/rsc-frameworks`** builds `vite-rsc/` with `@vitejs/plugin-rsc` (Vite's RSC plugin; Waku and React Router's RSC mode build on it) and renders a request through the built RSC entry. The app is the docs' Next.js page: `QueryProvider`, `HydrationBoundary client={qc}`, an `ensure`d post and a `prefetch`ed (pending) comments query. The test checks the HTML has both, each `queryFn` ran once, the RSC payload's client references are `QueryProvider`, `Hydrate`, `Post`, `Comments` (not `HydrationBoundary`), and the pending entry crossed as a promise. Removing the `react-server` condition from `@raf-query/react` fails it.
- It's a workspace package so it depends on `@raf-query/react` like an app: the plugin bundles (and resolves with `react-server`) every dependency of the app with a `react` peer, found from `process.cwd()`'s `package.json`.
- Production build: the test stubs `NODE_ENV=production`, since Vitest's `test` builds development JSX.
- **Every RSC bundler must resolve `react-server`**: React's own `exports` need it for the server build of `react`. A setup that didn't would fail on React's "Only plain objects … can be passed to Client Components" error, which names the `client` prop.
- Checked by hand, not in CI: the packed tarballs in a fresh Next.js 16 app (Turbopack and webpack builds), in the fixture with real Vite 8, and in the same page on Parcel 2.16's RSC (`@parcel/rsc`; same client references, hydrates with no `queryFn` call in the browser). Parcel stays out of CI: its dependency tree is large for one more resolver of the same condition. `serverExternalPackages: ["@raf-query/react"]` fails with a null `useState` dispatcher, the same as `main`'s `/rsc` and TanStack Query's provider: Next.js loads a second React for external packages that use hooks.
