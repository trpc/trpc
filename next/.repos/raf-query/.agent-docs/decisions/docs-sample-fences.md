# Docs code blocks that need the app are `sample` fences of real files (human)

- **Every block that needs the app is an include** (human: "Every block becomes an include"): a ` ```sample ` fence whose one line is `<app>/<path>#region`, a path from `www/samples`. The block is that region of a real file, so the editor, `tsc` and lint see it like any other file.
- **A fence of its own** (human: "so we see it's something different rather than the weird `<<<`"): the markdown reads as "this block is somewhere else", with the path on its own line and `title="…"` in the meta. Lost: VitePress's `<<< path#region [title]` (blends into prose), an `import … from "path#region"` line inside a `tsx` fence (reads as code).
- **Inline `twoslash` blocks stand alone** (human: "if we don't need a router or something "outside" it's fine to use a plain twoslash block too"): they import packages only. `build/markdown.ts` fails on a `~/` or relative import, and compiles them with `tanstack-start`'s compiler options and `node_modules` but none of its files, so an app's global `declare module` (`Register`) doesn't change them.
- **A page's own blocks are `src/docs/<page>.ts(x)`** (agent): one region per block, named after its section. Blocks whose hidden setup can't share a file (two `Route`s, one `declare` name with two types) get `src/docs/<page>.<region>.ts(x)`. A region's name says what it shows (`per-query`, `retry-predicate`), not a number. These blocks get no title: they aren't files a reader creates. App files (routes, `queries.ts`) are titled with their path in the app.
- **A block that shows a route is the app's route file** (agent): `Route.useLoaderData()` is typed by route id from the registered route tree, so a route written outside `src/routes` gets the app's loader types for its id. A variant in `src/docs/` is fine when it doesn't read loader data or reads the same shape; otherwise the page shows a region of the app's route (`posts.$slug.tsx#component`, `posts.tsx#route`, `issues.$issueId.tsx#services`), or a route of another id when the page needs both shapes (the homepage hero, `blog.$slug.tsx`).
- **Outside the pages, import the region** (human: fragments "just cause indirection"): `import hero from "sample:<app>/<path>#region"` is a virtual module of `build/content.ts` that renders the region as a fence would (`{ segments }`). The homepage uses it. Lost: a `www/content/_name.md` fragment holding one fence.
- **An expected error is `// @ts-expect-error -- 2345: why`** (agent): `tsc` holds the file to it, and `build/snippets.ts` swaps it for Twoslash's `// @errors: 2345`, so the page shows the error.
- **Lint** (agent): `.oxlintrc.json` turns off, in `www/samples/*/src/docs/**`, the rules that fight page fragments: unused bindings, top-level hooks, bare expressions for `// ^?`, and the `unknown`s the prose is about.
