# Page loads keep writes made while they ran (agent)

- `fetchNextPage` / `fetchPreviousPage` add the loaded page to the entry's data as of when the page arrives (`fetchPages`' `latest`), not the data the request started with. Live caches (a subscription `setData`-ing loaded pages) lost those writes before.
- If the write moved the end being loaded (its edge page param isn't deeply equal to the one the request started from), the write wins and the loaded page is dropped: appending it would put a page after a list it doesn't follow.
- Full refetches keep, per page param, a page written after that page's read started (`keepWrites`, comparing the page `latest()` held when the read started with the one it holds at the end, by identity). A page written before its read started is read again, and the read wins. Why: the cache can't tell whether a write or a read is newer. A live writer, though, delivers every later change again, while a dropped write never comes back. So the write wins once the read is already under way. Before this, KATTCORP/isbabyoutyet's Convex bridge re-delivered every subscription after each refetch (`redeliverAfterRefetch`).
- Lost: replacing every page (the old behavior, which silently reverted live writes), and a hook or an ordering guarantee for integrations to re-write after a refetch (every live integration would have to know about it).
- Tests: `packages/core/src/infinite.test.ts` ("add a page to data written while it loaded", "drop a loaded page…", "keep a page written during a refetch…", "replace a page written during a refetch before…").
