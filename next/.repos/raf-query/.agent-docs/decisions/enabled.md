# `enabled` is a boolean, as in TanStack (human asked, agent shaped)

- Human: "enabled might be nicer than ssr", then "the enabled flag can just be a boolean and described how tanstack does it". `enabled?: boolean` is a `QueryBehavior` option (factory or `config.defaults`), default `true`. `ssr` is gone. Browser-only queries use TanStack's idiom, `enabled: typeof window !== "undefined"`; the factory runs per call, so each side decides for itself.
- Kept a flag at all (human asked whether apps like `kattcorp/isbabyoutyet` could do without it): a `queryFn` that returns a placeholder (`null`) on the server caches it, the server sends it, and the browser never replaces it, since nothing refetches on mount and first-load loaders ran on the server. isbabyoutyet's push capability and visitor tag would read `null` until focus or invalidation. Not dehydrating disabled entries is what lets the browser run them.
- Where it's disabled, `Entry.begin` never runs the request and dies with `Query.DisabledError`, so `ensure` / `fetch` fail and `prefetch` stays quiet. `invalidate` / `reset` and the observer commands (`refetch`, paging) are no-ops; `dehydrateEntries` skips disabled entries.
- Readers: in a server cache, the pending promise rejects with `DisabledError`. A streaming render can't wait for a later factory call, and rejecting makes React render the Suspense fallback there and the boundary in the browser (reported to `onRecoverableError`). In the browser, the promise stays pending, so `use()` suspends instead of reaching the error boundary (the human worried `enabled` would fight Suspense; TanStack's `useSuspenseQuery` forces `enabled: true` for the same reason). A factory call that returns `true` starts the request and settles that same promise.
- `startRequest` makes a new pending promise only when the entry has no data and no pending one (after a failed first load, or a server-disabled one).
- Lost: `enabled: "browser"`, which read the cache's `isServer` instead of a global. TanStack users already write `typeof window`, and one boolean is less to learn. Tests that render "server" and "browser" in one happy-dom process flip a variable instead.
- Unlike TanStack, `refetch()` doesn't run a disabled query: a server-disabled query can't run at all, and one rule is simpler.
- Not used: React's internal `react.recoverable` symbol (not exported in stable React) and throwing from `useQuery` during SSR (breaks the `isPending ? … : use(promise)` reader pattern).
- Tests: `client.test.ts` ("enabled"), `use-query.test.tsx` (a disabled query stays suspended until enabled), `ssr.test.tsx` ("enabled: false on the server").
