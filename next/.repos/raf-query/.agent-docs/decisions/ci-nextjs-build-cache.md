# CI caches Next.js `.next/cache` without Turborepo (agent)

- `build_examples` restores/saves `examples/nextjs/.next/cache` and `.experimental/tanstack-query/nextjs/.next/cache` via `actions/cache@v4`. Key is `nextjs-build-<lockfile-hash>-<run_id>` with prefix restore-keys (same shape as the CodeSandbox workflow). Locally, a warm Next compile drops from ~6s to ~0.3s; full `pnpm build:examples` from ~19s to ~7s when both Next caches are warm.
- CI also cancels superseded runs (`concurrency` on PR number / ref). That is not a build cache; it stops paying for obsolete pushes.
- Already in place and left alone: pnpm store via `actions/setup-node` `cache: pnpm`; Vercel `ignoreCommand` (see [vercel-ignore-build-step.md](./vercel-ignore-build-step.md)); Vercel’s automatic Next.js build cache on deploys; CodeSandbox’s Next cache in `codesandbox.yaml`. Vercel Remote Caching is on for the team but only helps Turborepo / Remote Cache SDK users — not this repo.
- Lost: Turborepo / `turbo` remote cache (human asked to avoid); caching all of `www`'s build output (Twoslash dominates, and its results are cached on their own, see [www-twoslash-cache.md](./www-twoslash-cache.md)); caching Start/Vite `node_modules/.vite` (production builds stay multi-second); TypeScript `*.tsbuildinfo` (typecheck is already ~10s of work); path-filter job skips (easy to miss shared packages / tooling, and Vercel already skips deploys per project).
