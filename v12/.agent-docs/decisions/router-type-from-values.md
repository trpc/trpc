# Client-facing entry points take the router type from a value, with one signature (human)

- Human, 2026-11-01 (on trpc/trpc#7767, which gave v11's `createTRPCOptionsProxy` four overloads): "i'm confused why we're not using the `routerType<>` approach in e.g. `createTRPCOptionsProxy` / they all our client-facing things should work the same way. overloads shouldn't necessary if we do them that way, right? / also, reminder that we should use generic "bags" as much as it makes sense".
- Every entry point that types itself from a router takes the router in its options bag as a value: `routerType<AppRouter>()`, a contract, the router itself, or a client, which carries its router. Every other type parameter is inferred in the same call, so each has one signature and no overloads.
- (agent) Why overloads came up: TypeScript has no partial type-argument inference. Once a caller writes `fn<AppRouter>(…)`, every other type parameter takes its default instead of being inferred from the arguments, so a second inferred type (the links', a `keyPrefix`'s) needs one overload per case. A value carrying the router keeps the call fully inferred ([`root-extensions.md`](./root-extensions.md) hit the same limit).
- (agent) Audit, 2026-11-01:
  - `createTrpcClient`, `createEffectClient`, `createReactClient` and `createAtomClient` take `{ router, links }`. One signature each; the explicit-generic overloads went on 2026-10-16 ([`links.md`](./links.md), Q17.3).
  - `createTrpcQueryUtils({ client, keyPrefix })`, v12's `createTRPCOptionsProxy`, types itself from the client. `keyPrefix` goes into the key's path, so it doesn't change key types and needs no overload.
  - `createTrpcRsc({ router, ctx })` and `createRouterClient(router, { ctx })` need the router at runtime and infer from it.
  - `experimental_toContract(router)` infers from its argument.
  - The exception is the adapters' `createTrpcContext<typeof makeClient>()`, which has no value to infer from and takes one type argument ([`tanstack-context-shape.md`](./tanstack-context-shape.md)). It has no other type parameters, so it needs no overloads; whether it should take a value too is [`open/tanstack-context-from-a-value.md`](../open/tanstack-context-from-a-value.md).
- (agent) In v11 (trpc/trpc#7767), `createTRPCOptionsProxy` reads the router type from its `client` (or `router`) and the key types from `keyPrefix`, with one signature. `createTRPCOptionsProxy<AppRouter>()` without a prefix and the deprecated `<AppRouter, { keyPrefix: true }>` still compile, because v11 can't break them; with an explicit router type argument, a `keyPrefix` is a type error that says to leave the argument out.
- Why: one way to pass the router everywhere, and no overload sets, whose errors name the last overload rather than the mistake.
- Lost: writing the router as a type argument (`createTrpcClient<AppRouter>(…)`); the codemod moves it into `router: routerType<…>()`.
- Open (agent): public types still take positional generics: `TrpcClient<TRouter, TContext, TForm, TLinks>`, `EffectClient<TRouter, TContext, TLinks>`, and each adapter's `TrpcQueryUtilsFor`, `TrpcProviderProps` and `TrpcReactContext<TRouter, TContext, TLinks>`. A bag (`TrpcClient<TRouter, { context; form; links }>`, the shape `ClientTypes<>` already returns) would follow the bags rule. It touches every client type, so it needs `pnpm bench shapes` before and after.
- Lives in: `packages/trpc/src/client/client.ts` (`createTrpcClient`, `TypedClientOptions`), `packages/trpc/src/client/types.ts` (`routerType`, `RouterOf`), `packages/trpc/src/effect/index.ts`, `packages/experimental-react/src/client.ts`, `packages/experimental-react-atom/src/index.ts`, `packages/tanstack-query/src/utils.ts`, `packages/tanstack-react-query/src/rsc.ts`; v11's `v11/packages/tanstack-react-query/src/internals/createOptionsProxy.ts`.
