# Parity tracks oRPC v2's table; its missing rows are built as `experimental_` (human)

- Human, 2026-10-16 (decision round, the parity target after oRPC v2): "A".
  - Options were: A) track v2's table, rebuild the parity notes from it and build the missing rows Effect-native as `experimental_*` (locking on Effect services, Workers Traces through Effect's `Tracer`, a benchmark suite against v11 and oRPC), with the cookie helpers, SWR and Pinia staying out; B) track v2's table but only mark the new rows as gaps; C) keep v1.15.5's table.
- (agent) [`../reference/orpc-parity.md`](../reference/orpc-parity.md) follows v2's `comparison.mdx` row for row, in its four groups, with a v12 column.
- (agent) Locking: `experimental_lock()` and the `experimental_Locker` service ([`locking-on-effect-services.md`](./locking-on-effect-services.md)).
- (agent) Workers Traces: `experimental_workersTracer()`, an Effect `Tracer` ([`workers-traces-tracer.md`](./workers-traces-tracer.md)).
- (agent) Benchmarks: `pnpm bench runtime|typecheck|bundle` in `tooling/bench`, modelled on middleapi/orpc-benchmarks so its oRPC and v11 numbers can be checked against oRPC's own. Results in [`../notes/benchmarks.md`](../notes/benchmarks.md): v12 leads v11 on throughput (+13%) but trails oRPC (about a quarter), and it is behind both on type-check time (+23% over v11) and bundle size (3× v11's client gzipped).
- Why: v2 is what users compare against, and the benchmarks back up or refute "typesafe at scale" with numbers.
- Lost: the cookie, encryption and signing helpers row stays 🛑, and so does SWR and Pinia Colada; the benchmarks are run by hand, not in CI.
- Human, 2026-10-17 (decision round, whether to work on bundle size before v1 and what to hold the client to): "A sure, I only care about tree shakability when using core features". Bundle size is worked on before v1, with budgets checked in CI (only reported since 2026-10-19, below): a minimal JSON client ≤ 10 kB gzipped (18 kB since, below), the full client (retry, SSE, progressive JSON) ≤ 25 kB. Optional features must shake out of a bundle that uses only core ones. Type-check time is tracked, not worked on.
- Human, 2026-10-18 (after `dedupeLink` avoided Effect's `PubSub` to keep the client small): "Bundle sizing should be focused on minimum tree shaken stuff, touching dedupe link shouldn't have been a consideration for that as it's not the 'standard path'". The budget covers only the code its entries pull in: `createTrpcClient` with `httpLink` (minimal), and with `retryLink` and `httpLink`, without and with `experimental_createProgressiveJson()` (full; SSE is part of `httpLink`, and progressive JSON is measured both ways since 2026-10-21, below). Opt-in links and utilities outside them (`dedupeLink`, `wsLink`, `splitLink`, `loggerLink`, `experimental_*`, …) are designed for correctness and simplicity, not bytes; they only have to shake out of those bundles.
  - (agent) First cut: the Promise client runs its links without the client-span code (it runs on Effect's native tracer, so the span never opened; [`tracing-across-client-and-server.md`](./tracing-across-client-and-server.md)). 1.7 kB off each: 25.7 and 29.1 kB.
- (agent) Measured after: the 10 kB target was under the floor of links on Effect. `Effect.runPromise` alone is 8.5 kB gzipped and a one-element `Stream`, which every link returns, 10.7 kB ([`../notes/benchmarks.md`](../notes/benchmarks.md#budgets)). Options were: A) a Promise-native core path for the minimal client, against "all logic uses Effect"; B) keep links on Effect and raise the minimal target to about 18 kB; C) keep 10 kB as a long-term aim and only block growth.
- Human, 2026-10-17 (decision round, the minimal-client target): "B". Links stay on Effect; the minimal JSON client's target is 18 kB gzipped. The full client's stays 25 kB.
- Human, 2026-10-19 (decision round, whether the bundle budgets block the first npm publish): "c)".
  - Options were: A) keep the ceilings and gate 12.0.0 on the targets; B) gate the first publish on a target of about 20 kB; C) drop the ceilings and only track sizes in benchmarks.
  - No ceilings: `pnpm bench budget` bundles the clients, prints their gzip sizes against the targets and never fails. CI's `check` job still runs it, so each run's log shows the sizes; [`../notes/benchmarks.md`](../notes/benchmarks.md#budgets) keeps the table. Sizes don't block a publish.
  - The tree-shaking requirement stands: optional features must shake out of a bundle that uses only core ones.
- Human, 2026-10-21: "1. Rename. We don't care about breaking changes before v12 2. Yes 3. With and without 4. Progressive json". Its 3 answers whether the full client's budget includes progressive JSON, which is `experimental_` and opt-in: with and without, as two entries.
  - (agent) `pnpm bench budget` has three entries: the minimal JSON client, the full client (`retryLink`, `httpLink`, SSE) and the same with `experimental_createProgressiveJson()`. Both full entries keep the 25 kB aim. Measured that day: 40.0, 40.2 and 44.3 kB gzipped, so progressive JSON adds 4.1 kB and the rest of the full client 0.2 kB over the minimal one.
  - Its 1, 2 and 4 are in [`replaceable-transformers.md`](./replaceable-transformers.md) and [`progressive-json.md`](./progressive-json.md).
- (agent) The 18 and 25 kB targets stay in the report as aims, not gates. No check enforces tree-shaking on its own; an optional feature that stops shaking out shows up as a jump in the clients' sizes.
- Lost: the ceilings, which stopped growth: each raise had to be argued here. There were four on 2026-10-18, from 25.7 and 29.1 kB to 39.3 and 43.5 kB, for client fixes and Effect APIs in place of copies ([`effect-apis-over-hand-rolled.md`](./effect-apis-over-hand-rolled.md), [`http-link-on-effect-http.md`](./http-link-on-effect-http.md), history in [`../notes/benchmarks.md`](../notes/benchmarks.md#budgets)). Growth now only shows as a number in a CI log.
- Open: every client is over target: the minimal one by 22.0 kB, the full one by 15.2 kB without progressive JSON and 19.3 kB with it. The next cuts: the streaming progressive JSON decoder off per-index `Queue`s, and `Duration`, `Channel` and `Stream` operators the client pulls in over the floor.
