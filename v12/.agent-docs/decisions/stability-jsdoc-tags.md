# APIs are experimental, unstable or stable, named `experimental_*` or plain, with a stability tag; promoting renames with a deprecated alias (human)

- Human, 2026-10-16 (Q21.1, decision round): "B + keep stability tag, when promoting we should rename and do a deprecated alias".
- Human, 2026-10-16 (decision round, prefix): "A", switching the prefix from `unstable_` to `experimental_`, after writing `experimental_` in two earlier answers. The name and the `@stability experimental` tag now say the same thing.
- Human, 2026-10-19 (decision round, unstable stage): "B) experimental mean the feature might go away at any time, unstable means we want the general feature but how it works can change at any time.. that's how v11 rules worked and it should be documented the same". So there are three stages, as in v11: experimental (might change or go away in any release), unstable (we want it, but its name, options and behavior might change in a minor) and stable. Until 12.0.0 only experimental has a prefix ([`no-unstable-prefix.md`](./no-unstable-prefix.md)).
- Human, 2026-10-16 (decision round, which features start experimental): "B - we can probably have experimental_ on any api i haven't explicitly blessed". Experimental: the features v11 never had, `experimental_socketLink`, `experimental_messagePortLink`, `experimental_createAction`, `experimental_createCallable` (all of `@trpc12/trpc/actions`) and `experimental_createHibernatingWebSockets`, next to `experimental_durable`, `experimental_durableLink` and `experimental_generateOpenApiFromTypes`. Later in the round, all of `@trpc12/experimental-nest` ([`nest-integration.md`](./nest-integration.md)).
- Tentative (human): "we can probably have experimental_ on any api i haven't explicitly blessed". So a new public API starts experimental unless a `(human)` decision settles its shape. Existing exports outside the list above stay `stable` until the human names more. Challenge it when it gets in the way.
- Human, 2026-10-19: "make sure all experimental packages are experimental- prefixed, i see e.g. https://v12.trpc.io/v12/docs/integrations/tanstack-query/tanstack-db?flags=contracts%2Ctanstack-db and also the exported public apis should be prefixed". So what the docs keep hidden in an experiment isn't approved, and is experimental by name: a package whose docs are only on hidden pages is `@trpc12/experimental-*`, and an export documented only on hidden pages is `experimental_*`.
  - (agent) Renamed, without aliases (nothing has shipped): `@trpc12/nest` to `@trpc12/experimental-nest`, whose exports lose their prefix (`experimental_Implement` to `Implement`, likewise `ImplementInterceptor`, `TrpcHost`, `TrpcModule`, `TRPC_MODULE_OPTIONS`); `@trpc12/tanstack-{preact,vue,solid,svelte,angular,lit}-query` to `@trpc12/experimental-tanstack-*-query`, every export now `@stability experimental`; in `@trpc12/trpc`, `rateLimit` and `RateLimited` (`/middleware`), `Publisher` and `makeMemoryPublisher` (`/server`), and `serveSocket` (`/socket`) to `experimental_*`, with their option types tagged `experimental`. The packages' folders follow (`packages/experimental-nest`, …).
  - (agent) Nothing to rename for TanStack DB, the AI SDK, Better Auth or Firebase: those pages are recipes over stable exports (`queryOptions()`, `call`, `createFetchHandler`) and another library, with no tRPC package or export of their own. They stay hidden until reviewed. Proposal 26's TanStack DB adapter would be `@trpc12/experimental-tanstack-db` ([`live-queries.md`](./live-queries.md)).
  - (agent) `trpc/jsdoc` reads `www/v12/docs/` (`tooling/oxlint-plugin/docs-use.ts`). A value is documented on a page that imports it from its package in a code block; on a listed page, naming it at the start of an inline code span counts too (`` `isTrpcError(err)` ``). A value imported on hidden pages and documented on no listed page must be `@stability experimental`, so `experimental_*`. A package used only on hidden pages (imported, installed, or named in prose) must be named `experimental-`. `tooling/pack/docs.test.ts` checks the other way: a package is `experimental-` exactly when its docs are in an experiment, and every docs experiment documents an `experimental_` export or an `experimental-` package, except the recipe experiments (`integrations`, `tanstack-db`).
  - (agent, tentative) Types keep their names, tagged `experimental`, as before: only values carry the prefix, as in v11. Challenge it if the human meant types too.
  - Open: methods that only hidden pages use keep their names, because they hang off stable objects rather than being exports: `t.implement(contract)` and `.route({ spec })` (contracts), `handler.messagePort()` (message ports). Renaming them (`t.experimental_implement()`) is the human's call.
- Every export reachable from a published entry point carries `@since <version>` and `@stability experimental | unstable | stable | internal`, plus an `@example`; the `trpc/jsdoc` lint rule enforces it ([`acronym-casing.md`](./acronym-casing.md), Q21.4).
- An experimental export's name starts with `experimental_` (`experimental_durableLink`); an unstable or stable one has its final name ([`no-unstable-prefix.md`](./no-unstable-prefix.md)). Promoting an experimental export adds its final name (`experimental_x` to `x`) and keeps the old name as an alias tagged `@deprecated Use <name>`, removed in the next major. The codemod rewrites the alias.
- (agent, tentative) Built, 2026-10-16. Before this, all 468 public exports were tagged `experimental`, because the package is alpha; prefixing them all would rename the whole API. So `@stability` now says how an export is planned to ship in 12.0.0, and prereleases promise nothing (`www/v12/docs/packages.md#stability`). The core is `stable`.
  - Only values (functions, classes, consts) carry the prefix. Their option types are tagged `experimental` or `unstable` but keep their names (`DurableLinkOptions`, `MessagePortLinkOptions`, `CreateActionOptions`), as v11 did for `unstable_httpBatchStreamLink`. Types shared with a stable value (`SocketLink`, `ConnectionLinkOptions`, used by `wsLink`) stay `stable`.
  - `trpc/jsdoc` enforces both directions. An `experimental` value must be named `experimental_*`, and an `experimental_*` value must be experimental or `@deprecated`: an unstable or stable `experimental_x` is reported as promoted, to be exported as `x` with the old one as an alias. Any `unstable_*` export is reported. A `@deprecated` export must say `Use <name>`.
  - The codemod reads `PROMOTED` (`packages/upgrade/src/promoted.ts`, empty for now) and rewrites imports of promoted `experimental_*` names from `@trpc12/trpc` and `@trpc12/*`. (agent, 2026-10-19) It follows chains to their end, so an export renamed twice keeps both entries and old code goes straight to its last name.
  - Renamed without deprecated aliases: no release has shipped the old names.
- Human, 2026-10-16 (decision round, the Effect Atom React package): "In first version but with the name in c where the whole package is prefixed with experimental" ([`react-use-package.md`](./react-use-package.md)). A whole package can be experimental: `@trpc12/experimental-react` and `@trpc12/experimental-react-atom`.
  - (agent) In an `@trpc12/experimental-*` package, every export is `@stability experimental` and none carries a prefix, since the package name already says it. `trpc/jsdoc` enforces both.
  - (agent, tentative) Promoting such a package publishes it without the prefix (`@trpc12/react-atom`), and the last `experimental-` release re-exports it, marked deprecated on npm. (agent, 2026-11-03) Its exports that are still experimental get `experimental_` in the new package. The codemod reads `PROMOTED_PACKAGES` (`packages/upgrade/src/promoted.ts`, empty for now): the old package name, its new one, and the names that changed (`atom: 'experimental_atom'`), then `PROMOTED`; it rewrites subpaths too.
  - (agent, 2026-10-19) No `@trpc12/unstable-*` packages, and `trpc/jsdoc` reports one. Unstable means the feature stays, so its package can have its final name now, its unstable exports tagged `@stability unstable`; promoting them to stable then renames nothing, where renaming a package is breaking.
- (agent, 2026-10-19) Docs pages: an unstable feature's page is badged, not hidden. `stability: unstable` in its frontmatter shows an "Unstable" badge ("How it works might change in a minor release", linking Stability), and the page stays in the sidebar, search, `llms.txt` and the sitemap, because the human wants the feature used. Experimental features' pages stay hidden in experiments ([`docs-experiments.md`](./docs-experiments.md)); a page with both shows the Unstable badge. `www/v12/docs/packages.md` (Stability) has v11's FAQ definitions for both stages, under `#unstable` and `#experimental` as in v11.
- Open: which `experimental_` exports become unstable (a decision round, 2026-10-19; [`experimental-to-unstable-list.md`](../open/experimental-to-unstable-list.md)). No export is renamed until the human confirms the list. An `experimental-` package that becomes unstable takes its final name, its exports unprefixed (`@trpc12/nest` with `Implement`).
- (agent) No separate experimental entry points. `@trpc12/trpc/internal` and `@trpc12/trpc/internal/testing` are the no-guarantee entry points ([`entry-points.md`](./entry-points.md), [`testing-helpers-internal.md`](./testing-helpers-internal.md)).
- Why: stability is visible at the import site; the deprecated alias keeps promotion non-breaking, which v11's `unstable_httpBatchStreamLink` rename wasn't. `experimental_` tells a reader what v11's did: only try the feature, it might go away. An unstable one says so in its `@stability` tag and docs badge.
- Lost: names that never change; promotion out of experimental leaves an alias behind until the next major.
