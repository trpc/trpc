# Query handles: `$ensure()` returns a serializable handle, `$fromHandle()` reads it (human)

- Human, 2026-11-03: "port v11's query handles to v12's TanStack Query integration, with no `unstable_` prefix: `trpc.x.$ensure(input)` returns a serializable handle `{ queryKey, input }`, and `trpc.$fromHandle(handle)` reads it in components", including v11's fix that leaves `input` out when it's `undefined`, so Next.js can serialize the handle (#7848). Then "rewrite the v12 docs to default to ensure-style queries instead of ad hoc `.queryOptions`": loaders call `$ensure`, components read via `$fromHandle`.
- A query procedure's helpers get `$prefetch()`, `$ensure()` and `$fetch()`, v11's three verbs. Each starts the query on a `QueryClient` and returns `{ queryKey, input }`: `$prefetch()` right away (its error surfaces where the handle is read), `$ensure()` once the cache has data however old (stale data refetches in the background; rejects when the fetch fails), `$fetch()` once the data is fresh. Every router has `$fromHandle(handle, opts?)`, which returns what `queryOptions({ input })` would for the handle's procedure and input, and takes the same TanStack options and `context`.
- (agent) The verbs take the option bag ([`tanstack-option-bag.md`](./tanstack-option-bag.md)): `$ensure({ input, staleTime, context })`, not v11's `(input, opts)`. Their TanStack options are the ones a fetch uses (`staleTime`, `gcTime`, `retry`, `retryDelay`, `meta`); observer options such as `select` go to `$fromHandle()`. `input: skipToken` is not allowed: a handle always starts its query.
- (agent) The verbs need a `QueryClient`, which v12's helpers didn't hold: `createTrpcQueryUtils({ client, queryClient })` takes one, or a function returning one (`createTrpcRsc` passes its per-request `getQueryClient`). Only helpers made with it have the verbs, in the types too (`TrpcQueryUtils<TClient, true>`); providers still take only `client` ([`tanstack-query-adapters.md`](./tanstack-query-adapters.md)), so `useTrpc()`'s helpers read handles but don't make them, as v11's `useTRPC()` couldn't wait for one either. The second type argument costs nothing measurable: 150 query procedures typecheck in 763,534 instantiations before, 762,225 without a query client and 763,127 with one.
- (agent) `$ensure()` is TanStack 5.105's `queryClient.query()` (the deprecated `ensureQueryData({ revalidateIfStale: true })` was v11's): it awaits `query()` when the cache has no data, and otherwise resolves at once and lets `query()` refetch in the background if the data is stale.
- (agent) A handle's `queryKey` is typed `[path, { input?: TInput; type: 'query' }]` with the procedure's input, not `unknown` or a `DataTag`, and its types ride on a required type-only symbol, so only the verbs make handles and `$fromHandle()` infers the data, error and link context from it. `inferQueryHandle<typeof trpc.post.byId>` names the type for a prop, on helpers with or without a query client.
- (agent) With `keyPrefix`, the prefix is the key path's first segment ([`query-key-prefix.md`](./query-key-prefix.md)); `$fromHandle()` on helpers with a `keyPrefix` refuses a handle without it. Helpers without one can't tell a prefixed path from a router, so they read it as one.
- (agent) Left out of the port: v11's in-render `$prefetch` on `useTRPC()` (React-only, and `useTrpc()` has no query client), and its development warnings for a handle read outside `<HydrationBoundary>` and for a redacted hydrated error, which `queryOptions()` reads hit just the same.
- (agent) Infinite handles wait for [`open/tanstack-infinite-handles.md`](../open/tanstack-infinite-handles.md): `infiniteOptions()`'s `input` is a function, which a handle can't carry. The codemod leaves a note on v11's `unstable_$prefetch`, `unstable_$ensure`, `unstable_$fetch` and `unstable_$fromHandle`, and sends the infinite verbs to `infiniteOptions()`.
- Why: a loader or server component decides when a query starts and whether the page waits; the component reads what it started, from a value that survives `JSON.stringify`, RSC props and TanStack Router's loader data, without restating the input.
- Lost: v11's positional `(input, opts)` verbs and `unstable_` names; infinite handles, for now; `createTrpcQueryUtils` being free of a `QueryClient`, for helpers that want the verbs.
- Lives in: `packages/tanstack-query/src/handles.ts`, `packages/tanstack-query/src/utils.ts` (`QueryHandleVerbs`, `HandleReader`, `inferQueryHandle`), `packages/tanstack-react-query/src/rsc.ts`, `packages/upgrade/src/transform.ts` (`QUERY_HELPERS`); tests in `packages/tanstack-query/src/handles.test.ts`, `handles.test-d.ts`, `packages/tanstack-react-query/src/rsc.test.tsx`; docs in `www/v12/docs/integrations/tanstack-query/handles.md`.
