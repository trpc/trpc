- (agent) What's built and exported from `src/index.ts`:
  - `createErrorBoundary({ name, errors, parent?, claims })` returns `[Boundary, useBoundary]`. `errors` names what the errors come from, for the types only: a client factory (`makeClient`, as `createTrpcContext<typeof makeClient>()` takes it), a client, or `routerType<AppRouter>()`; `ErrorsOf<TSource>` is every error its calls are typed with, links' codes and the transformer's `data` form included. `claims` is an object, a fallback component per key: a code (`UNAUTHORIZED`), a tag (`ProcedureNotFound`), or `unexpected`. A key no call fails with is a type error.
  - Each fallback gets `{ error, reset }`, `error` typed by its claim (`ClaimedError`): a tag's is the errors with that tag; a code's is the errors with that code that no claimed tag takes first; `unexpected`'s is `unknown`. So `Auth`'s `UNAUTHORIZED` fallback reads `TrpcError<'UNAUTHORIZED', undefined, 'Unauthorized'>`, defined or not, and a custom code's fallback reads the procedure's `data`.
  - What a boundary owns adds up along `parent`, so `useQuery(useAuthBoundary().query(...))`'s `error` is typed without `UNAUTHORIZED` and what `Offline` and `Root` own (`Unclaimed<E, TClaims, TUnexpected>`), and `matchError()` below it needs no handler for them.
  - The hook returns `{ query, infiniteQuery, mutation, owns }`. Each transform takes what `queryOptions()`, `infiniteOptions()` or `mutationOptions()` returns and types its error, `DataTag` included, without the owned ones. TanStack's hooks infer the narrowed error from them: `useQuery` (with its `initialData` overload, kept by a second `query` overload), `useSuspenseQuery`, `useQueries`, `usePrefetchQuery`, `useInfiniteQuery` and `useMutation`.
  - Queries replace, mutations hold ([error-boundary-owned-errors](../open/error-boundary-owned-errors.md)'s B, its recommendation): `query()` and `infiniteQuery()` set `throwOnError` to "this boundary or one above it owns it", or-ed with the options' own. `mutation()` wraps `mutationFn`: an owned failure waits on the nearest mounted boundary of the hook's chain that claims it, which shows its fallback with its subtree hidden in React's `<Activity>`, and `reset` calls the procedure again. A boundary that unmounts rejects what it holds with the held error. The peer range is `react ^19.2.0` for `<Activity>`.
  - The component takes `resetKeys`, `onReset(details)` and `onError(error, info)` ([error-boundary-props](../open/error-boundary-props.md)'s B, its recommendation), with react-error-boundary's names and `details` (`{ reason: 'reset' }` or `{ reason: 'keys', prev, next }`). `onError`'s `error` is typed by the boundary's own claims. A fallback per mount isn't built: fallbacks are per claim now, and the factory stays the one place that says what a boundary shows.
  - `unexpected` takes every throw no boundary under it owns, crashes while rendering too, and re-throws an error with a string `digest` (Next's `redirect()`, `notFound()`) as `safe()` does ([error-boundary-render-errors](../open/error-boundary-render-errors.md)'s B, its recommendation). At the hook, it owns every `defined: false` tRPC error, as `matchError()`'s `unexpected` does.
  - A claim is a code or a tag in one object ([error-boundary-claims](../open/error-boundary-claims.md)'s C, its recommendation); a tag goes before a code, and `Unclaimed` subtracts both shapes.
  - (agent) The transforms take tRPC's option types (`QueryOptionsOut`, `InfiniteOptionsOut`, `MutationOptionsOut`), not any TanStack options, so a hand-written `{ queryKey, queryFn }` doesn't fit; a tRPC procedure's options always do, including spread ones with extra fields (`{ ...trpc.x.queryOptions(), select }`). The method names drop tRPC's `Options` suffix, since `auth.query(trpc.x.queryOptions())` already says it once.
- (agent) Why this tuple: it's `createTrpcContext`'s `[TrpcProvider, useTrpc]`, and what context helpers in React apps return (`const [Provider, useThing] = createSafeContext()`). The caller names both, so two boundaries never shadow each other. The component comes first because the tree needs it once and components many times. A tuple can't carry static members, so the parent is the component itself (`parent: RootBoundary`), and its owned claims ride on a type-only brand, as TanStack's `DataTag` does on query keys.
- (agent) Inspired by [Result RPC](https://result-rpc.com/) ([GitHub](https://github.com/jokull/result-rpc)): its shells are error boundaries for values that claim failures and subtract them from the component's error union. All three links returned 200 on 2026-11-03.
- (agent) Why a fallback per claim: it's what lets each one be typed by exactly its errors, and `errors` gives the factory the router's error union, which also makes a misspelt claim a type error ([error-boundary-claims](../open/error-boundary-claims.md)'s Details asked for that). The key is `claims`, not `catchTags`, since a key here can be a code.
- (agent) Calls with an obvious answer, not asked:
  - **A missing boundary throws**, on the first render, as the human asked. The hook outside its boundary: `The Auth error boundary's hook found no <AuthBoundary> above it: wrap the tree in <AuthBoundary>`. A boundary without its parent above it: `<AuthBoundary> needs <RootBoundary>, its parent, above it`. Both name the component as it's written in JSX, which is the fix, like React's own "must be used within" errors. result-rpc throws on the first render too; react-error-boundary's `useErrorBoundary` does too.
  - **`displayName` is `${name}Boundary`**, so React DevTools and the messages read `<AuthBoundary>`.
  - **A fallback is a component**, rendered with `createElement`, so it can call hooks. `reset` is TanStack Router's and Next.js's name (react-error-boundary's is `resetErrorBoundary`). It resets the failed queries under the boundary, so they refetch, sends the held mutations again, then renders the children again.
  - **One `QueryErrorResetBoundary` for a whole chain**, made by the outermost boundary. The spike found that with one per boundary, retrying from `Offline` reset the wrong one and the query never refetched.
  - **Nesting:** the innermost boundary that claims an error renders it, and a boundary re-throws what it doesn't claim. A held mutation waits on the hook's own chain, not on another boundary mounted between it and the component.
  - **A claim made twice in a chain** goes to the innermost claim, so a page can own `NOT_FOUND` under an app-wide one. result-rpc rejects a duplicate claim when the shell is defined; here it's legal, since nesting is how React boundaries work.
  - **Suspense:** `useSuspenseQuery` throws every error while it has no data, so its owned errors reach their boundary and the rest go on up, with or without `auth.query()`; with it, the result's `error` (after data, on a refetch) is typed without the owned ones. There's no suspense-specific transform.
  - **SSR:** React doesn't run error boundaries on the server. A query that fails while streaming SSR makes React render that Suspense boundary again on the client, where the error boundary catches it. A failed prefetch isn't dehydrated, and a pending one that `hydrationOptions()` streams fails on the client, so the client's boundary takes the error either way. Rendering the fallback on the server, by checking TanStack's cache for a failed query first, would work; not built.
  - **React only, all in `@trpc12/tanstack-react-query`** (Q24.5 B for now). `owns()`, `Unclaimed`, `ClaimedError`, `ErrorsOf` and the `throwOnError` transform have no React in them and can move to `@trpc12/tanstack-query` (Q24.5 A) when another adapter wants boundaries, re-exported so nothing breaks.
  - **Stability:** `createErrorBoundary` is `@stability unstable`, with no `unstable_` prefix since 2026-11-03 ([no-unstable-prefix](./no-unstable-prefix.md)). Its types keep their names (`ErrorBoundarySpec`, `ErrorBoundaryClaims`, `ErrorBoundaryFallbackProps`, `ErrorBoundaryProps`, `ErrorBoundaryResetDetails`, `ErrorBoundaryComponent`, `ErrorBoundaryOptions`, `TrpcErrorBoundary`, `ClaimKey`, `ClaimedError`, `ErrorsOf`, `Unclaimed`), tagged `unstable`. Its docs page is `www/v12/docs/integrations/tanstack-query/error-boundaries.md` with `stability: unstable`: badged, listed and indexed, not hidden in an experiment.
- Why: a component's `error` lists only what it must handle, and the app's sign-in, offline and crash handling is written once, in components that own them, with types to match. Boundary mode needs nothing from TanStack. Unstable because the human is sure it ships, while the open questions below can still change its shape in a minor.
- Lost:
  - The open question's A, no boundaries: each component handling the whole union, with app-wide failures in `unexpected` or an untyped boundary.
  - Its B as a stable, unprefixed export now: the shape isn't settled.
  - Its C, a side-effect mode (`mode: 'react'`, the hook's `error` `null` while `status` is `'error'`, `onError` with `retry`).
  - Its D, the primitives only (`owns()`, `Unclaimed` and the options transform, with each app writing its boundaries, the mounted-chain check and the shared reset boundary).
  - The hook question's A (2026-10-21): the hook returning wrapped hooks, `const { useQuery, useMutation } = useAuthBoundary()`. It was built first; it covered two of TanStack's hooks, dropped their overloads, and the rules-of-hooks lint skipped `useAuthBoundary().useQuery(…)`.
  - Its C: a three-element tuple, `[AuthBoundary, useAuthQuery, useAuthMutation]`, closest to result-rpc's `shell.useQuery`, but with three names per boundary and a tuple that grows with each hook it covers.
  - The spike's API: `createShell()` returning `{ Boundary, useQuery, useMutation, owns }`, `RootShell.extend({ … })` for nesting, and hooks that only checked their chain at render.
  - The internal port's shape (2026-10-21 to 2026-11-03): `claims: ['UNAUTHORIZED']` with one `fallback` for all of them and `unexpected: true` beside it, so a fallback's `error` was `unknown` and a misspelt code owned nothing, silently. `Remaining` is `Unclaimed` now.
  - E's `experimental_` prefix and its page hidden in an experiment, asked for again on 2026-11-03 and taken back the same day.
